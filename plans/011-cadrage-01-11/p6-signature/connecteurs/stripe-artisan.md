# Fiche connecteur — le compte Stripe de l'artisan (lecture des paiements) (tâche 036-009)

> Écrite le 03/11/2026 sur l'hôte d'agents d'Oracle, par Claude Code. Format : p6 § 0.4
> (`plans/011-cadrage-01-11/prompts-benj/p6-signature-et-sur-mesure-0311.md:235-262`, ligne « Stripe du client »). **Fiche seulement** (plan § 3.2,
> département 4 : « Stripe de l'artisan (fiche seulement) ») : aucun code dans ce lot. À ne pas confondre avec le Stripe **de Presti**, qui encaisse
> les abonnements (`lib/abonnementSync.ts`) et n'est jamais touché ici. Tout ce qui touche à l'argent reste une carte. Rien n'a été relu sur Internet
> depuis cet hôte : produits et règles de Stripe **à vérifier à la date du geste**.

| Champ | Stripe de l'artisan |
|---|---|
| **Portées demandées** | **Lecture seule.** Deux voies, à trancher par Benj : (a) **clé restreinte** créée par l'artisan **lui-même** dans son tableau de bord Stripe, droits en lecture sur les paiements et les sessions de paiement, rien d'autre, saisie par lui dans « Connexions » (p6 § 0.4 : « identifiant saisi par lui ») ; (b) Stripe Connect (compte « Standard » de l'artisan relié à la plateforme Presti, portée en lecture), qui exige d'inscrire Presti comme plateforme Connect (geste de compte). Défaut proposé : **(a)**, gratuite, sans plateforme, retrait trivial. Jamais une clé secrète complète. |
| **Ce qu'on lit** | Les paiements reçus (montant, date, référence de facture portée en métadonnée par le lien de paiement), pour **arrêter les relances d'impayé** d'une facture payée et **préparer** « marquer payée ». |
| **Ce qu'on écrit** | Rien chez Stripe en phase 1. Phase 2, si l'artisan le veut : un lien de paiement dans une facture déjà émise. Côté Presti : « marquer payée » est **toujours une carte**, en Studio comme en Signature (`marquer_facture_payee` dans `OUTILS_JAMAIS_AUTO`, `lib/pilote/regles.ts:79-82`) ; le montant vient de la facture en base, jamais du modèle. |
| **Où vit l'autorisation** | Table `connexions`, fournisseur `stripe_artisan` (déjà prévu par `0193_systeme_agents.sql:103-104`) : la clé restreinte chiffrée deux fois, `secret_app` (`CANAUX_KEY`) et `secret_n8n` (`BOITE_CLE_N8N`), format v1, liée à la ligne (`lib/connexions/chiffrement.ts`). Jamais dans un identifiant n8n en clair (le nœud Stripe de n8n exige un identifiant par compte : on passe par HTTP Request avec la clé déchiffrée à l'exécution), jamais versionnée, jamais renvoyée au navigateur (seuls les 4 derniers caractères peuvent s'afficher). |
| **Retrait par le client** | « Retirer » → `POST /api/connexions/retirer` : état `retiree`, clé effacée. L'artisan **supprime aussi la clé dans Stripe** (lien vers son tableau de bord dans « Connexions ») : c'est la seule révocation réelle d'une clé restreinte. |
| **Expiration, refus** | Clé supprimée ou droits retirés : Stripe répond 401 ou 403 → le lecteur de paiements se tait, « Connexions » le dit, une alerte part ; **les relances d'impayé ne s'arrêtent pas sur une supposition** : sans lecture, elles continuent selon leurs règles (`lib/relancesImpayes.ts:38`), et l'artisan peut toujours marquer payé à la main (double chemin). Rien ne plante. |
| **Quotas de l'API** | Limites de débit de l'API Stripe par compte (page officielle « Rate limits »), à relever le jour du geste ; lecture une fois par jour et à l'échéance d'une relance, jamais en boucle. |
| **Coût** | API gratuite ; une clé restreinte est gratuite. Les frais de transaction de Stripe sont ceux de l'artisan, sur ses encaissements, sans rapport avec Presti. Connect (voie b) : conditions de plateforme à relever. |
| **Le test qui le prouve** | À écrire avec le code de lecture (lot du département facturation) : faux Stripe, paiement reçu → relance arrêtée et carte « marquer payée » (jamais d'écriture seule) ; clé révoquée → silence + alerte, relances inchangées ; aucune clé dans une sortie. Le chiffrement et le retrait d'une ligne `connexions`, communs : `scripts/connexions-qa.mjs` ; « aucune facture émise par n8n, aucun montant hors du code » : `scripts/devis-facture-n8n-qa.mjs` (036-005). |
