## Le rapport et le méta-juge (revue du 24/09, B1)

Le `verifier` de cette fiche n'est pas ton script : c'est `scripts/juges-026-mutations-preuve.mjs`, le méta-juge écrit par Claude Code (026-001). Il lance ton script (20 minutes au plus : le reste du budget sert à ses propres contre-mutations), relit ton rapport, **refait lui-même** au moins trois de tes mutations tirées au hasard sur sa propre copie, et vérifie que rien n'a bougé dans les dépôts. Un script qui sort en code 0 sans avoir attrapé ses mutations, ou un rapport qui déclare une mutation que le juge n'attrape pas, fait échouer la fiche : c'est la raison d'être de ce méta-juge.

Ton script écrit donc, en plus de `mutations.md`, **`.orchestre/preuves/026-152/mutations.json`** :
`{ "mutations": [{ "juge", "commande", "fichier", "avant", "apres", "critere", "extrait", "duree_s" }] }`
- `juge` : le chemin du juge, tel qu'il est écrit dans la liste ci-dessous ;
- `commande` : la ligne exacte lancée sur la copie mutée, où la copie s'écrit `{racine}` (dépôt presti) ou `{source}` (dépôt orchestre) ;
- `fichier`, `avant`, `apres` : la mutation, sous la forme d'**un** remplacement de texte exact (`avant` présent une seule fois dans `fichier` ; `apres` peut être vide). Une mutation qui ne s'écrit pas ainsi (un fichier retiré, une image masquée) porte sur le texte qui la produit : le fichier qui charge l'autre, le script qui fabrique l'image ;
- `critere` : l'identifiant attendu en échec ; `extrait` : la ligne en échec réelle, 20 signes au moins ; `duree_s` : la durée du juge sur la copie mutée.
