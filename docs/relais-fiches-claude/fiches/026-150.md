Un script qui sort en code 0 sans avoir attrapé ses mutations, ou un rapport qui déclare une mutation que le juge n'attrape pas, fait échouer la fiche : c'est la raison d'être de ce méta-juge.

Ton script écrit donc, en plus de `mutations.md`, **`.orchestre/preuves/026-150/mutations.json`** :
`{ "mutations": [{ "juge", "commande", "fichier", "avant", "apres", "critere", "extrait", "duree_s" }] }`
- `juge` : le chemin du juge, tel qu'il est écrit dans la liste ci-dessous ;
- `commande` : la ligne exacte lancée sur la copie mutée, où la copie s'écrit `{racine}` (dépôt presti) ou `{source}` (dépôt orchestre) ;
- `fichier`, `avant`, `apres` : la mutation, sous la forme d'**un** remplacement de texte exact (`avant` présent une seule fois dans `fichier` ; `apres` peut être vide). Une mutation qui ne s'écrit pas ainsi (un fichier retiré, une image masquée) porte sur le texte qui la produit : le fichier qui charge l'autre, le script qui fabrique l'image ;
- `critere` : l'identifiant attendu en échec ; `extrait` : la ligne en échec réelle, 20 signes au moins ; `duree_s` : la durée du juge sur la copie mutée.
