# Le cœur de cerveau — comment les IA de Presti s'améliorent (depuis le 2026-09-13)

**Ce que c'est.** Presti n'a pas de modèle entraîné : il a des *cerveaux configurés* — le prompt de conversation, les consignes par métier, le filtre anti-invention, la détection d'urgence, le chiffrage, la recherche fournisseurs, la persona de plateforme (`presti/lib/ai*`). Le cœur de cerveau, c'est **un registre et un cycle** pour qu'ils s'améliorent autrement que « quand quelqu'un y pense » (prompt v15 §8).

**Le registre.** `presti/lib/ai/cerveaux/<cerveau>/` : `cas.jsonl` (les cas de référence : demande client, métier, sortie attendue, origine, statut « référence » ou « ouvert » pour un défaut connu), `evaluer.mjs` (rejoue tous les cas, sort un score, refuse une baisse — branché au commit), `score.json` (le dernier score accepté, daté), `journal.md` (chaque amélioration : avant, après, pourquoi). Premier cerveau équipé : la **détection d'urgence**, avec le cas du vitrier — « ma vitre de salon est cassée » ressortait en *normal* depuis le 09/09. Un cas ouvert ne compte pas dans le score : le score protège la vérité établie, les ouverts sont le carnet de travail.

**État au 2026-09-14 (cerveau urgence).** Score **100 %**, **672 références** réussies sur 672 (`score.json`, daté du 2026-09-14). **2 cas ouverts** : `carreleur-s-06` et `carreleur-s-24` (une casse de carrelage déclarée urgente par le corpus ; un carreau cassé n'est pas un sinistre en cours, et on ne change pas un attendu pour faire passer un cas — à trancher avec des cas réels). Chemin parcouru : 65 % sur 20 cas le 2026-09-13 (le vitrier), puis 550 cas synthétiques (tâche 014-15) qui ont fait tomber 92 cas en ouvert, corrigés par la négation (« sans urgence »), les leurres (« anti-effraction ») et sept familles de paires objet × casse (toit, structure, électricité, chauffage, eau, gaz, végétation). Le corpus a ensuite été réécrit dans la langue des clients par un agent Gemini 3.8 Flash (tâche **014-20**, verdict PASS le 2026-09-14) : 654 cas synthétiques, 81 % accentués, 30 % de messages longs, 26 % façon SMS.

**Le vérificateur du corpus.** `scripts/cas-urgence-verifier.mjs` juge la *vraisemblance* des cas, ce que l'évaluateur ne regarde pas — la première livraison (550 lignes, 17 messages accentués, médiane 44 caractères, « Devis pose… » trente-quatre fois) mesurait le cerveau sur une langue que les clients n'écrivent pas. Ce qu'il refuse : une ligne illisible, un identifiant en double, un cas auquel manque l'un des six champs (id, message, metier, attendu, origine, statut) ; moins de 500 cas synthétiques ; moins de 80 % de messages accentués ; moins de 15 % de messages longs (> 120 caractères) ou courts (< 40) ; un début de message répété plus de 12 fois ; un message en forme de gabarit (crochets, métier entre parenthèses, identifiant cité, mot répété, moins de 15 % de mots-outils — la livraison 014-20 refusée le 2026-09-13 en était un) ; un quasi-doublon (Jaccard sur les mots ≥ 0,8) ; moins de 5 pièges de chaque côté par métier (normaux avec un mot d'urgence, urgents sans aucun mot de la liste) ; un numéro de téléphone ou une adresse ; et un `evaluer.mjs` qui ne rend pas 0. Code 0 si tout passe, 1 sinon.

**Le cycle.** Chaque semaine : les scores au journal ; les échecs triés (consigne, connaissance métier, cas mal écrit) ; Antigravity propose des corrections ; Claude Code fusionne si le score monte sans en faire baisser un autre. Les scores se lisent dans le Poste de contrôle, onglet « Cerveaux » (`app/controle/Cerveaux.tsx`, route `/api/controle/cerveaux`) : score, cas, dernière amélioration.

**D'où viennent les cas.** Les défauts trouvés (le jour même, avant correction) ; des cas synthétiques par métier (Antigravity, relus par échantillon) ; plus tard, les corrections des artisans — uniquement avec le réglage « Aider Presti à s'améliorer » activé (désactivé par défaut) et après anonymisation testée. Jamais une conversation privée lue telle quelle : *la forme, jamais le fond*.

**Ce qu'une suite trouve que l'œil ne voit pas.** Le défaut « la suspension n'a pas d'effet » (prompt v15 §5), cherché à l'œil pendant des jours, a été trouvé le 2026-09-14 par la suite e2e `suspension-e2e` (tâche 014-17) ; la suite passe 29/29 en production depuis la réparation du déploiement (37 builds Vercel en ERROR depuis le 13/09 17 h 57 UTC, voir [[Produit/Antigravity]] « Poussé n'est pas déployé ») : la lecture de la suspension par imbrication PostgREST échouait en silence (PGRST201, « more than one relationship was found » — la table `suspensions` porte trois clés vers `artisans`), `maybeSingle()` rendait `null`, le code lisait « pas suspendu ». Le code fautif était la garde de connexion (`lib/authArtisan.ts`). Une première correction (nommer la clé, `suspensions!artisan_id`, commit 283b362) a encore échoué en silence ; la garde passe désormais par `suspensionEnCours()` de `lib/suspension.ts` (créé le 13/09 pour couper l'activité d'un compte suspendu), une seule source de vérité, fail-closed — une erreur de lecture vaut « suspendu » (commit a6c1da5). Même leçon que le vérificateur du corpus : ce qui « a l'air juste » se mesure de bout en bout.

**Ce qu'apprendre veut dire ici.** Pas d'entraînement, pas de fine-tuning (cher, lent, sans intérêt à cette taille) : des consignes plus justes, des règles de métier plus complètes, une base de prix qui s'enrichit — mesuré par des cas rejoués. Voir [[Produit/Antigravity]] pour la méthode de production.
