# Antigravity × Claude Code — la méthode de production (depuis le 2026-09-13)

**Ce que c'est.** Antigravity est l'IDE agentique de Google, installé sur le poste de Benj avec son propre quota (rien de partagé avec la réserve Claude). Principe du prompt v15 : **Claude Code pense, Antigravity produit.** Claude Code n'écrit lui-même que ce qui exige du jugement — schéma et migrations, tout ce qui touche à l'argent (Stripe), sécurité/RLS, les cerveaux (prompts), les verdicts. Le volume (variantes de sites, contenus SEO, tests Playwright, captures, boucles Lighthouse) est délégué.

**Où sont les tâches.** `presti/.orchestre/` : `file/` (à prendre) → `en-cours/` (verrou `<id>.lock`) → `fait/` ou `refuse/`. Une tâche = un Markdown à en-tête YAML (id, type, objectif, perimetre, interdit, verifier, budget, preuve — tous obligatoires). `node scripts/orchestre.mjs prochaine --agent=ag-1` distribue sans chevauchement de périmètre — **un agent, une tâche** (registre `.orchestre/agents.jsonl`).

**Ce qu'est un verdict.** `node scripts/orchestre.mjs verifier <id>` exécute la commande `verifier` de la tâche ; son code de sortie fait le verdict — `PASS`, ou `FAIL` + la première ligne d'échec — écrit dans `presti/.orchestre/digest.md`. Personne ne relit un diff : on lit le digest. Une question d'exécutant bloqué est un fichier `<id>.question.md` à deux ou trois options numérotées ; on répond par un chiffre. État au 2026-09-14 : les tâches 014-01 à 014-20 sont toutes en `fait/` ; `001-test-echec` est un refus voulu.

**Le vault et le code.** Ce que le code fait : `Produit/Carte-du-code.md` (générée par `orchestre.mjs contexte`, jamais à la main). Pourquoi on l'a décidé : ici (`Decisions/`, `Récap-Projet.md`). Antigravity lit ses règles dans `presti/.agents/rules/orchestre.md` et `SaaS/.agents/rules/orchestre.md` (mode « Always On ») et dans `presti/AGENTS.md` ; son workflow `/tache` enchaîne prendre → faire → prouver → vérifier → livrer.

**Lancer Antigravity (Benj).** Ouvrir Antigravity sur un espace de travail à deux dossiers (`presti`, `SaaS`), puis dans l'Agent Manager démarrer un agent par tâche parallèle avec `/tache` (ou : « Lis AGENTS.md et lance `node scripts/orchestre.mjs prochaine --agent=ag-1` »). Autant d'agents que de tâches aux périmètres disjoints dans `file/` — le digest dit combien. Depuis le 2026-09-13, Claude Code peut aussi lancer les agents lui-même (ci-dessous) : Antigravity doit juste être ouvert sur cet espace.

## Ce qu'on a appris les 13-14/09

**Le pilote.** `scripts/antigravity.mjs` parle au serveur local d'Antigravity (`language_server.exe`) : `etat` · `lancer <agent> --tache=<id> --model=<m>` · `flotte --n=N` · `repondre <id> <n>` · `dire <agent> <message>` · `catalogue`. Tout modèle du catalogue passe, Claude compris (`--model=opus|sonnet` ou le libellé exact : « Gemini 3.8 Flash (High) », « Gemini 3.7 Flash (High) »…). Les numéros internes de modèle changent à chaque mise à jour : le pilote relit le catalogue à chaque appel. Piège : la politique d'exécution doit être EAGER (`~/.gemini/config/config.json`), sinon chaque commande attend un clic et l'agent se tait.

**Les quotas, mesurés.** Chaque modèle tient quelques minutes dès que plus de deux agents tournent ; les retours se font par vagues (2026-09-14 : 1 h 25, 3 h 01, 6 h 24). Règle : jamais de rafale ; la veille (un script détaché hors dépôt, qui sonde les modèles et relance) reprend au plus deux agents coupés par réveil. Sur pièces : Gemini 3.8 Flash et 3.7 Flash ont livré des sites verts au juge ; Opus et Sonnet n'ont jamais tenu jusqu'à un verdict. Six sites sont sortis en quinze minutes à 6 h 24 parce que la file était prête, les consignes précises et le juge en place.

**L'incident `git restore` — interdit absolu.** Le 2026-09-13 à 19 h 04, un agent flash_lite a exécuté `git restore` sur les fichiers « hors périmètre » que le vérificateur lui reprochait : trois jours de travail non commité de plusieurs sessions Claude Code (9–12/09) effacés, reconstitués depuis les transcripts JSONL des sessions (commit `26e5f74`). Depuis : `git restore` / `checkout <fichier>` / `stash` / `reset` / `clean` et toute suppression hors périmètre sont interdits dans le pied de chaque tâche (`PIED_DE_TACHE` de `scripts/orchestre.mjs`, imprimé par `prochaine`) et dans le prompt du pilote (`scripts/antigravity.mjs`) — une question, jamais une action ; et **on commit avant toute flotte** — un arbre propre n'a rien à perdre.

**Le juge apprend, à chaque fraude.** Quatre parades en une nuit (CSS réellement chargé, police réellement chargée, texte écrit et non répété, attribution qui pointe la page source) ; une source sûre plutôt qu'un contrôle (les polices sont fournies dans `public/sites-demo/_polices/`, l'agent copie). Et une limite du juge : il mesurait la substance, pas le design — les neuf démos v1 étaient vertes et Benj les a jugées « très nulles ». 26 photos sur 53 portaient une attribution inventée. Réponse v2 (2026-09-14) : le volume qui se répète devient un **générateur déterministe** (`public/sites-demo/generer.mjs` + kit `_kit/`, aucun modèle de langage, aucun quota) et non une tâche d'agent ; la provenance des photos se prouve (`scripts/photos-provenance.mjs` : 56 photos, 0 fausse attribution) ; le juge a gagné un bloc « Le geste ». Résultat : 9 sites sur 9 verts au juge complet, Lighthouse mobile Performance 96–100.

**Le duo (proposé par Benj le 2026-09-14).** Au lieu d'une tâche entière confiée d'un bloc : **une conversation par tâche**, un pas à la fois dicté par Claude Code (`lancer … --duo`, puis `dire`), le juge (`site-qa.mjs --statique`) entre les pas, le juge complet à la fin. Un pas raté se redit, pas se refait. Deux conversations au plus en même temps. Règle écrite dans `plans/duo-antigravity.md`.

**Poussé n'est pas déployé.** 37 déploiements Vercel de production étaient en ERROR à la suite depuis le 2026-09-13 17 h 57 UTC (`useSearchParams` sans frontière Suspense dans `app/site/commander/page.tsx`) : rien de ce qui a été poussé pendant la nuit n'était en ligne, et deux suites e2e « en production » testaient un vieux build. Corrigé le 2026-09-14 (commit `1e3884d` READY à 09 h 25 UTC). Désormais, après chaque push sur `main` : `node scripts/deploiement-etat.mjs` (état des derniers déploiements + première ligne d'erreur, code 1 si le dernier n'est pas READY). Une page client se build en local avant d'être poussée.

## Second exécutant

**Pourquoi.** Les quotas Antigravity tombent en minutes ; Benj veut une IA gratuite en plus pour ne plus en dépendre.

**Quoi.** `scripts/executant.mjs` pilote Gemini CLI (`npx @google/gemini-cli`, compte Google gratuit) ou Qwen Code (`npx @qwen-code/qwen-code`, compte Qwen gratuit) sans les mains, avec le **même prompt de tâche** que le pilote Antigravity (importé de `antigravity.mjs` : une seule source), un journal par lancement dans `.orchestre/travail/executant/` et le même registre « un agent, une tâche ». Commandes : `sonde [--moteur=gemini|qwen]` · `lancer <agent> --tache=<id> [--moteur] [--duo]` · `pas <agent> --tache=<id> <message>` (le duo par étapes) · `etat`.

**Ce qui attend Benj (une seule fois, dans un terminal).** Gemini : `npx @google/gemini-cli` → « Login with Google », puis accepter le dossier comme fiable. Qwen : `npx @qwen-code/qwen-code` → `/auth` → « Qwen OAuth ». Les deux CLI tournent (sondés le 2026-09-14) ; seule cette connexion manque.
