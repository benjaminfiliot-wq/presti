## Contexte

Le plan (§5.7) prévoit un interrupteur `ops.pause_generale` qui coupe tout ce qui sort : envois, publications, mises en ligne. Il se commande de quatre façons :
1. depuis le Poste, sous reconfirmation `securite` : l'interrupteur **AUTO** de la station Mission Control, téléphone compris (026-117 : `{ actif, motif }` vers `/api/controle/pause`, après le mot de passe) ;
2. PC éteint, le **pont Telegram** de l'usine : `/pause <motif>` (026-195) ; il pose la pause, il ne la lève jamais ;
3. **Claude Code**, sur l'ordre de Benj (dans la conversation, ou par Remote Control de Claude Code depuis le téléphone quand le PC est allumé), exécute la ligne SQL de secours par le connecteur Supabase (`execute_sql`) ;
4. la variable Vercel, en dernier recours.

Les commandes déjà payées continuent.

**Qui envoie, depuis le 24/09 (décision de Benj).** Les agents trouvent, écrivent, envoient, relancent, répondent et qualifient. Benj ne prend que les appels. Ce qui fait sortir quelque chose vers un tiers :
- le **Facteur** : il juge et approuve chaque envoi, puis envoie les messages `email_sollicite` par le Gmail de prospection et les réponses Meta dans leur fenêtre (026-089) ;
- le **porteur du formulaire**, sur l'usine (026-095) : il soumet les formulaires approuvés ; il prend son travail par la route `travail`, qui rend `[]` pendant la pause, et relit la pause avant chaque soumission ;
- le **Répondeur** : il répond dans le fil (e-mail, Instagram, Facebook), se présente comme l'assistant IA de Presti ;
- les **réponses privées** Meta à un commentaire « SITE » et la **messagerie** Instagram et Facebook ;
- le **Crieur** : il dépose ses publications en brouillon dans Publora ; Benj programme celles qu'il accorde (27/09, R24 ; avant : « il publie ») ;
- la **mise en ligne** d'un site.

**Ce qui existe déjà :**
- **Dans la base** : la ligne `ops.interrupteurs('pause_generale')` (0096), `ops_interrupteur(p_nom)` et `ops_interrupteur_poser(p_nom, p_actif, p_motif, p_auteur)`, qui exige un fondateur et journalise dans `ops.evenements` (0097). Pendant la pause, `ops_tache_prendre` n'attribue plus aucune tâche sortante (0098), et le déclencheur des envois refuse toute carte qui **entre** en `prepare` ou en `approuve` (0099). Le passage à `envoye`, lui, n'est **jamais** refusé : il consigne un message déjà parti (par exemple un formulaire soumis par le porteur juste avant la pause), et la base écrit seulement un événement `envoi_hors_regle` (026-034).    - `process.env.PAUSE_GENERALE === '1'` → active, source `variable`, sans appel à la base ;
   - sinon, la fonction `ops_interrupteur` de `lib/agents/bus.ts`. `true` → `base` ; `false` → inactive ;
   - **erreur ou base injoignable → active, source `panne`**. Quand on ne sait pas, rien ne sort.
2. **`app/api/controle/pause/route.ts`** :
   - **GET** : `estFondateur`, puis `exigerDomaine(f, 'securite', 'voir')`. Rend l'état de `pauseGenerale()`.
   - **POST** `{ actif: boolean, motif: string }`, dans cet ordre :
     1. `estFondateur` ;
     2. `exigerDomaine(f, 'securite', 'ecrire')`, qui refuse un partenaire en lecture ;
     3. `exigerReconfirmation(req, f.uid, 'securite')` ;
     4. un motif de 3 à 200 signes, sinon 400 ;
     5. `journaliser({ action: 'pause_generale', cible_type: 'interrupteur', cible_id: 'pause_generale', avant, apres, reconfirme: true })`. S'il rend `false` → `refusJournal()` (503), et rien ne change ;
     6. `ops_interrupteur_poser('pause_generale', actif, motif, f.uid)` ;
     7. le nouvel état en réponse (sans champ `sequenceur` : il n'y a plus de file externe).
   - `runtime = 'nodejs'`, `dynamic = 'force-dynamic'`.
3. **`lib/direction/journal.ts`** : ajouter `'pause_generale'` au type `Action` (`:11-26`). Rien d'autre.
