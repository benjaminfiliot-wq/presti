# 026-245 — le SAV : réponses aux clients déjà payants, brouillons d'abord, escalade

## Place dans la série

- **Id :** 026-245 (poste manquant n° 2 de l'organigramme du 27/09, §6, « Service client après la vente ») ; **vague :** à situer par Claude Code lors de l'intégration à `INDEX.md` ; **exécutant :** codex, **sur l'usine** (comme le Standard et le Répondeur, 026-085/026-096 : le classement et la rédaction du brouillon appellent Codex avec une donnée de client, D1 — les routes restent sur Vercel, seul l'appel de modèle se fait sur l'usine).
- **Dépend de (PASS) :** 026-244 (le juge de cette fiche, qui écrit `scripts/sav-qa.mjs`) ; **bus :** 026-040 (jetons d'agents), 026-042 (routes `/api/agents/*` derrière `busAgents`), 026-050 (compte `agents` et coffre de l'usine) ; **argent/Stripe :** aucune dépendance directe (le SAV ne touche pas l'argent — un remboursement s'escalade, il ne se décide jamais ici) ; **livraison des sites :** 026-021 (migration 0103 : colonnes de livraison de `sites_commandes`, la source du rattachement client ↔ commande), 026-100 (`livrer-site.mjs`, la commande dont le client parle) ; **pause générale :** 026-044 ; **station :** 026-070 (`EQUIPAGE`), 026-092 (routes de la station), 026-083 (J3 : modèles approuvés, liste fermée des affirmations, dont ce module reprend le garde) ; **portier générique :** 026-074 (routes des gestes, dont « trancher » — le geste que Benj pose pour approuver un brouillon).
- **Point ouvert, non couvert par une fiche existante** (même nature que pour 026-243) : aucune migration n'a encore seedé une identité `sav` dans `ops.agents` (contrairement à `tresorier`, `garde`, `studio`, `contenu`, `douleurs` seedés par 026-175). Avant de lancer cette fiche, Claude Code écrit et applique une petite migration qui seed `sav` (sans jeton ni pause, comme les cinq autres), puis émet son jeton par `agents-jeton.mjs` (026-040) et sa capacité `pause`. C'est un geste hors du périmètre de cette fiche, comme tous les jetons et toutes les migrations (jamais par l'exécutant codex).
- **Salle :** Presti — vacante aujourd'hui (§4 de l'organigramme : « Presti | argent | — | sans titulaire »), où la station montre déjà le nombre agrégé de tickets de support (026-174, 026-189) sans agent nommé. Cette fiche ne modifie pas la station (hors périmètre) ; Claude Code branche `sav` comme titulaire de cette salle à l'assemblage.

## Contexte

Reprend la suspension de Support (A13, décision D18 du 09/09, « ce sont des humains qui répondent ») **sans la lever** : le SAV écrit des brouillons, jamais un envoi libre. Il ne peut ouvrir l'automatique que pour la **FAQ**, et seulement après **20 approbations consécutives sans retouche** du même type de question — l'exécutant ne décide jamais lui-même quand ce seuil est atteint : c'est le compteur, tenu par la base, qui tranche, et Claude Code confirme le premier franchissement avant toute mise en service réelle.

**Aucun envoi à un client sans l'accord de Benj.** Note pour l'assembleur : la formulation « accord individuel, 24 h au plus » évoque R24, mais **R24 dans `INDEX.md` désigne une règle différente** (le Crieur : Benj programme chaque publication qu'il accorde, tranché le 27/09). Cette fiche **n'emploie pas** le nom « R24 » pour la règle du SAV, afin de ne pas entrer en collision avec ce nom déjà pris — elle la décrit en toutes lettres : *un brouillon attend l'accord individuel de Benj, posé par le geste « trancher » de 026-074 ; passé 24 h sans réponse, le brouillon reste en attente (jamais un envoi par défaut), et remonte comme carte « à lire »*. Si Claude Code veut lui donner un nom court à l'intégration, un nom qui ne collisionne pas avec R24 est préférable (par exemple une lettre de domaine, « SAV-1 »).

## Ce qu'il faut faire

1. **`lib/agents/sav/repondeurClient.ts`**, ESM/TypeScript :
   - `classerMessage(message, deps)` : par le lecteur de modèle (`deps.lecteur`, Codex `personnelles: true` en production, le lecteur factice en essai) rend une classe parmi `question_faq`, `question_autre`, `remboursement`, `litige`, `hors_fil` ; un message sans identifiant de commande ou de compte devient `hors_fil` sans appel au modèle (le rattachement est du code, jamais deviné par le modèle) ;
   - `remboursement` et `litige` → **toujours** `escaladerBenj(message, motif)` : écrit une carte Attention, jamais un brouillon de réponse ;
   - `question_faq` et `question_autre` → `preparerBrouillon(message, modeleApprouve)` : un gabarit approuvé (liste fermée des affirmations, comme 026-083), jamais un texte libre du modèle, avec la référence de commande et le ton de Presti ;
   - `compteurApprobations(type)` : lu et écrit par la base (pas en mémoire du processus) ; incrémenté à chaque brouillon approuvé **sans retouche** (texte identique à la proposition), remis à 0 à la première retouche de ce type ; à 20, `question_faq` peut sortir en `automatique_faq` — **jamais** `question_autre`, qui reste en brouillon quel que soit le compteur.
2. **`app/api/usine/sav/travail/route.ts`** (`GET`, mêmes gardes que 026-097 : `authAgent(req)` doit rendre l'agent `sav`, `actif('busAgents')`, `pauseGenerale()` → `{ pause: true }` sans travail) : rend les messages de clients à classer, non encore traités.
3. **`app/api/usine/sav/brouillon/route.ts`** (`POST`) : dépose un brouillon (classe, texte, référence de commande) dans la file d'approbation du Poste ; pour une `escalade`, crée la carte Attention au lieu d'un brouillon ; jamais un envoi direct depuis cette route.
4. **`app/api/usine/sav/rapport/route.ts`** (`GET`, pour le Poste) : lit le compteur d'approbations par type, l'état des brouillons en attente et des escalades, sans jamais afficher le contenu d'un message dans un résumé destiné à un tiers.
5. **Envoi** : cette fiche ne crée **aucune** route d'envoi. L'approbation d'un brouillon passe par le geste générique « trancher » de 026-074 (hors périmètre) : Claude Code y ajoute, à l'assemblage, un type de décision `sav_brouillon` qui, approuvé, déclenche l'envoi par le canal du client (e-mail ou messagerie déjà connu de sa commande) — **jamais** un nouveau portier parallèle au Facteur ou à 026-074.
