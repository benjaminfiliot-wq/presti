## Contexte

Le plan (§4.4) veut deux digests par jour (7 h 30 et 18 h 30) et **une notification immédiate seulement pour** un paiement, un client qui demande un appel, un agent en panne depuis plus de 2 h ; au plus 3 notifications par jour pour le reste. Il dit aussi : « Web Push étendu aux fondateurs. `lib/push.ts` n'écrit aujourd'hui qu'aux artisans. »

Qui fait quoi :
- **le veilleur A0** (fiche 026-047, `lib/agents/veilleur.ts`) décide **quand** prévenir : ses urgents (`paiement`, `appel`, `panne_agent`, `argent_bloque`, `coupe_circuit`) partent par `envoyerAlertes` (`lib/alertes.ts:305`), le digest aussi (motif `digest`), et c'est lui qui tient le plafond de 3 par jour ;
- **cette fiche** donne le **second canal** : chaque alerte d'entreprise de ces motifs part aussi en Web Push sur les appareils des fondateurs.

Ce qui existe :
- `lib/push.ts` : `envoyerPushArtisan(artisanId, charge)` (`:105-147`) envoie à tous les appareils actifs d'un compte (web et natifs), avec un plafond par heure (`:28`, `:122`), et une charge bornée, neutre et rembourrée à taille fixe (`chargeUtile`, `:58-69`) dont l'adresse est forcée sur un chemin Presti (`cheminSur`, `:52`). Un fondateur **est** un compte `artisans` (`is_founder`) : ses appareils s'abonnent par Paramètres → Notifications (`app/parametres/SectionNotifications.tsx:107-150`) comme ceux d'un artisan. Le service worker ouvre l'adresse de la notification au clic (`app/sw.ts:64-96`) ;
- `lib/alertes.ts` : `envoyer(al, simulation)` (`:311-328`) prend d'abord un verrou d'une fois par jour et par clé (`:312-313`), garde l'alerte (`:316`), puis envoie l'e-mail. **Le push se branche après ce verrou**, et hérite donc de son dédoublonnage ;
- `lib/pilotage/liens.ts` (fiche 06) : `lienPilotage({ decision?, bloc? })`, qui ne rend que `/controle?onglet=pilotage`, avec au plus un UUID de décision ou un nom de bloc.

**La règle qui compte** : une notification ne porte **jamais** le sujet ni le corps d'une alerte. Le sujet d'une alerte de paiement porte le nom de l'artisan (`lib/alertes.ts:266`) ; une push l'afficherait sur l'écran verrouillé. Le titre et la ligne viennent d'une **liste fermée**, par motif.

## Ce qu'il faut faire

1. **`lib/pilotage/notifications.ts`**, pur (imports permis : `./liens`, et `import type { ChargePush } from '@/lib/push'`) :
   - `MOTIFS_POUSSES = ['paiement', 'appel', 'panne_agent', 'argent_bloque', 'coupe_circuit', 'digest'] as const` ;
   - `chargeFondateur(motif: string): ChargePush | null` : `null` pour tout motif hors de la liste ; sinon :
     - `paiement` : « Paiement » / « Un paiement demande votre attention. Le détail est dans le Poste. » → `lienPilotage({ bloc: 'argent' })` ;
     - `appel` : « Appel à rendre » / « Quelqu’un demande à être rappelé. » → bloc `appeler` ;
     - `panne_agent` : « Agent en panne » / « Un agent ne donne plus signe de vie depuis plus de 2 h. » → bloc `agents` ;
     - `argent_bloque` : « Argent bloqué » / « Une commande payée n’avance pas. » → bloc `argent` ;
     - `coupe_circuit` : « Agents en pause » / « Des coûts sans recette ce mois : une décision vous attend. » → bloc `decider` ;
     - `digest` : « Le point du Pilotage » / « Décisions, appels et argent du jour : tout est dans le Poste. » → `lienPilotage()` ;
     - `tag` = `pilotage-<motif>`, `renotify` vrai pour les quatre urgents.
2. **`lib/push.ts`** : ajouter, sans toucher au reste :
   - `lireFondateurs()` : les `id` d'`artisans` avec `is_founder = true` et `est_demo = false` ;
   - `envoyerPushFondateurs(charge, dep = { fondateurs: lireFondateurs, envoyer: envoyerPushArtisan })` → `{ envoyes: number; raison?: 'aucun_fondateur' }` : la même charge à chaque fondateur par `dep.envoyer` ; une erreur sur un fondateur n'arrête pas les autres ; ne lève jamais.
3. **`lib/alertes.ts`**, dans `envoyer` seulement, **après** le verrou et la persistance : si `!simulation` et `al.a === 'entreprise'`, calculer `chargeFondateur(al.motif)` et, si elle n'est pas nulle, lancer `envoyerPushFondateurs(charge)` sans l'attendre et sans pouvoir lever (`.catch` qui journalise, comme `lancerPush` de `lib/notifications.ts:48-51`). L'e-mail part comme avant, que le push réussisse ou non. Rien d'autre ne change dans ce fichier.
4. `npm run typecheck` doit être vert.
