## Contexte

**L'usine** (`presti-ops/usine/LISEZMOI.md`) : `presti-usine`, Oracle Always Free, Paris, ARM 2 OCPU, 12 Go, Ubuntu 24.04, 24 h/24. Compte `usine` joint par `ssh -i ~/.ssh/presti-usine usine@88.96.53.3` (`PRESTI_USINE=usine@<ip>` si l'IP change). Il fait tourner les fiches de l'orchestre par Codex (`scripts/usine.mjs`, commit 698f8eb), **avec le réseau**, dans un arbre jetable. Clone du dépôt en lecture seule dans `~/presti`. Aucun secret aujourd'hui. Les commandes distantes passent par `ssh … 'bash -s'` avec le script sur l'entrée standard, après `. "$HOME/.profile"` (jamais `bash -l` : `clear_console` de `~/.bash_logout` change le code de sortie). Le modèle à suivre pour ssh est la fonction `distant()` de `scripts/usine.mjs` (options `-i <clé> -o BatchMode=yes -o ConnectTimeout=20 -o ServerAliveInterval=30`).

**Le besoin (rectification du 24/09, §3.12 ; décisions R11 et R12, provisoires ; R16 annulée).** Le chef, l'atelier des maquettes, le livreur et la surveillance tournent sur l'usine, PC éteint. Il leur faut leur jeton d'agent (026-040 : un jeton par agent, stocké haché dans la base, limité à ses types et à ses tables) ; le pont Telegram (026-195) y ajoute le jeton de son bot. **Un agent qui a besoin d'un secret ne tourne pas sur l'usine tant que ce coffre n'existe pas.**

**Les règles, dans l'ordre où elles protègent :**
1. **Un compte à part.** `agents` fait tourner les services ; il n'a ni sudo, ni shell de connexion, ni droit d'écrire le code qu'il exécute. `usine`, qui fait tourner Codex avec le réseau pour l'orchestre, **ne peut pas lire** le coffre : les droits Unix l'en empêchent, et le bac à sable de Codex ne les contourne pas.
2. **Le coffre ne reçoit que des clés plafonnées.** Liste fermée : `PRESTI_JETON_CHEF`, `PRESTI_JETON_USINE`, `PRESTI_JETON_ATELIER` (l'agent `atelier_maquettes`, nom fixé par 026-097 réécrite), `PRESTI_JETON_LIVREUR_USINE`, `PRESTI_JETON_FACTEUR_USINE` (le porteur du formulaire, 026-095 : voie gratuite du 25/09), `PRESTI_JETON_TELEGRAM`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (le pont Telegram, 026-195 et 026-196 : revue transverse du 25/09), `PRESTI_JETON_STANDARDISTE`, `PRESTI_JETON_FACTEUR` et `TELEGRAM_CODE_APPAIRAGE` (contre-revue du 25/09 au soir). `PRESTI_URL` n'est pas un secret : il se pose dans l'unité (`Environment=`), jamais dans le coffre. **Jamais** la clé de service Supabase (écriture complète), jamais une clé Stripe, jamais la clé Anthropic du produit, jamais `.env.local`. Les formes connues de ces clés sont refusées **quel que soit le nom** sous lequel on essaie de les poser.
3. **Une valeur ne passe jamais en argument** : ni sur le poste (l'argv d'un processus se lit), ni sur l'usine (`ps`). Elle voyage sur l'entrée standard de ssh, une fois.
4. **Une valeur ne s'imprime jamais** : aucun outil ne sait la relire. On liste des **noms**.
5. **Chaque service ne reçoit que ses variables** : `avec-coffre.mjs` lit le coffre et ne passe à la commande que les noms qu'on lui donne (pas de `EnvironmentFile=` systemd, qui chargerait tout).
6. **Deux mises en œuvre des mêmes règles** (le script bash sur l'usine, le module Node sur le poste), jugées sur **la même table de cas** : elles ne peuvent pas diverger sans que le juge le voie.

**Le code déployé.** `/srv/presti-agents` : un arbre de travail détaché de `~/presti` (clone en lecture seule) sur `origin/main`, propriété d'`usine`, lisible par le groupe `agents`. Seul le code poussé sur `main` (après PASS et push par Claude Code) y tourne. `npm ci --ignore-scripts` y est lancé par `usine`, **jamais** par `agents` : aucun script d'installation d'un paquet ne tourne là où le coffre est lisible. Les écritures des agents vont dans `/home/agents/travail`, vers lequel pointe `/srv/presti-agents/.orchestre/travail`.

**Deux assistants, seuls permis à `usine` sous `agents`** (sudoers) : `presti-coffre` et `presti-journal`. Ils permettent à Benj de poser une clé, et au juge (sur le poste, par ssh) de relire les journaux des agents, qui ne contiennent aucune donnée personnelle par construction (leurs juges le vérifient).

**Tout reste reprenable par le poste** : `docs/agents/usine.md` donne, service par service, la commande à lancer sur le PC si l'usine tombe ou est reprise par Oracle.
