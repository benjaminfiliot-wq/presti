## Contexte

**Dépend de :** 026-121 et 026-105 (`commun.mjs`).

**Revue hebdomadaire (A11).** Une routine Claude écrit chaque lundi `docs/revues/AAAA-SS.md`, sans jamais inventer un nombre : elle commente un JSON calculé ici.

Les sources :
- `.orchestre/verdicts.jsonl` : une ligne JSON par verdict, `{id, verdict: PASS|FAIL|REFUSÉE|EXPIRÉE|DISJONCTÉE|QUOTA, ligne, code, date (ISO UTC), duree_s, agent, executant, lignes, dossier: en-cours|fait|refuse}` ;
- `.orchestre/agents.jsonl` : les lancements, `{agent, tache, modele, date}` ;
- l'état du bus, `GET /api/agents/etat`, lu par `lireJeton()` et `baseSure()` de `scripts/chef/commun.mjs`, sans jeton affiché.

**Chantier (A12).** Une idée approuvée devient une fiche proposée dans `.orchestre/propositions/<id>.md`, avec son juge écrit par la routine. Avant son dépôt dans `.orchestre/file/`, un garde déterministe la vérifie. Ce garde dit aussi quels changements pourraient être fusionnés sans Benj : les textes, `docs/**`, et un test e2e **nouveau**. Jamais un juge ni un test existant.

Le validateur d'en-tête existe : `node scripts/orchestre.mjs valider <fichier>` sort en code 0 ou 1. Les deux juges, écrits par Claude Code, te renvoient leurs lignes d'échec. Tu ne lances rien dans ton bac à sable.

## Ce qu'il faut faire

1. **`scripts/chef/revue-donnees.mjs --semaine=AAAA-SS [--verdicts=<f>] [--agents=<f>] [--etat=<fichier JSON> | --base=<url>] [--sortie=<f>]`**. Les défauts sont `.orchestre/verdicts.jsonl`, `.orchestre/agents.jsonl` et la sortie standard.
   - La semaine est une semaine ISO, du lundi 00 h au dimanche 24 h, **heure de Paris**.
   - Par exécutant (`executant`, sinon `agent`) :
     - `pass` et `fail` : les verdicts de la semaine ;
     - `taches_reussies` : les ids qui ont un PASS depuis `fait/` dans la semaine ;
     - `minutes_mediane_par_reussite` : médiane, en minutes arrondies, entre le premier lancement de la tâche dans `agents.jsonl` et son PASS depuis `fait/` ; `null` sans lancement connu ;
     - `quotas`, `expirees` et `disjonctees`.
   - `lignes_illisibles` : les lignes JSON invalides, comptées sans plantage.
   - `fraicheur` : `{verdicts: <date de la dernière ligne lue>, etat: <date de l'état ou "non mesuré">}`.
   - `argent` et `entonnoir` : repris tels quels de l'état s'il contient ces clés, avec leur `source`. Sinon `"non mesuré"`. Un état absent, un 401 ou une erreur réseau donnent « non mesuré », avec le code 0.
   - La forme exacte, clé par clé, est celle de `scripts/fixtures/026/revue/attendu.json`. **Lis-la : c'est le contrat.**
   - Aucune écriture hors `--sortie`, aucun appel hors `--base`.
2. **`scripts/chef/chantier.mjs`**, quatre sous-commandes. Aucune commande git d'écriture : pas de `push`, `commit`, `merge`, ni `gh`.
   - `idees --depuis=<ISO> [--base=…] [--sortie=<f>]` (revue du 24/09, A6) : `GET <base>/api/agents/decisions?tranchees=1&depuis=<ISO>` avec `lireJeton()` et `baseSure()` de `commun.mjs` (le jeton en en-tête `Authorization`, jamais dans l'URL) ; garde les seules décisions dont `cle_idempotence` commence par `chef:` suivi d'une date et de `:idee-`, et dont `choix` vaut `lancer` ; écrit `[{ id, cle_idempotence, tranchee_le }]` dans `--sortie` (sortie standard par défaut). Tout code autre que 200 → code 1, sans fichier. `ops_etat()` ne rend que les décisions ouvertes : c'est la seule façon de retrouver une idée que Benj a tranchée ;
   - `verifier-fiche <fichier> [--racine=…]` sort en code 0 seulement si :
     - `orchestre valider` passe ;
     - la fiche porte une ligne `Décision : chef:<AAAA-MM-JJ>:idee-…` ;
     - **le juge proposé échoue aujourd'hui** (revue du 24/09, B2) : `verifier-fiche` lance lui-même la commande `verifier` de la fiche dans la racine, sous le budget de la fiche, et exige un code ≠ 0 **et** une ligne en échec qui porte un identifiant de critère (`[A-Z]{2,5}-<nombre>`). Un juge vert avant la fabrication, ou un échec sans identifiant (plantage), est refusé ;
     - aucun motif du périmètre ne touche une zone protégée quand `executant` n'est pas `claude-code`. Les zones : `supabase/**`, `lib/plans.ts`, `lib/stripe*`, `app/api/stripe/**`, `proxy.ts`, `middleware.ts`, `lib/ai.ts`, `lib/agents/llm.ts`, `app/api/agents/**`, `vercel.json`, `scripts/*-qa.mjs`, `scripts/juges/**`, `scripts/fixtures/**`, `.claude/**`, `.github/**` et tout chemin en `../`. La comparaison se fait par préfixe littéral, comme `orchestre.mjs` ;
     - le script lancé par `verifier` existe dans la racine et n'est pas couvert par le périmètre ;
     - l'id n'existe dans aucun de `file/`, `en-cours/`, `fait/` et `refuse/`.

     Sinon, code 1 avec une ligne par raison.
   - `fusion-permise <base> <tete> [--racine=…]` lit `git diff --name-status <base> <tete>`. Il sort en code 0 seulement si chaque chemin est sous `docs/`, est un `plans/*.md`, ou un `scripts/*-e2e.mjs` en statut `A` (ajouté). Sinon, code 1 avec la liste.
   - `deposer <fichier> [--racine=…] [--base=…]` lance `verifier-fiche`, relit la décision de la ligne `Décision :` par `GET …/api/agents/decisions?tranchees=1` et exige qu'elle soit tranchée `lancer`, puis copie la fiche dans `.orchestre/file/<id>.md`. Il ne modifie jamais la source et refuse d'écraser.
