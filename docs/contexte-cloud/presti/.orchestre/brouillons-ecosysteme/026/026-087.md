## Contexte

**Dépend de :** 026-083 PASS (modèles, douleurs, `jugerMessage`), 026-073 PASS (`DOULEURS`).

**Décision du 24/09, voie gratuite du 25/09** : la Plume remplit un modèle approuvé avec un fait sourcé et une douleur tirée de la bibliothèque ; J1, J3 et le second juge jugent ; le Facteur approuve ; le porteur de l'usine soumet le formulaire (026-095). **Aucun humain n'appuie sur « Envoyer »** : entre professionnels, la base légale est l'intérêt légitime quand l'objet est lié au métier (CNIL, 10/06/2026). La Plume ne fait partir **rien** : elle prépare (`prepare`) ; le Facteur approuve.

**Pourquoi sans modèle de langage.** Le texte est un modèle approuvé ; seuls changent le fait cité (mot pour mot), la douleur (tirée d'une liste approuvée), l'adresse, la notice, la référence et les noms. Un modèle de langage n'apporterait que de quoi se tromper (règle 1 du plan §2.1 : « le déterministe d'abord »). La Plume n'appelle aucun modèle et n'a pas besoin du réseau.

**Les plafonds** (voie gratuite §2) : le formulaire monte par paliers, 5, 10, 20, 30 puis 40 par jour ouvré. La valeur fait foi dans la base (`plafondDuJour('formulaire_site')` et `envoisDuJour('formulaire_site')` ; la ligne `(formulaire_site,'*')` est écrite par 0111 à partir des paliers), qui refuse aussi d'elle-même le message de trop et le second formulaire à une entreprise (0099), et le rend `{ ok: false, raison: 'quota_nouveaux' | 'formulaire_deja' }`, jamais par une exception.

**La variante A** (« J'ai préparé une maquette ») : elle ne part qu'après le PASS de 025-02, drapeau `varianteA` levé, et seulement si la maquette existe déjà. Par défaut, B (« Je peux vous préparer… ») : la maquette ne se fait qu'après un « oui » (l'Atelier, 026-097).

**Plus de relance à froid** (garde-fou 8) : un formulaire par entreprise, à vie, jamais relancé. La seule relance est `relance_oui_v1`, une fois, après un « oui », annoncée dans le message du lien : c'est le Répondeur qui la prépare (026-096).

## Ce qu'il faut faire

1. `executerRedacteur(deps)`, `deps = { magasin: Magasin, horloge, echeance, adresseReponse: string, drapeaux: { varianteA: boolean }, modeles?: typeof MODELES, douleurs?: typeof DOULEURS }` (défauts : les imports de `./modeles` et `./douleurs` ; le juge peut en passer des copies).
2. D'abord `magasin.perimerEnvois()` (les envois préparés depuis plus de 20 h sans partir reviennent à leur étape : un fait se relit avant de partir).
3. `magasin.etatEnvoi()` : `envoi_froid` faux → bilan `envoi_froid_ferme`, **rien d'autre** ; `adresseReponse` vide → bilan `en_attente_adresse`, rien d'autre ; `NOTICE_URL` nulle → bilan `en_attente_notice`, rien d'autre.
4. **Les premiers contacts** : `n` = le reste du jour de `(formulaire_site,'*')` (`plafondDuJour` moins `envoisDuJour`, en nouveaux) ; `prospectsPourPremierContact('formulaire_site', n)` rend au plus `n` prospects `maquette_prete` puis `verifie` au formulaire éligible, dont aucune entreprise (même SIREN ou même domaine) n'a déjà reçu de formulaire. (Contre-revue du 25/09 au soir, I5) Tant que `etatEnvoi().ads_archive.permis` est faux, un prospect dont la `source` est `meta` est **sauté** (compté dans le bilan sous `ads_archive_non_lue`, jamais préparé) : la lecture datée des conditions de l'API se fait en 026-162. Instagram et Facebook : leur plafond à froid vaut 0, la boucle n'y prépare rien, sans cas particulier dans le code. Pas de `reserver` ici : ses tentatives enverraient à tort un prospect non retenu vers `a_decider`. Aucune relance : `prospectsPourRelance` n'est jamais appelé ici.
5. **Le contenu**, déterministe :
   - le modèle : `formulaire_studio_v1` pour une `marque` ; sinon `formulaire_A_v1` si `drapeaux.varianteA` **et** `maquetteDe(prospect)` rend une maquette prête et non expirée ; sinon `formulaire_B_v1` ;
   - le sujet, seulement si le formulaire du prospect a un champ de sujet : `sujet_formulaire_v1` (`{entreprise}` = `prospect.entreprise`) ou `sujet_studio_v1` (`{produit}`) ; sinon `objet: null` ;
   - le fait : pour un artisan, un fait qui parle de refonte, dans cet ordre : `site_copyright`, `site_http`, `site_mobile`, puis `site_h1`, `site_titre`, `site_intertitre` ; à égalité, l'extrait le plus court d'au moins 20 signes ; pour une `marque`, son fait `pub_meta` et son `produit` ; sans fait `ok`, pas d'envoi (événement `aucun_fait_verifie`) ;
   - la douleur (artisan seulement) : parmi les douleurs **approuvées** du métier du prospect, celle d'indice `SHA-256(cle_dedup) mod n` (même prospect, même douleur) ; aucune douleur approuvée pour ce métier → pas d'envoi (événement `aucune_douleur`) ;
   - `{adresse}` = `deps.adresseReponse` (l'adresse de prospection, écrite en toutes lettres deux fois) ; `{notice}` = `NOTICE_URL` ; la phrase de `SOURCES_LISTE` de la source du prospect (`ademe_rge` ou `meta`) ;
   - `{reference}` : 6 signes `[A-Z0-9]` tirés du SHA-256 de `prospect.id + ':' + modele_id + ':' + <jour de Paris>` (le texte n'entre pas dans le calcul : pas de cercle) ; une référence déjà prise (`{ ok: false, raison: 'reference' }`) → un second essai avec le suffixe `:2`, puis on passe ;
   - **la longueur** : le texte rempli ne dépasse jamais le `max` du champ de message du formulaire du prospect (`formulaire.longueur_max_message`) ; sinon pas d'envoi (événement `longueur_champ`).
6. `jugerMessage(...)` ; refusé → aucun envoi, événement avec les **codes** de raison (jamais le texte) ; accepté → `preparerEnvoi({ prospect_id, type: 'premier_contact', canal: 'formulaire_site', envoyeur: 'facteur_usine', destinataire: <URL de la page du formulaire>, objet, texte, empreinte_texte: SHA-256 du texte, modele_id, variante, fait_id, douleur_id, fil_envoi_id: null, conversation_id: null, preuve_demande: null, reference })`. Un refus de la base (`{ ok: false }`) n'arrête pas les autres envois.
7. `preparerMessageLien(prospect, { lien, paiement, rendez_vous, date_fin, canal, destinataire, preuve_demande, fil_envoi_id, adresseReponse, drapeaux }, deps)` : **jamais** de contrôle d'`envoi_froid` ici ; `canal` est `email_sollicite` ou `messagerie` ; choisit le modèle par trois questions, sans autre cas : le prospect est-il un entrant (`source = 'entrant'`) ? le canal est-il `email_sollicite` ou `messagerie` ? `drapeaux.siteAchatPublic` est-il levé (sinon la forme `_rdv`, et `paiement` n'est pas utilisé) ? ; le froid prend `lien_maquette_email_v2` ou `lien_maquette_meta_v1`, l'entrant `lien_maquette_entrant_email_v1` ou `lien_maquette_entrant_meta_v1` (sans fait) ; **sur `email_sollicite`** : envoyeur `gmail`, `destinataire` = l'adresse de la personne (l'expéditeur de sa réponse, ou l'adresse qu'elle a donnée), `preuve_demande` **obligatoire** (`{ type: 'message_recu', id }` : la réponse « oui » ; ou `{ type: 'case_entrant', id }` : la demande entrante, 026-145), sans elle → refus `preuve_demande_absente` sans rien préparer ; rend le texte rempli et jugé par `jugerMessage` (avec les mêmes `drapeaux`), ou un refus (`modele_non_approuve` tant que Benj n'a pas approuvé). C'est la route de l'Atelier (026-097) qui l'appelle, côté Vercel, quand elle crée le lien : le jeton en clair ne sort jamais de Vercel.
8. Un événement de bilan par exécution, sans donnée personnelle (compteurs : premiers contacts, refus par code, formulaires trop courts). Aucun `fetch`, aucun `process.env` (l'adresse de prospection arrive par `deps`).
