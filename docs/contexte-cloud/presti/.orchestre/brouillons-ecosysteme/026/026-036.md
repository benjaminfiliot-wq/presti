## Contexte

La recherche du 24/09 (`SaaS/Produit/Ecosysteme-Recherche-Agents-2026-09-24.md` R8) recommande Supabase Queues (`pgmq`) pour le chemin de l'argent, plutôt qu'une file maison :
- `pgmq` livre un message exactement une fois dans sa fenêtre d'invisibilité ;
- il archive ce qu'il a traité ;
- il vit déjà dans Postgres.

Chaque étape d'une commande devient un message, avec l'identifiant de la commande pour clé d'idempotence. Après 3 lectures sans succès, le message est archivé et une ligne part dans « Attention ».

Le premier usage est posé en 026-046 : une commande de site `payee` (`lib/siteCommande.ts:27` pour les états) doit **toujours** faire naître sa tâche de livraison, même si un maillon tombe entre-temps. Aujourd'hui, le webhook encaisse de façon idempotente (`lib/siteCommandeServeur.ts:52-97`) et prévient l'entreprise, puis rien ne suit sans Benj.

**Exactement une fois, jusqu'où.** `pgmq` garantit une livraison, pas un effet. Un effet externe (un e-mail, un appel à une API) peut encore se produire deux fois si le processus meurt entre l'effet et sa marque. La table `ops.argent_messages` porte donc la clé et la marque `fait_le`. Un gestionnaire idempotent (fiche 13) consulte la marque avant d'agir. Les effets de ce premier gestionnaire restent dans la base, où ils sont idempotents par construction.

**[à vérifier dans la documentation Supabase du jour] :**
- l'activation de `pgmq` sur l'offre de Presti, soit par `create extension if not exists pgmq`, soit par Database → Integrations → Queues ;
- les signatures `pgmq.create`, `pgmq.send`, `pgmq.read`, `pgmq.delete`, `pgmq.archive`, `pgmq.set_vt`, `pgmq.metrics` et `pgmq.list_queues`.

Si la création par SQL est refusée, Benj active l'extension dans le tableau de bord, et la migration ne garde que `create extension if not exists`, qui est sans effet. **Ne pas activer « Expose Queues via PostgREST »** : on passe par nos fonctions.

Réservée à Claude Code : argent et schéma (`CLAUDE.md:23`).

| Fonction | Rend | Effet |
|---|---|---|
| `ops_argent_envoyer(p_type text, p_cle text, p_charge jsonb, p_delai_s integer)` | `bigint` ou `null` | Type hors liste → `ops:type_argent`. `insert … on conflict (cle) do nothing` : si la clé est déjà connue, rend `null` et n'envoie rien.
