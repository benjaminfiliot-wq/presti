## Contexte

**Le défaut** (contre-revue du 25/09 au soir, I2) : à chaque vente, 026-078 demandait à Benj de « soumettre le plan du site à la Search Console, puis appuyer sur Plan soumis » (5 min), un geste absent de la liste de ce que fait Benj, qui ne prend que les appels et les paiements. L'API de vérification de site et l'API de la Search Console sont **gratuites** ; un **compte de service** Google peut vérifier un site par un fichier, en devenir propriétaire, et soumettre son plan.

**Pourquoi par un fichier** : un site vendu est un dossier statique du bucket privé `sites`, sous `<commande>/…`, servi sur le domaine de l'artisan par la route des sites générés (`lib/sitesGeneres.ts`) ; poser un fichier `google<…>.html` dans ce dossier le rend visible à `https://<domaine>/google<…>.html`, sans DNS, sans toucher au générateur ni au livreur.

**Le geste de Benj, une fois** : créer, dans la console Google Cloud, un projet, y activer l'API de vérification de site et l'API de la Search Console, créer un compte de service et sa clé JSON, et la déposer dans `presti-secrets/google-search-console.json` ; Claude Code la pose dans Vercel (`GSC_COMPTE_SERVICE`, le JSON en base64) par le connecteur, sans l'afficher ni la lire à l'écran. S'il veut voir les sites dans sa propre Search Console, Benj s'y ajoute comme propriétaire plus tard ; ce n'est pas nécessaire.

## Ce qu'il faut faire

1. **`lib/sites/searchConsole.ts`** (tout le monde extérieur injecté : `fetch`, stockage, horloge, adresses de base) :
   - `jetonCompteService(env, deps)` : lit `GSC_COMPTE_SERVICE` (JSON en base64 : `client_email`, `private_key`) ; absent → `{ ok: false, raison: 'sans_compte' }`, aucun appel ; sinon un JWT RS256 signé par `node:crypto` (`iss` = `client_email`, `scope` = `https://www.[MASQUE_SECRET]/auth/siteverification https://www.[MASQUE_SECRET]/auth/webmasters`, `aud` = le point de jeton, 1 h), échangé contre un jeton d'accès (`grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`) ; jamais journalisé ;
   - `soumettreSiteSearchConsole(commande, deps)` : sans domaine propre (`domaine_mode = 'aucun'`) ou déjà soumise → `sans_objet` ; sinon, dans l'ordre : `POST …/siteVerification/v1/token` (`site: { type: 'SITE', identifier: 'https://<domaine>/' }`, `verificationMethod: 'FILE'`) → le nom du fichier ; le fichier écrit dans le bucket `sites` sous `<commande>/<nom>` avec le contenu attendu (`google-site-verification: <nom>`), et **aucune autre écriture** ; `POST …/siteVerification/v1/webResource?verificationMethod=FILE` ; `PUT …/webmasters/v3/sites/<site encodé>` ; `PUT …/webmasters/v3/sites/<site encodé>/sitemaps/<https://<domaine>/sitemap.xml encodé>` ; puis `search_console_le` posé **seulement** après cette dernière réponse 2xx ; rend `{ ok, etape, raison? }` ;
