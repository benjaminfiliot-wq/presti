## Contexte

Aujourd'hui, un site ne s'achète qu'avec un compte : `/api/site/commander` exige `authArtisan` (`app/api/site/commander/route.ts:22-23`), lit le brouillon de l'artisan et ouvre un Checkout Stripe à paiement unique avec facture (`:38-64`, `invoice_creation` et mention de franchise `:55`, métadonnées `type: 'commande_site'` et `commande_id` `:60-61`). Le webhook passe le brouillon à `payee` (`app/api/stripe/webhook/route.ts:40-43`, `lib/siteCommandeServeur.ts:52-98`).

Le plan (§6.4, « Achat public sans compte ») veut que les choses se passent dans cet ordre :
1. un visiteur paie sans compte ;
2. le compte est créé **après** le paiement, par `auth.admin.generateLink` ;
3. le lien part par Resend (`lib/email.ts:31`), et non par l'envoi par défaut de Supabase ;
4. surtout pas sur le modèle de `lib/clientAuth.ts`, qui sert les clients d'un artisan (`:5-10`).

Deux points du code actuel à corriger au passage :
- `poserSessionStripe` exige `artisan_id = uid` (`lib/siteCommandeServeur.ts:44-47`) : il faut une variante pour une commande sans compte ;
- `encaisserCommandeSite` cherche l'artisan par `avant.artisan_id ?? uid` (`:91`) : sans compte, il ne doit pas chercher du tout.

Dépend de :
- 025-07 PASS : `lib/stripeAiguillage.ts` et la branche des paiements orphelins ;
- rien du pack pubs : 026-112, qui touche aussi le webhook, passe **après** celle-ci (ordre fixé à l'assemblage) ;
- la fiche 05 (026-021, 0103 : colonnes `achat_public`, `entreprise`, `cgu_acceptees_le`, `lien_envoye_le`, `lien_envois`) appliquée ;
- la fiche 07 (`envoyerCourrielsDus`).

## Ce qu'il faut faire

1. **Un seul constructeur de Checkout.** `parametresCheckoutSite({ commandeId, email, clientStripe, uid, origin, public })` dans `lib/siteCommandeServeur.ts` rend l'objet passé à `stripe.checkout.sessions.create`. Il reprend à l'identique les lignes de prix, l'adresse de facturation, le numéro de TVA, `invoice_creation` avec `mentionFranchise('auto')`, l'interrupteur `STRIPE_TAXE_AUTO` et les métadonnées. La route avec compte l'appelle, sans changer son comportement. L'achat public ajoute `metadata.achat = 'public'` et `customer_email` ; il ne porte ni `uid` ni `client_reference_id`, et ses adresses de retour sont `/site/commander/merci?commande=<id>` et `/site/acheter?annule=1`.
2. **`POST /api/site/commander/public`**, dans cet ordre :
   1. 404 si `siteAchatPublic` ou `siteCommande` est baissé ;
   2. `isBanned(getIp(req))` : 403 ;
   3. le piège `website` rempli : 200 neutre, sans rien créer ;
   4. les plafonds `consommerLimite` : 5 par heure et par `ipPseudonyme`, 50 par jour pour tout le site, sinon 429 ;
   5. la validation : e-mail, `entreprise` de 2 à 80 signes sans HTML, `metier` de 2 à 60, `commune` de 2 à 80, `cgu === true` ;
   6. l'insertion d'une commande `brouillon`, avec `artisan_id: null`, `achat_public: true`, l'adresse en minuscules, `cgu_acceptees_le` et `prix_cents: PRIX_SITE_CENTS` ;
   7. le Checkout, puis `poserSessionStripePublique(id, sessionId)`, conditionnée à `artisan_id is null` et `etat = 'brouillon'`.

   Réponse : `{ url }`. Aucun compte n'est créé à cette étape.
3. **`lib/siteAchatPublic.ts`**, avec ses dépendances injectables :
   - `ouvrirCompteAcheteur(commandeId, deps)` :
     - la commande doit être `payee` et `achat_public` ;
     - `auth.admin.createUser({ email, email_confirm: true })` **sans mot de passe** ; l'erreur « adresse déjà inscrite » n'est pas un échec ;
     - `auth.admin.generateLink({ type: 'magiclink', email })` ; on garde `properties.hashed_token`, jamais `action_link` ;
     - un e-mail de Presti à `commande.email`, avec `critique: true`, dont le lien est `https://prestiapp.fr/connexion/lien?th=<hashed_token>&commande=<id>` ;
     - puis `lien_envoye_le` et `lien_envois + 1`. Si l'envoi échoue, l'erreur remonte et rien n'est marqué ;
   - `purgerBrouillonsPublics(deps)` : efface les commandes `brouillon`, `achat_public`, sans compte, créées il y a plus de 7 jours (minimisation des données).
4. **Le webhook**, dans la branche `commande_site` :
   - après `encaisserCommandeSite`, qu'il rende `encaissee` ou `deja_encaissee`, il relit la commande ; si elle est `achat_public` sans `lien_envoye_le`, `await ouvrirCompteAcheteur(id)`. Une erreur remonte, donc le webhook répond 500 et Stripe rejoue ; l'encaissement reste idempotent ;
   - puis `envoyerCourrielsDus(id).catch(journaliser)`, qui ne bloque jamais ;
   - `introuvable` lève toujours une erreur, comme avant. La branche `pack_pub` (026-112) ne change pas.
5. **`POST /api/site/commander/public/renvoyer`** `{ commande }` :
   - 404 si le drapeau est baissé ;
   - plafond de 3 par heure et par commande ;
   - si la commande est payée, `achat_public` et toujours sans compte, `ouvrirCompteAcheteur` ;
   - elle répond toujours `200 { ok: true }`, que la commande existe ou non ;
   - elle n'accepte jamais d'adresse dans le corps.
6. **Le drapeau** `siteAchatPublic: false` dans `lib/flags.ts`, avec son commentaire, et **une ligne** dans la carte de `scripts/fermeture-e2e.mjs` (`:226-248`) : `'siteAchatPublic': ['route', '/api/site/commander/public', 'POST', 'app/api/site/commander/public/route.ts', 'app/api/site/commander/public/renvoyer/route.ts']`.
7. **`lib/siteLivraison.ts`** : un appel à `purgerBrouillonsPublics()` dans `tourLivraison`, dans son propre `try`.
