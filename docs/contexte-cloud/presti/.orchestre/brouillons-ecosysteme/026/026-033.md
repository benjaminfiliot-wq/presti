## Contexte

Quand un site est payé, sa matière est en base : la ligne `sites_commandes` (`supabase/migrations/0088_site_commande.sql:31-62`, dossier dans `matiere`) et le profil `artisans`. Les photos sont dans le bucket public `artisan-media`, sous `<artisan_id>/…` (`lib/media.ts:4`, `app/api/media/route.ts:96-100`), et le dossier garde leur URL publique (`:122`).

Le générateur, lui, lit un dossier : `generer.mjs --source=<dossier> --sortie=<dossier>` (fiche 025-03). Ce dossier contient :
- `commande.json` ;
- `contenu.json`, écrit par le rédacteur (fiche 14) ;
- `photos/` et `photos/attributions.json`.

Le modèle exact est `scripts/fixtures/025/commande-exemple/` (champs `id`, `etat`, `slug`, `nom`, `email`, `telephone`, `metier`, `metiers_secondaires`, `communes`, `domaine_mode`, `domaine`, `matiere` avec `artisan`). Le lire avant d'écrire.

Règles du juge `scripts/site-qa.mjs` que l'export doit tenir :
- dès qu'un `attributions.json` est présent, chaque image doit avoir un auteur crédible, une source qui est une URL avec un chemin, et une licence permise (`:108-114`) ;
- la licence `propriétaire` est permise (`:75`).

Sécurité :
- la route d'envoi des photos déduit le type du paramètre `?ext=` sans lire les octets (fait établi le 24/09 ; la correction est dans la série 026-code-securite). L'export revérifie donc chaque image lui-même ;
- une photo de téléphone porte souvent la position GPS dans ses EXIF : elle ne doit jamais atteindre un site public.

Dépend de : 025-09 PASS (`matiere.artisan`), fiche 11 PASS (`erreursFabrication`, prestations).

## Ce qu'il faut faire

1. **Usage** : `node --import ./scripts/ts-loader.mjs scripts/commande-exporter.mjs <commande_id> --sortie=<dossier>`. Pour le juge seulement : `--depuis=<fichier.json>` (lignes commande et artisan lues dans un fichier au lieu de la base) et `--hote-photos=<url>` (serveur local des photos).
2. **La sortie** : refus en code 2, rien d'écrit, si elle est sous `<racine>/public`, ou dans le dépôt ailleurs que sous `.orchestre/travail/`. Les vraies livraisons vont dans `.orchestre/travail/livraison/<commande>/source/`, que git ignore (`.gitignore:84`).
3. **La lecture** : `.env.local` est chargé comme `scripts/site-deposer.mjs:17`, sans rien afficher. La commande doit être en `payee` ou en `generee` (régénération). Si `erreursFabrication(commande)` (`lib/siteCommande.ts`, fiche 11) n'est pas vide : code 3, les erreurs listées, rien d'écrit. Le téléphone vient de `artisans.tel_public`, sinon `tel` ; sans téléphone ni adresse de contact : code 3.
4. **Les photos** :
   - chaque URL de `matiere.photos[]` et `logo_url` doit désigner le bucket public `artisan-media` du projet Supabase, sous `<artisan_id>/`. Toute autre URL est refusée et listée, et n'est **jamais téléchargée** ;
   - lecture par l'API de stockage en `service_role`, pas par un `fetch` libre ;
   - chaque fichier passe par `sharp` : format `jpeg`, `png` ou `webp` exigé, sinon refusé et listé ;
   - sorties en webp et en avif, aux largeurs 480, 960 et 1600 qui ne dépassent pas l'original ;
   - **aucune métadonnée conservée** (pas de `withMetadata`) ;
   - si moins de 3 photos valides restent : code 3.
5. **`photos/attributions.json`**, au format de `scripts/fixtures/025/commande-exemple/photos/attributions.json` : `fichier`, `base`, `largeur`, `hauteur`, `largeurs`, `legende`, `alt`, `auteur` (le nom de l'artisan), `licence: "propriétaire"`, `source` (l'URL d'origine dans le stockage), et `modifiee: "Oui — recadrée et compressée par Presti"`.
6. **`commande.json`** au contrat de la fixture 025, avec `matiere.prestations` en plus. Aucune clé de plus.
7. **Les journaux** : nombres et chemins seulement. Ni adresse, ni téléphone, ni SIREN, ni nom de l'artisan dans la sortie standard ou d'erreur. Codes : 0 exporté, 2 usage, 3 dossier incomplet, 1 autre erreur.
