## Contexte

**Dépend de :** 026-109.

`bin/executant.mjs`, déplacé dans la source par la fiche 06, lance Codex en `exec` et boucle jusqu'à trois tours avec le vérificateur (`boucleCodex`). Quand la sortie de Codex contient « hit your usage limit … try again at <date> », il affiche la date et sort en code 3. **Mais la tâche reste dans `en-cours/`, verrouillée** : c'était le bloc de `presti/scripts/executant.mjs:132-138`, recopié tel quel dans la source. Le 17/09, Codex est resté bloqué jusqu'au 21/09 avec des tâches prises.

Par convention, les noms d'agents disent le moteur : `codex-<n>` pour Codex, `ag-<n>` pour Antigravity (`.orchestre/agents.jsonl`). Le champ `executant` d'une fiche est indicatif : seul `claude-code` réserve une tâche.

Depuis la fiche 07, `bin/orchestre.mjs` a un bloc « Attention » dans le digest, et `verdicts.jsonl` connaît les verdicts EXPIRÉE et DISJONCTÉE.

## Ce qu'il faut faire

1. **Le seuil pour les tests** : `binaireCodex()` renvoie `process.env.ORCHESTRE_CODEX_BIN` si la variable est posée. Si ce chemin finit par `.mjs`, `executer` lance `process.execPath` avec ce fichier en premier argument.
2. **Sur « hit your usage limit »** :
   - l'échéance se lit dans le texte « try again at Sep 30th, 2026 2:17 AM » : mois anglais, jour avec suffixe, année, heure sur 12 h. Elle s'entend à l'heure de Paris et s'écrit en UTC ISO. Sans date lisible, elle vaut maintenant + 6 h ;
   - `.orchestre/quotas.json` est fusionné, jamais écrasé : `{"codex": {"jusqua": <ISO>, "vu": <ISO>, "message": <160 signes au plus>}}` ;
   - `verdicts.jsonl` gagne `{id, verdict: 'QUOTA', ligne: 'codex à sec jusqu'au <date lisible>', executant: 'codex', agent, dossier: 'en-cours', …}` ;
   - la tâche est rendue à la file par le même chemin que `liberer`, puis on sort en code 3.
3. **`export function quotaActif(moteur)`** dans `executant.mjs` rend `{ actif: boolean, jusqua: string | null }`, lu dans `quotas.json`. Une échéance passée n'est pas active.
4. **Refus en amont** :
   - `executant.mjs lancer` avec le moteur `codex` sort en code 3, **sans lancer Codex**, quand le quota est actif ;
   - dans `bin/orchestre.mjs`, `prochaine --agent=codex-…` sort en code 2 avec « codex à sec jusqu'au <date> » quand le quota est actif. `quotas.json` est lu directement ; `orchestre.mjs` n'importe pas `executant.mjs`.
5. **Le bloc Attention** : une ligne par quota actif, « codex à sec jusqu'au <date> », avec la commande `node scripts/antigravity.mjs lancer ag-<n> --tache=<id>` pour chaque tâche en file qui porte `executant: codex`, deux au plus.
6. **Le `README.md`** : `quotas.json` et le réaiguillage.
7. **Dans presti** : `node scripts/orchestre.mjs maj`.
8. **À ne pas faire.** Ne pas lancer Antigravity automatiquement : le choix de relancer reste à Claude Code (au plus deux exécutants à la fois). Ne pas toucher `antigravity.mjs`. Aucune commande git.
