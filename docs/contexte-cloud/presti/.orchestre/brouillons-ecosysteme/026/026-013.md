## Contexte

La migration 0096 a posé les tables du schéma `ops`, fermées à tous. La 0097 a posé l'identité des agents, le journal et l'interrupteur. Ses fonctions :
- `ops_agent_pause(p_nom, p_pause, p_motif)` ;
- `ops_evenement_ajouter(p_agent, p_type, p_objet, p_resume, p_tache)` ;
- `ops_interrupteur(p_nom)`.

Cette migration pose la mécanique du bus, telle que la décrit le plan (`SaaS/Produit/Ecosysteme-Plan-2026-09-24.md` §3.3-3.4) et la recherche (`Ecosysteme-Recherche-Agents-2026-09-24.md` R4) :
- une tâche confiée porte une clé d'idempotence, son origine et une profondeur augmentée de 1 ;
- elle est prise sous un bail de 30 min ;
- un bail expiré remet la tâche en file et compte une tentative. Après 3 tentatives, la tâche devient une décision ;
- **disjoncteur par tâche** (R4) : la même erreur deux fois de suite arrête la tâche ;
- **disjoncteur par agent** : 3 échecs en une heure le mettent en pause et ouvrent une décision ;
- profondeur de 3 au plus, 5 sous-tâches au plus, quota quotidien de créations par agent ;
- les agents créent les décisions, **seul un fondateur les tranche** : `is_founder`. Benj est seul depuis le 24/09 (Gabriel et Louis-Victor sont partis) : aucun rôle délégué n'est prévu ;
- un agent relit les décisions **qu'il a créées** une fois tranchées : le chantier A12 (026-121, 026-146) y retrouve les idées que Benj a dit de « lancer » ;
- une tâche se **clôt par sa clé** quand l'effet qu'elle attendait a eu lieu ailleurs : la livraison (026-141) clôt `livrer_site:<commande>` quand la commande atteint `generee`, sans prendre de bail ;
- l'option par défaut à l'échéance est toujours la plus prudente (plan §4.3).

La pause générale n'arrête pas le bus. Elle empêche seulement de **prendre** une tâche sortante (`envoi`, `publication`, `mise_en_ligne`). Les commandes déjà payées continuent (plan §5.7).
