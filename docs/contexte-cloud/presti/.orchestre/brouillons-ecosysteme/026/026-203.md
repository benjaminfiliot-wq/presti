## Contexte

Claude Code a écrit `usine-pubs-qa` et `search-console-qa` **avant** la production (026-199). Un juge qu'on n'a jamais vu échouer sur une vraie faute ne prouve rien (CV-6 de 026-001) : cette fiche plante des fautes réalistes dans des copies du code livré par 026-200 et 026-201 et exige que chaque juge les attrape avec le bon critère.

Chaque juge accepte `--racine=<dossier>` : il lit et exécute à partir de ce dossier.

## Ce qu'il faut faire

1. Pour chaque mutation : copier les fichiers utiles du dépôt dans `.orchestre/travail/026-203/<juge>/<mutation>/` (sans `node_modules`, `.git` ni `.next` ; jonction vers `node_modules`), lancer le juge sur la copie intacte (**témoin : code 0 attendu**), puis sur chaque copie mutée (**code ≠ 0 attendu, avec le critère nommé dans une ligne en échec**). `usine-pubs-qa` est lancé avec `--partie=routes,tourneur,unites`, `search-console-qa` sans option : **jamais `--reel`**.
2. **Mutations minimales à couvrir** (une copie par mutation, chacune **un** remplacement de texte exact) :
   - **usine-pubs-qa** :
     - la route `travail` accepte aussi le jeton de `chef` → UP-2 ;
     - la route `travail` renvoie le courriel du pack → UP-3 ;
     - la route `depot` accepte un chemin hors de `livraison/` → UP-4 ;
     - la route `rendu` passe le pack à `fabriquee` sans relire les fichiers → UP-5 ;
     - la route `rendu` tranche le premier échantillon en `depose` sans la décision de Benj → UP-5 ;
     - le tourneur dépose avant que `pub-locale-qa` soit vert → UP-6 ;
     - le tourneur passe la réponse d'accord au lecteur `studio` → UP-7 ;
     - le jeton d'agent écrit dans une ligne de journal → UP-8 ;
   - **search-console-qa** :
     - le jeton d'accès écrit dans le journal → SC-7 ;
     - `search_console_le` posé avant la soumission du plan → SC-3 ;
     - le fichier de vérification écrit à la racine du bucket au lieu du dossier du site → SC-4 ;
     - plus de limite d'essais (un 4e essai après trois échecs) → SC-6.
3. Écrire `mutations.md` et `mutations.json` (même format que 026-130).
4. **Si une mutation passe, NE PAS corriger le juge.** L'écrire en tête du rapport et sortir en code 1. Ne jamais modifier un juge, un jeu d'essai, ni le dépôt en place.
5. Lancer les passages l'un après l'autre ; 25 minutes au plus pour tout le script.
6. Aucun `--reel`, aucun appel à un vrai service de Google, aucune commande sur l'usine réelle hors du dossier de travail.
