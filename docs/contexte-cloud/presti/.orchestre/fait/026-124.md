## Contexte

Les vidéos du pack pubs (fiches 11 et 12) sont des films verticaux de 15 s faits de photos réelles, avec une voix de synthèse ou sans son. Le juge vidéo actuel ne les accepte pas tel quel :
- `scripts/video-qa.mjs` : la barre (`:19-40`) exige 5 coupes par 10 s et une piste son de −26 à −19 LUFS, niveau d'un fond musical ; une voix off se mesure autour de −14 LUFS et serait refusée ; les formats sont 1080×1920, 1080×1350 et 1920×1080 (`:51-55`) ; deux profils existent, `reseaux` par défaut et `landing` (`:171-172`, verdict `:173-212`). `publier-suite.mjs` et la vidéo de la landing (`public/promo/demo-site/lestraque.mp4`) dépendent de ces deux profils : ils ne doivent pas bouger.

Le plan exige « manifeste des entrées et détection de visages » pour prouver qu'aucune personne n'est générée (§1.1 offre C, faille B8 du §9.2). **La détection doit être fiable, sinon elle bloque tous les packs.** Mesuré le 24/09 par Claude Code sur les 68 photos `public/sites-demo/*/images/*-720.webp` avec les cascades de Haar livrées avec OpenCV 4.13 (facteur 1,1, 8 voisins, taille mini 8 %) :
- `haarcascade_frontalface_default` : 7 photos sur 68 déclarées « avec visage » (10 %) ;
- `haarcascade_frontalface_alt2` : 1 ; `haarcascade_profileface` : 1 ;
- l'accord `default` + `alt2` garde encore `lestraque/images/tournage-copeaux-720.webp`, qui ne montre qu'une main et des copeaux (vérifié à l'œil).

Donc : **pas de Haar**. Le détecteur est `cv2.FaceDetectorYN` (YuNet), présent dans OpenCV 4.13 installé sur le poste, avec le modèle ONNX officiel `face_detection_yunet_2023mar.onnx` du dépôt `opencv/opencv_zoo`, **qui n'est pas sur le poste**.

Outils locaux vérifiés le 24/09 : Python 3.12 avec OpenCV 4.13.0 (`FaceDetectorYN` disponible), ffmpeg 8.1.1, `sharp` et Playwright dans `node_modules`.

Réservée à Claude Code : juges. Dépend de : 026-108 PASS (preuve générique).

## Ce qu'il faut faire

1. **`video-qa.mjs --profil=pub-locale`** : une branche de plus dans `juge()`, rien d'autre ne change. Critères, chacun nommé « … (pub locale) » :
   - format 1080×1920 seulement ; durée de 14 à 16 s ; au moins 29 images/s ; débit ≥ 3 000 kbps ; poids ≤ 8 Mo ;
   - aucun plan figé plus de 0,8 s ; l'image vit ; au moins N coupes par 10 s ; cadre rempli ; dernière image non blanche ;
   - son : **aucune piste**, ou une piste entre −17 et −11 LUFS (voix normalisée vers −14, mémoire `loudnorm-apres-un-carton-muet` : normaliser le corps **avant** de coller un carton muet).

   Les seuils « l'image vit » et N (proposé : 3) sont **étalonnés** : le film conforme du socle passe, un diaporama figé de 2 s par photo échoue. Les valeurs retenues et les mesures sont écrites dans la preuve.
2. **`scripts/visages.py`** : lit une liste d'images, applique YuNet (seuil de score 0,9 par défaut), rend du JSON (`fichier`, `visages: [{ x, y, l, h, score }]`). Refuse de tourner si l'empreinte du modèle ne correspond pas.
3. **`scripts/visages-qa.mjs <chemins…> [--json] [--seuil=0.9] [--ips=2] [--attendu=0]`** : images et vidéos (ffmpeg extrait 2 images/s dans `.orchestre/travail/visages-qa/`) ; `--attendu=0` sort en code 1 dès qu'un visage est trouvé, avec le fichier et l'instant ; modèle absent → code 2.
4. **Jeux d'essai `socle/`** :
   - `calibrage-sans-visage.json` : les 68 chemins et leur empreinte à la référence ;
   - `visage-domaine-public.jpg` et sa source (auteur, licence, adresse) ;
   - `fabriquer-films.mjs` : fabrique par ffmpeg, dans `.orchestre/travail/socle/`, un film conforme au profil (photos CC0 des démos, 15 s, 1080×1920, 30 images/s, zooms lents, 5 coupes, voix française `Microsoft Hortense` de Windows normalisée à −14 LUFS), et ses mutations (12 s, 1080×1350, voix à −25 LUFS, diaporama figé), plus un film de 4 s où le portrait apparaît entre 2 et 3 s.
5. **`scripts/socle-pubs-qa.mjs`**, critères SP-1 à SP-8 du cahier ci-dessous.
6. **`preuve-09.json`** : référence de `preuve-01.json` ; échecs attendus sur la référence : SP-1 et SP-4.
