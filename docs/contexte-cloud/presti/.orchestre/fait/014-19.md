# 014-19 — l'e2e de l'hébergement des sites générés (v15 §3.2)

## Ce que tu testes (les briques existent, ne les modifie pas)

- `scripts/site-deposer.mjs <commande_id> <dossier> [--statique]` : refuse si le juge est rouge ; sinon dépose le dossier dans le bucket privé `sites/<id>/…`, pose `apercu_jeton`, et (sans `--statique`) passe la commande `payee → generee` avec `scores` et `verifications`. Il imprime l'adresse d'aperçu.
- `GET /site-genere/<id>/<chemin>` : tant que la commande n'est pas `en_ligne`, 404 sans jeton, 200 avec `?apercu=<jeton>` (et un cookie posé pour la suite), `X-Robots-Tag: noindex`, `Cache-Control: private, no-store` ; en ligne : 200 pour tous, cache public. Les types : `text/html; charset=utf-8`, `text/css`, `image/webp`. `/` → `index.html`, `/x/` → `x/index.html`. Sur un hôte Presti, les liens absolus du HTML sont réécrits vers `/site-genere/<id>/…`.
- `POST /api/controle/sites/<id>` `{ action: 'mettre_en_ligne' }` : 409 sans dépôt ; sur une commande `validee` déposée sans domaine → 200, état `en_ligne`, `en_ligne_le`, journal `site_en_ligne`, `artisans.site_origine = 'commande'`.

## Comment tu écris la suite

Harnais de `scripts/controle-apports-e2e.mjs` (comptes `heb-<nom>-<st>@presti-test.invalid`, fondateur, session, `T()`, purge en `finally`). Un site témoin minimal **généré par la suite elle-même** dans un dossier temporaire (`os.tmpdir()`), conforme au contrat de `scripts/site-qa.mjs` (regarde `scripts/site-qa-temoin.mjs` : `fabriquer()` — recopie la logique, n'importe pas le fichier), déposé avec `--statique` d'abord (rapide), puis complet une fois. Une commande de test insérée par la clé service en `payee` (avec `artisan_id` de test, `domaine_mode: 'aucun'`), passée à `validee` par la clé service pour tester la mise en ligne (la validation humaine est testée par `014-13`). Purge : les objets `sites/<id>/…` du bucket (`storage.from('sites').remove`), la commande, les comptes.

Ce qu'elle prouve, dans l'ordre :
1. `site-deposer` refuse un dossier sans `site.json` (code 1, « le juge refuse ») ; accepte le témoin (`--statique` : commande reste `payee`, jeton posé ; complet : `generee`, `scores` avec quatre valeurs, `verifications.blocs` présent).
2. Sans jeton : `GET /site-genere/<id>/` → 404 ; avec `?apercu=<jeton>` → 200 `text/html`, `X-Robots-Tag` noindex, `Set-Cookie` ; avec le cookie seul → 200 ; `/styles.css` → `text/css` ; `/images/hero.webp` → `image/webp` ; un chemin `..` → 404 ; un jeton faux → 404.
3. Sur l'hôte de test (Presti), le HTML servi contient `/site-genere/<id>/` dans ses liens (réécriture), pas de `href="/plombier-lyon/"` nu.
4. `mettre_en_ligne` sur une commande `validee` sans dépôt → 409 ; après dépôt → 200, `en_ligne`, journal `site_en_ligne`, `site_origine = 'commande'` ; puis `GET /site-genere/<id>/` sans jeton → 200 avec `Cache-Control: public`.
5. Garde-fous : `mettre_en_ligne` sur `payee` → 409 ; rôle `lecture` → 403 ; `GET /api/controle/sites` donne `apercu` à la direction, `null` à la lecture.

Cible `TEST_BASE` (local `http://localhost:3000` d'abord — la route lit le bucket avec la clé service de `.env.local`). Zéro appel IA, zéro paiement. Termine par `014-19 : PASS|FAIL — …` et « N réussis, M échoués ».
