## Contexte

**Pourquoi** (rectification du 24/09, §3.3 et §3.12 ; décision R11, provisoire). Ce sont les agents qui contactent les artisans ; un site payé est en ligne sous 48 h ouvrées après validation. Rien de cela ne tient si la génération attend que le PC de Benj soit allumé. Le Livreur tourne donc sur l'usine Oracle `presti-usine` (ARM, 2 cœurs, 12 Go, 24 h/24, Chromium, Playwright et ffmpeg installés), sous le compte `agents` (fiche 02), avec le code du commit déployé en lecture seule dans `/srv/presti-agents`. GitHub Actions (026-106) reste son repli.

**Le tourneur ne fabrique rien lui-même.** Il fait le lien entre le bus et un fabricant : il prend une tâche, prépare le dossier d'entrée, lance le fabricant de la capacité, contrôle ce qui sort, le dépose et rend la tâche. Il est le seul à tenir le jeton de l'agent ; le fabricant ne le voit jamais. C'est un adaptateur : une autre capacité s'ajoute par une ligne de la table et une entrée de `usineLimites.json`.

**Le bus** (routes de 026-042, jeton `Bearer`) : `POST /api/agents/battement` ; `POST /api/agents/taches/prendre` (aucun corps ; rend la plus ancienne tâche en file de la capacité de l'agent, sous un bail de **30 min**, ou rien ; un agent en pause reçoit une erreur `ops:agent_en_pause`) ; `POST /api/agents/taches/<id>/rendre` (`{ resultat: 'faite' | 'echec', preuve_url?, erreur? }` ; `faite` exige une preuve qui commence par `supabase://`) ; et les routes de l'usine (fiche 06) : `POST /api/agents/usine/entree` `{ tache }` → `{ tache, entrees: [{ nom, url, octets }] }` et `POST /api/agents/usine/depot` `{ tache, fichiers: [{ nom, octets, type, sha256 }] }` → `{ depots: [{ nom, url, jeton }] }` (dépôt par `PUT` sur `url`, avec le `Content-Type` du fichier).

**Le contrat** (copie du juge : `scripts/fixtures/026/usine-production/contrat-usine.json` ; limites : `lib/agents/usineLimites.json`, seule source des nombres, écrite en fiche 06) :
- `livraison` : agent `livreur_usine`, jeton `PRESTI_JETON_LIVREUR_USINE`, tâches de type `livrer_site` ; charge `{ commande: <uuid>, essai?: true }` et rien d'autre ; entrée : `commande.json` et les photos de l'artisan ; sortie : `site/**` et `rapport-qa.json` ; 25 min ; le fabricant ne reçoit rien du coffre ; il reçoit `CODEX_LANCEUR` (non secret) pour la rédaction (R16 annulée) ;
- `<sortie>/manifeste.json` = `{ fichiers: [{ nom, type }] }` : seuls les fichiers listés partent.

**Les ressources de l'usine** : 12 Go partagés avec l'atelier, le chef et les fiches Codex de l'orchestre. Un travail ne démarre pas s'il reste moins de 1,5 Go de mémoire disponible ou 2 Go de disque ; chaque service est borné à 4 Go (`MemoryMax`).

**Vercel reste en offre Hobby** jusqu'au premier site vendu (ce jour-là, Vercel Pro, 20 $ par mois : la seule dépense permise) (1 million d'invocations par mois) : un passage toutes les 10 min, deux appels quand la file est vide, c'est moins de 300 appels par jour.

**Tout reste reprenable par le poste** : le même script, lancé sur Windows avec les jetons dans l'environnement, fait la même chose ; et la livraison a GitHub Actions en repli.

## Ce qu'il faut faire

1. **`scripts/usine/capacites.mjs`** exporte `CAPACITES` :
   ```js
   {
     livraison: { agent: 'livreur_usine', jeton: 'PRESTI_JETON_LIVREUR_USINE', type: 'livrer_site', minutes: 25, env: ['CODEX_LANCEUR'],
                  commande: ['{node}', '--import', './scripts/ts-loader.mjs', 'scripts/livrer-site.mjs', '--usine', '--entree={entree}', '--sortie={sortie}'] },
   }
   ```
   `{node}` devient `process.execPath`. Le schéma de la charge est écrit ici, à côté (validation sans dépendance : clés exactes, UUID, booléen).
2. **`scripts/usine/tourneur.mjs --capacite=<nom> [--une-passe] [--base=<url>] [--travail=<dossier>] [--max=<n>] [--delai-s=<n>] [--meminfo=<fichier>]`**, en ESM, sans dépendance npm :
   - `--capacite` doit être une clé de `CAPACITES` et de `usineLimites.json` (sinon code 2). `--base` : `https://prestiapp.fr` par défaut ; `http://` seulement vers `127.0.0.1` ou `localhost`, sinon code 2. `--travail` : `$HOME/travail/usine` par défaut. `--max` : 2 par passage par défaut. `--delai-s` remplace les minutes de la table (les essais). `--meminfo` lit un autre fichier que `/proc/meminfo` (les essais) ;
   - le jeton se lit **seulement** dans la variable que nomme la table (et `process.env` ne sert, en dehors de lui, qu'à `PATH`, `HOME`, `LANG`, `TZ`, `PLAYWRIGHT_BROWSERS_PATH` et aux variables `env` de la table) ; absent → code 2, aucune requête ; jamais imprimé, jamais journalisé ;
   - **verrou** `<travail>/tourneur-<capacite>.verrou` (pid, date) : un passage déjà en cours → code 0, « déjà en cours » ; un verrou de plus de 60 min est repris, et le journal le dit ;
   - **un passage** :
     1. `POST /api/agents/battement` ;
     2. ressources : mémoire disponible (`MemAvailable` sous Linux, `os.freemem()` ailleurs) d'au moins 1,5 Go, et 2 Go libres sur `--travail` (`fs.statfsSync`) ; sinon une ligne `ressources` et code 0 ;
     3. jusqu'à `--max` tâches, et 50 min au plus : `POST /api/agents/taches/prendre` ; rien → fin ; `ops:agent_en_pause` → ligne `en_pause`, code 0 ;
     4. pour une tâche : `type` égal à celui de la table (sinon `rendre` `echec`, `capacite`) ; charge conforme au schéma (sinon `echec`, `charge`, et le fabricant n'est pas lancé) ;
     5. `POST /api/agents/usine/entree` ; chaque entrée téléchargée dans `<travail>/<tache>/entree/`, octets comptés contre la limite ; `charge.json` écrit à côté ;
     6. le fabricant : `spawn` de la commande de la table (`{entree}`, `{sortie}` remplacés), **sans shell** (mémoire `spawn-windows-shell-ffmpeg`), dans la racine du dépôt, avec un environnement **fait de zéro** : `PATH`, `HOME`, `LANG`, `TZ`, `PLAYWRIGHT_BROWSERS_PATH` (ceux qui existent) et les seules variables de `env` de la table ; délai de la table ; au délai, **tout l'arbre** est tué (groupe de processus détaché sous Linux, `taskkill /T /F` sous Windows) et la tâche rendue en `echec`, `fabrication:delai` ; un code non nul → `echec`, `fabrication:code <n>` ; les 50 dernières lignes de sortie du fabricant vont dans `<travail>/<tache>/fabrication.log`, jamais ailleurs ;
     7. **contrôle de la sortie**, tout avant le moindre dépôt : `manifeste.json` présent et lisible (sinon `sortie:manifeste`) ; chaque fichier listé existe, est un fichier ordinaire (`lstat` : un lien → `sortie:lien`), a un nom au contrat (`sortie:nom`), un type de la capacité cohérent avec son extension (`sortie:type`), une taille dans les limites, fichier par fichier et au total, et un nombre de fichiers permis (`sortie:taille`) ; ses octets magiques correspondent à son type (JPEG `FF D8` … `FF D9`, PNG, WebP, AVIF par `ftyp`, WOFF2, JSON qui se lit, texte en UTF-8 valide ; sinon `sortie:type`) ; aucun fichier ne contient une chaîne de `MOTIFS_SECRETS` (`scripts/instantane-quotidien.mjs`) ni **la valeur exacte** d'une variable secrète passée au fabricant (`sortie:secret`, la valeur jamais répétée) ; les fichiers non listés sont ignorés ;
     8. `POST /api/agents/usine/depot` avec la liste (nom, octets, type, `sha256`) ; puis un `PUT` par fichier vers l'URL rendue, au bon `Content-Type`, trois essais au plus sur une erreur réseau ou 5xx ; un 507 → `echec`, `depot:stockage` ; un `PUT` qui échoue trois fois → `echec`, `depot` ; **tout ou rien** : la tâche n'est jamais rendue `faite` avec une partie de ses fichiers ;
     9. `POST /api/agents/taches/<id>/rendre` `{ resultat: 'faite', preuve_url: 'supabase://usine/<tache>/sortie/' }` ;
     10. le dossier `<travail>/<tache>/` est effacé après un succès ; après un échec, il est gardé 24 h pour le diagnostic, puis effacé à un passage suivant (minimisation : il contient les données de l'artisan) ;
   - **erreurs du bus** : 429 → arrêt du passage, code 3 ; 401 → code 1 ; 5xx ou réseau → une ligne, arrêt du passage, code 1 ;
   - **journal** `<travail>/tourneur-<capacite>.jsonl` : par passage `{ le, capacite, taches, duree_s }`, par tâche `{ le, tache, code, etape, octets, duree_s }`, **rien d'autre** : aucune valeur d'entrée, aucune URL, aucun jeton ;
   - **sortie console** : des nombres, des codes et des identifiants de tâche, jamais une valeur d'entrée ;
   - le tourneur n'appelle jamais un modèle, ne lit jamais `.env.local` ni le coffre (c'est `avec-coffre.mjs` qui lui passe son jeton), et ne lit, pour sa commande, **aucune** variable d'environnement.
3. **Les unités** :
