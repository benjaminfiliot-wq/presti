# 025-19 — le domaine sans site, et le tableau de bord

## Contexte

Relecture à froid avant mise en ligne du 25/09 (`.orchestre/preuves/025-relectures/revue-avant-mise-en-ligne-2026-09-25.md`),
défauts D11 (« Le nom de domaine se dit servi … Site non publié ») et D12 (« Le tableau de bord annonce des réponses envoyées
automatiquement »). Numéros de ligne de l'état du 25/09 (83ce3dd). Depuis 025-05, plus rien ne pose `site_active` (le
constructeur est fermé) : un artisan sans site historique qui branche son domaine obtient un badge « Actif — votre site est
servi », pendant que son client lit « Site non publié ».

- **D11, la racine.** `middleware.ts:68` (`cibleInterne`) réécrit la racine d'un domaine vérifié vers `/site/<slug>` ;
  `app/site/[slug]/page.tsx:131-132` répond « Site non publié » si `site_active !== true`. Seul `/demande` sert la page de
  contact. Même page morte sur prestiapp.fr/site/<slug>.
- **D11, les écrans.** `app/profil/page.tsx:293` affiche « Actif — votre site est servi sur ce domaine » dès que le domaine est
  servi ; `app/parametres/SectionProfil.tsx:52` donne à chacun une ligne « Site » vers `urlSite` ; l'infobulle `profil.domaine`
  (`lib/aide.ts:811`) dit « branchée sur votre site ».
- **D12.** `app/dashboard/page.tsx:118` « envoyées automatiquement », `:171` « Réponse envoyée automatiquement », `:174` « Pas
  encore de réponse automatique » ; l'article d'aide « dashboard » (`lib/aide.ts:74-75`, `:83`) répète « réponses envoyées
  automatiquement par l'assistant ». Or une proposition validée par l'artisan (`app/api/messages/route.ts:94`) garde
  `type: 'reponse_auto'` : la base ne distingue pas une réponse partie seule d'une réponse validée.

## Ce qu'il faut faire

1. **Un seul endroit décide ce que sert la racine d'un domaine** : nouveau `lib/surfaceDomaine.ts`, pur (aucun import de
   module serveur ou client, il est lu par le middleware), qui exporte :

   ```ts
   export type SurfaceDomaine = 'site' | 'site_genere' | 'contact'
   export function surfaceDuDomaine(p: { siteActif: boolean | null | undefined; commandeEnLigne: boolean }): SurfaceDomaine
   // commande en ligne d'abord (le middleware sert le site généré avant tout), puis site publié, sinon la page de contact
   export function libelleDomaineActif(surface: SurfaceDomaine): string
   // 'contact' → « Actif — votre page de contact est servie sur ce domaine » ; 'site' et 'site_genere' → « Actif — votre site est servi sur ce domaine »
   ```
2. **middleware.ts** : pour un domaine perso vérifié sans commande en ligne, `slugForDomain` lit aussi `site_active`
   (`select=slug,site_active`, toujours en PostgREST) ; la racine `/` va vers `/p/<slug>` quand `surfaceDuDomaine` dit
   `'contact'`, vers `/site/<slug>` sinon. `/demande`, `/infos-legales`, les autres chemins, la commande en ligne
   (`commandeForDomain`, en premier) et les hôtes Presti ne changent pas.
3. **app/site/[slug]/page.tsx** : quand `a.site_active !== true`, plus de « Site non publié » : si l'artisan a une commande
   `en_ligne` (`sites_commandes`, `artisan_id`), `redirect` vers son site (`https://<domaine>/` si elle en a un, sinon
   `/site-genere/<id>/`) ; sinon `redirect(ch.plateforme)` (la page de contact à l'adresse de l'hôte : `/p/<slug>` sur
   prestiapp.fr, `/demande` sur un domaine). Le reste de la page (404, anciennes adresses, redirection vers le domaine vérifié,
   site publié) ne change pas.
4. **app/api/domain/route.ts** : le GET rend aussi `surface` (`surfaceDuDomaine` avec `site_active` de l'artisan et une commande
   `en_ligne` de cet artisan sur ce domaine).
5. **app/profil/page.tsx** : le badge d'un domaine servi affiche `libelleDomaineActif(<surface lue dans /api/domain>)` ; plus de
   texte « votre site est servi sur ce domaine » écrit en dur. Ne rien toucher d'autre dans /profil (constructeur-ferme-qa CF-5
   le garde).
6. **app/parametres/SectionProfil.tsx** : la ligne « Site » (et son lien) seulement quand `a.site_active === true` ; la ligne
   « Plateforme » ne change pas.
7. **lib/aide.ts** : l'infobulle `profil.domaine` dit que le domaine sert le site s'il est publié, sinon la page de contact.
   L'article « dashboard » ne dit plus « automatiquement » ni « réponse automatique » (par exemple « réponses de l'assistant
   envoyées à vos clients »).
8. **app/dashboard/page.tsx** : libellés exacts, puisque la base ne distingue pas l'envoi automatique de l'envoi validé : par
   exemple « Réponses IA » / « envoyées à vos clients », « Réponse envoyée », « Pas encore de réponse envoyée pour cette
   demande. ». Plus aucun texte ni chaîne du fichier ne contient « automati… ». Le compte (`reponse_auto`, `etat` nul) ne change
   pas.
9. **À ne pas faire.** Pas de migration ni de nouvelle colonne ; ne pas toucher `lib/urls.ts` (une autre session), `lib/flags.ts`,
   `lib/plans.ts`, `app/p/**`, `app/site-genere/**`, `app/api/leads/**`, les juges et leurs jeux d'essai. Aucun appel à la
   production. Référence permise en lecture : `scripts/fixtures/025/temoins/domaine-sans-site-qa/` (copies corrigées, marquées
   « TÉMOIN 025-19 ») passe le juge.
