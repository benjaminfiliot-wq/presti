## Contexte

Un pack fabriqué et jugé est déposé dans le bucket privé `packs-pubs`, sous `packs-pubs/<id>/` (huit fichiers : `video-1..3.mp4`, `visuel-1..3.jpg`, `textes.md`, `fiche-10-min.md`), et sa ligne `packs_pubs` passe à `fabriquee` (fiche 14). Le plan veut que Benj **regarde et valide les cinq premiers packs** (§1.1, offre C) : la livraison est donc un geste humain, fait depuis le Poste, même au téléphone. **Ce geste tourne PC éteint** : tout se passe sur Vercel.

Modèles existants (à imiter, pas à modifier) :
- `app/api/controle/sites/[id]/route.ts` : `estFondateur` puis `exigerDomaine(f, 'clients', 'ecrire')` (`:33-37`) ; lecture puis contrôle de transition (`:46-52`) ; **journal d'abord** : si `journaliser` échoue, le geste est refusé en 503 (`:72-77`) ; mise à jour conditionnée à l'état lu, 409 si rien ne passe (`:79-81`) ; `ctx.params` est une promesse (`:33`, compatible Next 16) ;
- `lib/direction/reconfirmation.ts` : `exigerReconfirmation(req, uid, portee)` (`:49-55`), portées `securite | argent | artisan | reglages` (`:11`) ; écrire à un client relève de la portée `artisan` ;
- `lib/direction/garde.ts` : `estFondateur`, `estDirection`, `exigerDomaine`, `domaineRefuse`, `estRefus`, `reponseRefus` (`:40-91`) ; `lib/direction/journal.ts` : `journaliser({ acteur, action, cible_type, cible_id, artisan_id, avant, apres, reconfirme }, req)`, qui rend `false` s'il n'a pas écrit (`:65`) ; `action` est une union fermée de libellés (`:11-26`, dernière ligne `'site_valide' | 'site_regeneration' | 'site_en_ligne'`), sans contrainte en base ;

- `lib/packPub.ts` : `transitionPackValide(de, vers)` ; états `brouillon → payee → fabriquee → livree` ; `fabriquee → payee` pour refaire avant livraison ; `livree → payee` pour la retouche unique promise par les CGU 3 ter (dans les 30 jours).

Colonnes utiles de `packs_pubs` : `id`, `artisan_id`, `email`, `etat`, `matiere` (dont `voix`), `fabrique_le`, `livre_le`, `lien_expire_le`, `verifications`, `consigne`, `refaits`.
