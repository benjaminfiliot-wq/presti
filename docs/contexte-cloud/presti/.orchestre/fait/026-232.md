# 026-232 — l'auto-recherche : le savoir d'abord, le web ensuite, toujours avec ses sources

## Contexte

Un agent qui ne sait pas doit pouvoir chercher lui-même, mais pas n'importe comment. Les règles de Benj : aucune donnée de prospect vers une IA gratuite ni un service web ; aucun achat (Firecrawl sur la **réserve de départ** de 1 000 crédits, qui n'est pas un solde constaté ; Perplexity réservé à une recherche ponctuelle publique, **après** constat du plan et du coût, jamais en boucle : décision `decisions-benj.md:56`, correction du 27/09 de 026-041) ; rien n'aspire Facebook, Instagram ni PagesJaunes (les lectures web passent par `lireAvecFirecrawl` de 026-223, qui applique robots, conditions et repli sur le lecteur poli de 026-020).

**Le contrat que ce juge fixe pour 026-233** (`lib/savoir/recherche.ts`, toutes les E/S par `deps`) :

- `PLAFONDS_RECHERCHE`, gelé : `{ questionSignes: [3, 300], resultats: 8, extraitSignes: 600, savoirParAgentEtJour: 200, webParAgentEtJour: 10, pagesWebParRecherche: 3, perplexityParJour: 5, perplexityParRecherche: 1, besoinsParReponse: 2, relances: 1, creditsParLecture: 1, creditsParRecherche: 2 }`.
- `RECHERCHE_WEB_DE`, gelé : `['chef', 'douleurs', 'redacteur_site', 'studio']` (le Standard, le Facteur et la veille des pubs ne cherchent jamais sur le web : leurs questions touchent des prospects).
- `classesPour(agent, moteurs)` : agent absent de `MOTEUR_DE` → `['public']` ; `personnelles: false` → `['public', 'interne']` ; `personnelles: true` (Codex) → `['public', 'interne', 'prospects']`. `demande.classes` ne peut que restreindre.
- `refusDonneePersonnelle(question, nomsProspects)` → `null`, `'adresse'`, `'numero'`, `'siren'` ou `'nom_prospect'` (un nom d'entreprise de la liste locale, comparé après `normaliser`).
- `chercher(demande, deps)` avec `demande = { agent, question, web? }` et `deps = { savoir(question, { k, classes }), moteurs, reglages, nomsProspects, firecrawl?: { chercher, lire }, perplexity?, compteurs, credits, journal, horloge }` :
  1. question hors bornes → rejet, rien d'appelé ;
  2. **savoir d'abord** : `deps.savoir` avec les classes de l'agent ; tout résultat sans source complète est jeté ; tout résultat d'une classe non permise est jeté (le filtre est appliqué deux fois : à la demande et au retour) ;
  3. **web ensuite**, seulement si `web: true`, l'agent dans `RECHERCHE_WEB_DE`, `recherche_web` allumé, le savoir insuffisant (moins de 2 résultats, ou le meilleur sous le seuil `SEUIL_SAVOIR` exporté), aucune donnée personnelle dans la question, le plafond du jour et la réserve de crédits tenus : `firecrawl.chercher` (2 crédits) puis au plus 3 `firecrawl.lire` (1 crédit chacune), la question envoyée **telle quelle**, jamais augmentée d'un extrait ;
  4. **Perplexity en dernier**, seulement si Firecrawl n'a rien rendu, `perplexity` allumé, `plan` connu, `cout_par_requete_eur === 0`, `constate_le` de moins de 30 jours, au plus une fois par appel et cinq par jour ; sinon `ferme` avec sa raison ;
  5. rend `{ id, agent, question_sha256, resultats: [{ origine: 'savoir'|'web'|'perplexity', extrait, source }], web: { etat: 'non_demande'|'ferme'|'indisponible'|'refuse'|'fait', raison?, credits, requetes }, refus? }`. Source `savoir` : `{ racine, chemin, debut, fin, classe, sha256, synchronise_le }` ; `web` : `{ url, url_finale, lu_le, methode, robots }` ; `perplexity` : `{ url, lu_le, via: 'perplexity' }` ;
  6. un seul `deps.journal({ type: 'savoir_recherche', objet: 'recherche:<id>', resume })` par appel, résumé de 1 à 200 signes (`<n> résultat(s) · savoir <a> · web <b> · <c> crédit(s)`, plus le refus éventuel), **jamais** la question ni un extrait.
- `avecRecherche(lecteur, agent, deps)` : rend un `Lecteur` ; si la réponse JSON du modèle porte `besoins_recherche` (tableau de chaînes), les 2 premiers sont cherchés (savoir seulement, sauf agent de `RECHERCHE_WEB_DE`), puis le lecteur est rappelé **une** fois avec `resultats_recherche` (extraits et sources) ajouté aux données ; les `besoins_recherche` de la seconde réponse sont ignorés.
- `scripts/savoir/chercher.mjs --agent=<nom> --question=<texte> [--web] [--base=https://prestiapp.fr] [--racine-travail=/home/agents/travail/savoir] [--sortie=<fichier>]` : charge les index (`chercherIndex` de 026-231), les noms du compartiment `prospects` (liste locale, jamais écrite ailleurs), `reglages.json`, les compteurs du jour et la réserve de crédits (`credits-firecrawl.json`, sérialisée par un verrou `O_EXCL`) ; le journal passe par `POST <base>/api/agents/evenements` (026-042) avec `Authorization: Bearer $PRESTI_JETON_<AGENT>` ; jeton absent → code 2 sans rien faire ; `--base` en `http://` hors boucle locale → code 2 ; événement refusé → code 3 ; écrit le résultat en JSON et une ligne `{ le, id, agent, question_sha256, n, origines, credits, refus }` dans `recherches-<jour>.jsonl`.

Les agents l'appellent de deux façons : leur script appelle `chercher()` avant le modèle, ou il enveloppe son lecteur par `avecRecherche()` pour que le modèle demande lui-même ce qui lui manque (le modèle n'a jamais d'outil : 026-041). Matt s'en sert dans son bilan (026-239).
