## Contexte

Jusqu'ici, un site vendu se génère sur le poste de Benj (`scripts/livrer-site.mjs`, fiche 15). C'est la seule étape de la livraison qui ne tourne pas PC éteint (plan §2.1, règle 4). Depuis la décision du 24/09, les agents contactent et vendent pendant que le PC dort (rectification §3.1, §3.12) : la livraison ne peut plus attendre le poste. Elle part dans GitHub Actions, **avec un budget de minutes** (§6.5), sans rien faire tourner de lourd sur Vercel (offre Hobby : 4 h de calcul par mois ; le travail lourd des agents n'y tourne pas).

Les minutes sont rares :
- le dépôt est privé (l'API publique de GitHub répond 404, constaté le 24/09), avec 2 000 min par mois [à vérifier selon l'offre du compte] ;
- les nuits consomment déjà jusqu'à 75 min : `audit.yml` (45 min au plus, `.github/workflows/audit.yml:27`) et `sauvegarde.yml` (30 min au plus, `sauvegarde.yml:28`). Au pire, cela fait environ 2 250 min par mois ;
- d'où trois règles du plan : aucun chien de garde planifié sur Actions, **aucun `schedule`**, et Benj lit la consommation réelle avant d'activer.

Le déclenchement vient donc de Vercel, par `repository_dispatch`, seulement quand une commande est prête. `scripts/livrer-site.mjs --ci` (fiche 15) fait le travail et écrit la durée mesurée (`generation_duree_s`).

Règles des secrets (plan §5.5) :
- le runner ne reçoit jamais la clé Anthropic du produit : `audit.yml:37` retire déjà `ANTHROPIC_API_KEY` ;
- Actions n'a aucun moteur : le repli rédige `--sans-ia` (revue transverse du 25/09 : R16 annulée) ;
- le dépôt est privé, mais les journaux d'exécution restent lisibles par les collaborateurs. Rien de personnel ne doit s'y écrire, et **aucun artefact**, puisque le site contient les données de l'artisan.

Dépend de : fiche 15 PASS avec sa mesure de durée `--reel` ; fiches 07 et 11 (`erreursFabrication`) ; fiche 05 (026-021, 0103) appliquée.

## Ce qu'il faut faire

1. **`.github/workflows/generer-site.yml`** :
   - `on: repository_dispatch` (types `[generer-site]`) et `workflow_dispatch`, avec une entrée `commande` ;
   - `permissions: contents: read` ;
   - `concurrency: { group: generer-site, cancel-in-progress: false }` ;
   - un job `ubuntu-latest`, `timeout-minutes: 20` ;
   - étapes :
     1. `actions/checkout@v4`, puis `setup-node` 22 avec le cache npm, puis `npm ci` ;
     2. `npx playwright install --with-deps chromium` ;
     3. l'identifiant de commande, lu dans `client_payload.commande` ou l'entrée, est **refusé s'il n'est pas un UUID** ;
     4. `.env.local` est écrit depuis le secret `LIVRAISON_ENV`, filtré par une liste blanche `grep -E '^(NEXT_PUBLIC_SUPABASE_URL|SUPABASE_SERVICE_ROLE_KEY)='` ;
     5. `node --import ./scripts/ts-loader.mjs scripts/livrer-site.mjs "$COMMANDE" --ci`.
   - Ni `upload-artifact`, ni `schedule`, ni `echo` d'une variable secrète.
2. **`lib/siteGenerationDistante.ts`**, `demanderGeneration(commande, deps)`, avec ses dépendances injectables `fetch`, `base`, `limite` (`consommerLimite`), `alerter` (`envoyerAlertes`), `env` et `maintenant` :
   - **conditions** :
     - `etat = 'payee'` et `erreursFabrication(commande)` vide ;
     - `generation_tentatives < 3` ;
     - `generation_demandee_le` vide ou plus vieille que 45 min (le bail) ;
     - `GITHUB_DISPATCH_TOKEN` présent ;
     - plafond mensuel `consommerLimite('actions:generer:<AAAA-MM>', GENERATIONS_MOIS_MAX || 10, 32 j)` ;
     - (revue du 25/09) **l'usine n'a pas la commande en main**, lu par la dépendance injectable `usine` : pas d'index `usine/commandes/<id>.json` (aucune entrée déposée : bucket absent, dépôt échoué) ; **ou** payée depuis plus d'une heure (`paye_le`) sans `usine/<tache>/sortie/manifeste.json` ; **ou** `livreur_usine` absent de `ops_etat().agents` ou muet (battement plus vieux que 2 × `periode_minutes`) ; sinon, rien (l'usine livre) ;
   - **appel** : `POST https://api.github.com/repos/<GITHUB_DEPOT_LIVRAISON>/dispatches` avec `Authorization: Bearer <jeton>`, `Accept: application/vnd.github+json` et `{ event_type: 'generer-site', client_payload: { commande: id } }`. Délai de 10 s ;
   - **204** : mise à jour conditionnelle de `generation_demandee_le` et de `generation_tentatives + 1` ;
   - **autre réponse, ou plafond atteint** : une alerte (motif `paiement`, clé `generation:<id>:<cause>`), aucune écriture ;
   - le jeton n'est jamais journalisé.
3. **`lib/siteLivraison.ts`** : dans `tourLivraison`, pour les commandes payées prêtes (5 au plus par passage), `demanderGeneration` quand `GITHUB_DISPATCH_TOKEN` existe et que `enPause()` est faux. Sans jeton, rien ne change : la ligne « Générer le site » d'« À faire » reste le chemin (fiche 18).
