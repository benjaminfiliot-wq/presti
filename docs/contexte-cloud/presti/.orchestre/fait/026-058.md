## Contexte

L'usine `presti-usine` (Oracle Always Free, Paris, ARM 2 OCPU, 12 Go, Ubuntu 24.04) tourne depuis le 24/09 (`presti-ops/usine/LISEZMOI.md`). Le compte `usine` y fait tourner les fiches de l'orchestre par Codex, avec le réseau ; il n'y a aucun secret. Pour que l'atelier, le livreur et le chef tournent **PC éteint** (rectification du 24/09 §3.12, décisions R11 et R12, provisoires), il faut le socle écrit en fiche 02 : un compte `agents` à part, un coffre lisible par lui seul, deux assistants, et le code déployé en lecture seule. Puis la surveillance (fiche 03), parce qu'Oracle reprend une instance restée sous 20 % sur 7 jours (processeur, réseau **et** mémoire au 95e centile).

**Les outils** (fiche 02 ; `docs/agents/usine.md` pour le détail) :
- `node scripts/usine-agents.mjs socle [--a-sec]`, `maj [--forcer]`, `installer <groupe>`, `arreter <groupe>`, `etat` ;
- `node scripts/usine-coffre.mjs poser <NOM> [--depuis-env=<VAR>]`, `retirer <NOM>`, `noms`, `etat` : la valeur ne passe jamais en argument ni sur la conversation ;
- l'accès : `ssh -i ~/.ssh/presti-usine usine@88.96.53.3` (`PRESTI_USINE=usine@<ip>` si l'IP a changé).

**Les pièges de l'usine** (LISEZMOI) : jamais `ufw` ; jamais le paquet `bubblewrap` ; pas de `bash -l` à distance ; le statut « error » de cloud-init peut être trompeur ; l'IP est éphémère.

2. **Avant tout** : `node scripts/usine.mjs etat` (l'usine répond, Codex du compte `usine` connecté) ; sous `usine`, `sudo -n true` [à vérifier : si `usine` n'a pas sudo sans mot de passe, s'arrêter et demander à Benj de passer par la console d'Oracle ; ne jamais contourner].
