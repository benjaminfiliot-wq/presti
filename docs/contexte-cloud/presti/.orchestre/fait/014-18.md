# 014-18 — aperçu privé et mise en ligne dans l'onglet « Sites » (v15 §3.2)

## Préalable

La tâche `014-14` (l'onglet lui-même) doit être **livrée** : `prochaine` ne te donnera pas celle-ci tant que `app/controle/Sites.tsx` n'existe pas — si le fichier manque, libère la tâche (`node scripts/orchestre.mjs liberer 014-18`) et prends-en une autre.

## Le contrat d'API (tel quel)

- `GET /api/controle/sites` rend désormais, **pour la direction seulement**, `apercu: '/site-genere/<id>/?apercu=<jeton>' | null` sur chaque commande (le rôle lecture reçoit `null`).
- `POST /api/controle/sites/<id>` accepte une troisième action : `{ action: 'mettre_en_ligne' }` (état `validee` seulement) → `{ ok, commande, dns: [{ type, name, value }] }`. 409 si aucun site n'est déposé ; 502 si le domaine déclaré ne peut pas être rattaché (message dans `error`).

## Ce que tu fais (dans `app/controle/Sites.tsx` uniquement)

1. Dans le panneau de détail : si `apercu` existe, un lien « Ouvrir l'aperçu privé » (nouvel onglet, `rel="noopener"`). Une phrase : *lien privé, ne pas le partager ; il ne s'indexe pas.*
2. Pour une commande en état `validee` et le rôle `direction` : un bouton « Mettre en ligne » (confirmation simple : « Le site sera servi sur <domaine> — les enregistrements DNS seront à donner à l'artisan. »). Après un `ok` : afficher la liste `dns` (type · nom · valeur, copiable), et la phrase *à poser chez le registrar du domaine par l'artisan ; le sitemap est à soumettre dans la Search Console (Benj).* Recharge la liste.
3. Pour une commande `en_ligne` : le lien public `/site-genere/<id>/` (et le domaine s'il existe).

## Preuve

`node scripts/controle-sites-ui-verifier.mjs --avec-hebergement` vert (il vérifie en plus : `apercu` utilisé, `action: 'mettre_en_ligne'` envoyé sur `validee` seulement, `dns` affiché), capture, `fait/` + `verifier 014-18`, une ligne `014-18 : PASS|FAIL — …`.
