## Contexte

**Pourquoi.** Les agents contactent les artisans ; un site payé est en ligne sous 48 h ouvrées après validation. Si la génération ne tourne que PC allumé, la promesse tombe dès que le PC dort. D'où le Livreur (génération, `site-qa`, dépôt) sur l'usine Oracle `presti-usine`, 24 h/24 ; GitHub Actions reste son repli (026-106) ; le poste peut tout reprendre.

**Les contraintes de l'usine** (`presti-ops/usine/LISEZMOI.md`, et le socle des fiches 01 à 03) :
- elle ne commite jamais : sa clé du dépôt est en lecture seule. **Ses résultats passent par le stockage et le bus**, pas par git ;
- **aucune clé de service Supabase** n'y va jamais. Le seul secret du livreur de l'usine est son **jeton d'agent** (026-040 : un par agent, limité à ses types et à ses tables) ; la rédaction passe par le moteur Codex de l'usine (`CODEX_LANCEUR`), sans clé (R16 annulée). La « clé plafonnée » du stockage, c'est donc : le jeton de l'agent, présenté à une route de Vercel qui ne signe d'URL **que** pour la tâche que cet agent tient sous bail, dans un bucket privé à part, `usine` ;
- Vercel reste en offre Hobby jusqu'au premier site vendu (ce jour-là, Vercel Pro, 20 $ par mois : la seule dépense permise) : les routes font un appel SQL et quelques signatures, jamais de travail lourd ; les fichiers vont **directement** de l'usine au stockage par l'URL signée (pas de corps de 4,5 Mo à travers Vercel) ;
- le bail d'une tâche dure 30 min (`ops_tache_prendre`, 0098) : un travail doit finir avant ;
- 12 Go de mémoire, partagés avec l'atelier, le chef et les fiches Codex de l'orchestre.

## Cahier du juge

Ce que les trois juges font eux-mêmes :

- **Ils comptent** les requêtes reçues par le faux bus, les signatures reçues par le faux stockage et les octets reçus par ses `PUT`, jamais ce qu'un script dit avoir fait.
- **Ils tirent au hasard** les jetons (assemblés à l'exécution, en lettres seules s'ils doivent traverser `scripts/usine.mjs`), puis les cherchent partout : sorties, journaux, corps reçus, argv.
- **Ils décodent** eux-mêmes les fichiers déposés (octets magiques, JSON) ; en `--reel`, ils relisent le site déposé : une sortie « livrée » n'est pas une preuve (mémoires `preuve-vide-est-un-mensonge`, `juge-capture-lui-meme`).
- **Ils lisent** les unités systemd avec un analyseur INI, le SQL avec le tokenizer de `sql-nu.mjs`, commentaires ôtés.
- **En `--reel`**, ils ne créent que des objets marqués `essai_e2e_` ou `essai: true`, et font le ménage dans un `finally`.
- **Ils refusent** tout fichier de preuve, journal ou sortie de 0 octet.
