# 021-01 — le socle des familles

**Pourquoi.** Benj veut la démo Atelier Lestraque au niveau MotionSites : récit au défilement, révélation au survol, objet
éclaté, vidéo. Aujourd'hui, tout le mouvement vit dans `_kit/kit.css` et `_kit/kit.js`, et chaque tâche retouche le générateur.
Pour que ces effets avancent en parallèle, chacun vivra dans sa **famille**, avec ses propres fichiers, et le générateur les
assemblera. Spécification complète : `.orchestre/preuves/021-00/cahier-vague-5.md` §3.0 (lecture seule). Les numéros de ligne
du cahier ont pu bouger : lis le code.

**Règle d'or.** Sans famille active, le site généré est **identique octet pour octet** à celui du commit e33aec0. Seuls les
attributs `data-relief-*` du héros peuvent différer.

## Ce qu'il faut faire dans `public/sites-demo/generer.mjs`

1. **Familles.** Le dossier `public/sites-demo/_kit/familles/` accueille, par famille `<nom>`, jusqu'à trois fichiers :
   `<nom>.css`, `<nom>.js` et `<nom>.mjs`. Un fichier absent ne change rien. Le fichier `.mjs` est chargé par `await import()`
   avec `pathToFileURL`. Il exporte par défaut un objet de crochets, tous facultatifs.
2. **Liste active.**
   - Par défaut, c'est `da.familles`, et `da.json` pose `"familles": []` pour lestraque.
   - `--familles=a,b` la remplace ; `--familles=` veut dire aucune famille.
   - L'ordre de la liste est l'ordre d'assemblage.
3. **Assemblage.**
   - `styles.css` : après `sansCommentaires(KIT_CSS)`, ajouter `sansCommentaires(<nom>.css)` de chaque famille active.
   - `site.js` : écrire `KIT_JS`, puis chaque `<nom>.js`, séparés par `\n;\n`.
4. **Les six crochets.** Chacun a une valeur par défaut qui rend exactement la sortie actuelle.

   | Crochet | Où | Par défaut |
   |---|---|---|
   | `plateauCitation(texte, ctx) → html` | contenu du `<blockquote><p>` du plateau | `esc(texte)` |
   | `plateauValeur(chiffre, i, ctx) → html` | le `<span class="chiffre__valeur">` de chaque chiffre | ce même span |
   | `atelierPhrase(texte, ctx) → html` | contenu de chaque `<p class="atelier__phrase …">` | `esc(texte)` |
   | `etapesMedia(ctx) → html \| null` | remplace `photoEtapes` s'il n'est pas nul | `null` |
   | `herosMedia(ctx) → html` | ajouté après `photoHeros(…)` dans `.hero__media`, **accueil seulement** | `''` |
   | `garde(html, ctx)` | appelé pour chaque page, avec les garde-fous ; lève une erreur pour refuser la génération | rien |

   `ctx` vaut `{ metier, da, site, contenu, rel, photoDe, esc, page }`, avec les fonctions existantes, sans en ajouter.
5. **Attributions.**
   - Les entrées `"type": "video"` et `"type": "rendu"` d'attributions.json sont exclues de la liste des photos : ni contrôle
     des orphelines, ni ligne de crédits photo. Leur famille les affichera elle-même.
   - Les entrées de `lestraque/<nom>/attributions.json` de chaque famille **active** s'ajoutent à la liste avant tout
     garde-fou. Celles d'une famille inactive sont ignorées.
6. **Relief du moment signature**, sur la balise du héros de l'accueil :
   - `data-relief-calme` et `data-relief-lumiere-css`, sans valeur comme aujourd'hui. Ils sont posés quand `da.relief.calme`
     (resp. `da.relief.lumiereCss`) vaut `true`, ou, si la clé est absente, quand `da.signature` est vrai, comme aujourd'hui.
   - `data-relief-descente="<JSON échappé par esc>"` quand `da.relief.descente` existe. Refus (erreur levée) si :
     - `palier` ≠ 0.30 ;
     - `dmax1` n'est pas dans ]0 ; 0.26] ;
     - `dmax15` > `dmax1` ;
     - `h` n'est ni −1 ni 1 ;
     - `gamma` ≠ 0.6 ;
     - `rw` ≠ 0.045.
   - `data-relief-texture="<chemin>"` quand `da.relief.texture` existe. Refus si le fichier est absent du dossier du métier ou
     pèse moins de 1 024 octets.
7. **Ligne de commande.**
   - `--sortie=<dossier>` copie `public/sites-demo/<metier>/` dans `<dossier>` et génère **là**, sans toucher au site.
     **Tout est rendu et vérifié avant la moindre écriture, copie comprise.** Un refus (garde-fou, crochet `garde`, `--da`
     invalide) laisse le dossier de sortie tel qu'il était, et n'en crée pas s'il n'existait pas.
   - `--da=<fichier.json>` : le fichier contient l'entrée du métier, qui remplace `DA[metier]`.
8. `process.exitCode` différent de 0 sur toute erreur, comme aujourd'hui.

## Dans `public/sites-demo/_kit/da.json`, entrée `lestraque`

- `"familles": []`.
- Dans `relief`, ajouter :
  - `"calme": true` ;
  - `"lumiereCss": true` ;
  - `"descente": {"palier": 0.30, "dmax1": 0.116, "dmax15": 0.066, "roulisParDelta": 0, "gamma": 0.6, "rw": 0.045, "h": -1}`.
- **Pas de `texture`** : la clé revient à la tâche 021-02, qui branchera la texture (mipmaps, délai). Le fichier `images/heros-escalier-2880.avif` existe déjà : n'y touche pas.
