## Contexte

**La voie officielle vers une personne** (rectification §3.2 bis, faits du 24/09) : Instagram ne donne **jamais** la liste des abonnés (l'API des statistiques ne rend que des agrégats ; Windsor.ai, relié à @prestiapp, ne donne lui aussi que la démographie agrégée et les commentaires). Le profil d'une personne n'est lisible **qu'après qu'elle a écrit** au compte, ou cliqué une amorce de conversation ; un simple commentaire ne suffit pas (l'API rend une erreur de consentement). D'où l'aimant : le Crieur finit ses publications par « Commente SITE » (026-119) ; chaque commentaire « SITE » reçoit une **réponse privée** officielle (un seul message, dans les 7 jours) ; si la personne répond, la conversation s'ouvre (fenêtre de 24 h), l'agent lit son profil, lui demande métier, ville et site, et le Recenseur la retrouve dans SIRENE.

**Cette fiche ne répond à personne** : elle reçoit, vérifie, range et, pour un STOP, s'oppose tout de suite (§3.10 : en moins de 10 minutes). Le Répondeur (026-096) prépare les réponses ; le Facteur (026-089) les envoie.

**La signature** : Meta signe chaque POST par `X-Hub-Signature-256: sha256=<HMAC-SHA256 hexadécimal du corps brut, clé : le secret de l'application>`. Elle se vérifie sur les octets reçus, **avant** tout `JSON.parse`, par une comparaison à temps constant. La vérification de l'abonnement est un `GET` avec `hub.mode=subscribe`, `hub.verify_token` et `hub.challenge`. [à vérifier le jour de R6 : champs exacts des événements `comments`, `messages`, `messaging_postbacks` pour Instagram et pour la Page.]

**La pause générale ne coupe pas la réception** : recevoir et s'opposer ne s'arrêtent jamais. Et Meta réessaie un webhook qui ne répond pas vite : la route répond 200 dès que les événements sont rangés.

## Ce qu'il faut faire

1. **`lib/agents/acquisition/metaWebhooks.ts`**, pur hors `lireProfil` :
   - `verifierSignature(corpsBrut: Uint8Array, entete: string | null, secret: string)` → `boolean` : préfixe `sha256=`, 64 caractères hexadécimaux, `timingSafeEqual` de `node:crypto` sur des tampons de même longueur ;
   - `normaliserEntrees(corps)` → événements neutres : `commentaire` `{ id_externe: <id du commentaire>, plateforme, meta_id: <from.id>, pseudo: <from.username>, texte, publie_le }` ; `message` `{ id_externe: <mid>, plateforme, meta_id: <sender.id>, texte, a_piece_jointe }` ; `postback` (amorce de conversation) `{ id_externe, plateforme, meta_id, charge }` ; un message **écho** (envoyé par notre compte) et tout le reste → ignorés ;
   - `estAimant(texte)` : après normalisation (minuscules, accents et émojis retirés, ponctuation retirée, espaces fusionnés), le texte vaut exactement `site`, ou commence par `site` et fait 20 signes au plus ; « joli site, bravo » n'est **pas** un aimant ;
   - `traiterEvenements(evenements, deps)`, `deps = { magasin, lireProfil, maintenant }`, pour chaque événement, dans cet ordre :
     - `magasin` : l'événement brut rangé par `acq_meta_evenement_enregistrer` (idempotent : un doublon s'arrête là) ;
     - `commentaire` aimant → `enregistrerConversation({ plateforme, meta_id, pseudo, commentaire_id, commentaire_le })` (le Répondeur préparera la réponse privée) ; commentaire qui n'est pas un aimant → rien d'autre ;
     - `message` ou `postback` → `enregistrerConversation({ plateforme, meta_id, dernier_message_recu_le: maintenant })`, puis `reponseRecue({ source: 'meta', canal: 'messagerie', id_externe, conversation_id, texte })` ; si `estStop(texte)` → `opposer({ meta_id, instagram: pseudo }, 'stop', 'webhook_meta')` tout de suite ; si la conversation n'a pas encore de profil → `lireProfil(meta_id)` (une seule requête, 5 s au plus, après `consommerJauge(magasin, 'instagram_api')`) et les seuls champs `pseudo`, `suit_le_compte`, `abonnes` rangés dans la conversation ;
     - aucune réponse, aucun envoi, aucune création de prospect ici ;
   - `creerLecteurProfil({ jeton, fetch })` → `lireProfil(meta_id)` : `GET https://graph.facebook.com/<version>/<meta_id>?fields=…` [à vérifier], rend `{ pseudo, suit_le_compte, abonnes } | null` ; une erreur de consentement ou de débit → `null`, sans lever ; le jeton n'est jamais journalisé.
2. **`app/api/webhooks/meta/route.ts`** (`runtime = 'nodejs'`, `dynamic = 'force-dynamic'`) :
   - **`GET`** : `hub.mode === 'subscribe'` et `hub.verify_token` égal à `META_WEBHOOK_VERIFY_TOKEN` (comparaison à temps constant ; variable absente → 403) → 200 `text/plain` avec `hub.challenge` tel quel (50 signes au plus, chiffres seulement) ; sinon 403 ;
   - **`POST`**, dans cet ordre : `META_APP_SECRET` absent → **503**, avant toute lecture ; corps brut lu une fois, 256 Ko au plus (sinon 413) ; `verifierSignature` faux → **401**, sans rien parser ni écrire ; `JSON.parse` ; `traiterEvenements` avec `magasinSupabase`, `creerLecteurProfil` (si `META_PAGE_TOKEN` existe, sinon un lecteur qui rend `null`) ; 200 `{ ok: true }` ; une erreur de la base → 500 sans détail (Meta réessaiera) ;
   - pas de `pauseGenerale()` ici ; aucune valeur du corps, pseudo, texte ni jeton dans `console.*` ou dans une réponse.
3. **À ne pas faire** : aucun appel à l'API d'envoi de Meta (c'est le Facteur) ; aucun tag ; aucun pilotage de navigateur ni relevé de la liste des abonnés (conditions d'Instagram, art. 4.2 : interdit) ; aucun import de `@/lib/ai` ni de `@/lib/agents/llm`.

## Cahier du juge (`meta-webhooks-qa`, écrit en 026-081)

Le juge appelle le module et exécute la route par `ts-loader`, avec des doublures de `magasinSupabase`, de `lib/agents/acquisition/standardiste` (le vrai `estStop` est aussi éprouvé) et du `fetch` du profil ; le secret et le jeton d'essai sont posés dans l'environnement du juge.
- **MW-1** le module exporte `verifierSignature`, `normaliserEntrees`, `estAimant`, `traiterEvenements`, `creerLecteurProfil` ; la route exporte `GET` et `POST`.
- **MW-2** `verifierSignature` : juste sur chaque corps signé des jeux d'essai ; faux sur le corps modifié d'un octet, sur une signature tronquée, sans préfixe, absente ; lu dans le source : `timingSafeEqual`, jamais `===` sur la signature.
- **MW-3** `GET` : bon jeton → 200 et le `hub.challenge` exact ; mauvais jeton, jeton absent ou variable absente → 403.
- **MW-4** `POST` : `META_APP_SECRET` absent → 503 et zéro appel au magasin ; signature fausse → 401, zéro appel ; 300 Ko → 413 ; lu dans le source : la vérification précède `JSON.parse` et tout appel au magasin, et aucun `pauseGenerale(`.
- **MW-5** `estAimant` : « SITE », « site ! », « Site 🙂 » → vrai ; « Joli site, bravo », « sites web pas chers » → faux.
- **MW-6** un commentaire aimant → un événement rangé et une conversation avec `commentaire_id` ; un commentaire ordinaire → rangé, sans conversation ; le même commentaire rejoué → aucune seconde écriture hors l'enregistrement idempotent.
- **MW-7** un message reçu → conversation avec `dernier_message_recu_le`, une `reponseRecue` de source `meta`, et un seul appel au profil (pas de second pour la même conversation) ; un message écho → rien ; « STOP » → `opposer` avec `meta_id` dans le même appel.
- **MW-8** profil : réponse d'erreur de consentement → `null` et aucune erreur ; seuls `pseudo`, `suit_le_compte` et `abonnes` sont rangés ; la jauge `instagram_api` pleine → aucun appel au profil.
- **MW-9** aucune valeur des corps d'essai (textes, pseudos) ni le secret n'apparaissent dans la console capturée ou dans les réponses HTTP ; aucune requête vers un autre hôte que `graph.facebook.com` ; `npm run typecheck` vert.
