# Intégration des outils web et voix — 26 septembre 2026

## Firecrawl

**Examen.** `npm view firecrawl-cli repository maintainers scripts dist.tarball version --json` indique la version 1.24.6, publiée sous le nom Firecrawl, dépôt `https://github.com/firecrawl/cli`, mainteneurs `hello_sideguide` et `abimaelmartell`. J'ai décompressé l'archive npm avant exécution : aucun `preinstall`, `install` ou `postinstall` ; `prepare` et `prepublishOnly` servent au développement/publication. L'installation a été faite avec `--ignore-scripts`. Le code utilise surtout `https://api.firecrawl.dev` pour search, scrape, map et crédits ; il contacte aussi `registry.npmjs.org` pour l'avis de mise à jour. Les commandes facultatives `init`, `skills` et `setup` peuvent télécharger des ressources depuis GitHub ou configurer des intégrations ; elles n'ont pas été lancées. Pas de code d'exfiltration ni d'obfuscation détecté dans les chemins examinés.

**Installation et test.** `~/.npm-global` est réellement en lecture seule (`EROFS`/`ENOENT` lors de `npm install --global --prefix /home/usine/.npm-global`). Repli fonctionnel dans `outils/firecrawl-cli/`, sans sudo, par `npm install --prefix outils/firecrawl-cli --ignore-scripts firecrawl-cli@1.24.6`. L'enveloppe [firecrawl.sh](firecrawl.sh) lit la clé en variable puis exécute la CLI sans argument secret. `outils/firecrawl.sh search 'artisan couvreur Marans' --sources web --limit 5 --country FR --json --output outils/essais/firecrawl-search.json` : cinq résultats, 2 crédits. `outils/firecrawl.sh scrape https://prestiapp.fr --format markdown --output outils/essais/firecrawl-scrape.md` : 8 435 octets de Markdown. `outils/firecrawl.sh map https://prestiapp.fr --limit 100 --json --output outils/essais/firecrawl-map.json` : dix URL. Fichiers dans [essais](essais/).

**Compétences utiles.** `search` pour trouver artisans et concurrents publics ; `scrape` pour lire une page ciblée ; `map` pour découvrir les URL sans lire leur contenu ; `crawl` et `batch scrape` pour un site après cadrage du nombre de pages ; `parse` pour des documents publics ; `monitor` pour les changements ; `agent` pour une recherche complexe. Les workflows CLI `find-tools`, `list`, `alexandria`, `research` et `developer` découvrent des sources et outils spécialisés ; les commandes `setup`/`skills` peuvent ajouter des intégrations et doivent être examinées avant emploi. Toujours limiter `--limit` et réutiliser les fichiers déjà produits.

## Fish Audio

**Examen.** Les [références officielles des modèles](https://docs.fish.audio/api-reference/endpoint/model/list-models) et de la [synthèse](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech) décrivent `GET https://api.fish.audio/model` et `POST https://api.fish.audio/v1/tts`, avec authentification Bearer, filtre `language=fr`, tri `task_count` et sortie MP3. Aucun paquet ou installeur tiers n'est exécuté : [fish-tts.mjs](fish-tts.mjs) est un script Node local, qui lit la clé en mémoire et n'envoie que le texte et l'ID public de voix à l'API. L'inventaire [fish-voix-fr.json](essais/fish-voix-fr.json) contient 1 000 voix publiques françaises, nom, ID et nombre d'utilisations, obtenues sur dix pages de l'API. Aucune des 1 000 voix retournées n'a `licensed: true` : une voix publique n'est pas nécessairement autorisée pour une publicité.

**Installation et test.** Script exécutable dans `outils/`, sans sudo. Commande : `outils/fish-tts.mjs 'Bonjour, ici Presti. Votre demande de devis a bien été reçue, un artisan vous rappelle aujourd’hui.' outils/essais/fish-essai-presti.mp3 --voix=<id du catalogue>`. Test réel avec la première voix du catalogue : [MP3](essais/fish-essai-presti.mp3) de 94 457 octets, en-tête de trame MP3 vérifié. Le modèle utilisé est `s2.1-pro-free`. Selon les [tarifs API](https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits), son coût est 0 USD par million d'octets UTF-8 : cet essai n'a donc consommé aucun crédit facturable selon ce barème. L'API TTS ne renvoie pas de compteur de crédits dans cette réponse.

**Licence.** Les [conditions Fish Audio](https://fish.audio/terms/) réservent explicitement l'usage commercial aux services payants ; la [page des forfaits](https://fish.audio/fr/plan/) précise que le niveau gratuit est limité aux projets personnels non commerciaux, malgré un libellé commercial ambigu plus haut sur cette page. Ne pas diffuser ce MP3 dans une campagne ou chez un client sans vérifier le statut payant du compte **et** les droits de la voix choisie. L'essai est un contrôle technique interne.

## uv et GEO

**Examen.** L'installeur officiel `https://astral.sh/uv/install.sh` a été téléchargé et lu avant exécution : script MIT de `astral-sh`, version 0.12.19, choisit l'archive correspondant à l'architecture, la télécharge depuis `releases.astral.sh` avec repli `github.com/astral-sh/uv`, vérifie son SHA-256 intégré, puis copie `uv`/`uvx`. Le mode `UV_UNMANAGED_INSTALL` évite la modification du PATH et le reçu sous `~/.config`. Aucun `sudo` ni écriture dans `/etc`.

Le paquet PyPI `geo-optimizer-skill` 4.18.3 renvoie au dépôt `github.com/Auriti-Labs/geo-optimizer-skill` (commit examiné `ad1bc310`). J'ai lu `pyproject.toml`, le point d'entrée `geo`, les modules d'audit et le client HTTP : requêtes GET/HEAD vers l'URL publique auditée et ses ressources (`robots.txt`, `llms.txt`, découvertes IA), vérification des redirections et des adresses privées, limite de réponse ; les services externes de SERP/LLM sont des fonctions séparées, non nécessaires à `geo audit`. Les dépendances de base sont `click`, `requests`, `beautifulsoup4`, `lxml`, `urllib3`. Aucun installateur additionnel, code obfusqué ou envoi automatique de données privées détecté dans ce chemin.

**Installation et test.** `~/.local/bin` est en lecture seule dans cette session ; l'installeur y échoue à créer son dossier temporaire. Repli en espace utilisateur autorisé : `UV_UNMANAGED_INSTALL=$PWD/outils/uv UV_NO_MODIFY_PATH=1 sh /tmp/presti-uv-install.sh`, puis `outils/uv/uv --version` → `uv 0.12.19`. La commande `uvx --from geo-optimizer-skill==4.18.3 geo audit --url https://prestiapp.fr`, avec `UV_CACHE_DIR` et `UV_TOOL_DIR` sous `~/veille/.cache`, a produit [geo-audit-prestiapp.txt](essais/geo-audit-prestiapp.txt) : HTTP 200, score **52/100**.

**Huit catégories principales :** 1) `robots.txt` et accès des bots IA : ouvert ; 2) `llms.txt` : absent ; 3) JSON-LD : SoftwareApplication, Organization et WebSite présents, FAQPage absent ; 4) métadonnées : titre, description, canonical et Open Graph présents ; 5) contenu : environ 1 103 mots, chiffres présents, sources externes absentes ; 6) technique : langue `fr`, flux RSS et `dateModified` absents ; 7) découverte IA : fichiers `ai.txt`, `summary.json`, `faq.json` absents ; 8) marque et entité : 3/10, manque de liens d'entité, page À propos et coordonnées détectables. Le rapport complet ajoute des contrôles CDN, JS, confiance et multimodal ; les recommandations ne sont pas toutes des facteurs de classement prouvés.

## mcp-gsc

**Examen.** Dépôt `github.com/AminForou/mcp-gsc`, commit `d49eea9e`, cloné sous [competences/mcp-gsc/repo](../competences/mcp-gsc/repo/). J'ai lu le README, les dépendances et `gsc_server.py` : serveur MCP Python qui appelle les API Google Search Console via `google-api-python-client`; l'authentification OAuth lance un serveur local navigateur et stocke un jeton, ou charge une clé de compte de service. Pas de post-install inconnu repéré. Les commandes d'écriture GSC (ajout/retrait de propriété, soumission/suppression de sitemap) existent : les agents ne doivent les utiliser qu'avec une demande expresse. Aucun accès Google n'a été configuré, conformément à la mission.

**Installation et test.** Clone en lecture seule du code ; `git -C competences/mcp-gsc/repo rev-parse --short HEAD` → `d49eea9e`. Aucun test de connexion GSC possible sans identifiants, donc pas de donnée de performance prétendue. Pour l'activer, Benj doit choisir **une** méthode :

1. **OAuth utilisateur :** dans Google Cloud Console, créer ou sélectionner un projet, activer **Google Search Console API**, configurer l'écran de consentement OAuth (ajouter son compte parmi les utilisateurs de test si l'application reste en test), créer un **ID client OAuth de type application de bureau**, télécharger le JSON et le conserver dans un chemin privé absolu. Vérifier que ce compte a accès à la propriété Search Console voulue. Configurer ensuite le client MCP avec la commande `uvx mcp-search-console` et `GSC_OAUTH_CLIENT_SECRETS_FILE=/chemin/absolu/client_secrets.json`. Au premier lancement, ouvrir le navigateur, choisir ce compte et consentir ; le jeton local est ensuite réutilisé.
2. **Compte de service :** même projet et API activée ; créer un compte de service, créer et télécharger une clé JSON, conserver le fichier dans un chemin privé absolu. Dans Search Console → Paramètres → Utilisateurs et autorisations, ajouter l'adresse e-mail du compte de service avec accès complet à la propriété. Configurer le MCP avec `GSC_CREDENTIALS_PATH=/chemin/absolu/[MASQUE_SECRET].json` et `GSC_SKIP_OAUTH=true`. Vérifier avec `list_properties` après démarrage.

Les chemins et variables sont des exemples, pas une configuration appliquée ici. Éviter d'exposer les JSON et jetons dans le dépôt.

## Règles pour les agents

- Lire d'abord les fichiers `outils/essais/` et les pages publiques déjà connues. Firecrawl `search` pour découvrir, `map` pour l'inventaire, `scrape` pour une page précise. Fixer un `--limit` bas ; demander avant un crawl large ou un workflow payant. `outils/firecrawl.sh status` ou `outils/firecrawl.sh credits` affiche le quota restant, sans exposer la clé.
- GEO sert à diagnostiquer les pages publiques ; confronter ses alertes à la page et au code avant de modifier un site. OpenSEO `simple-issue-description` sert à rédiger des tâches, pas à mesurer le référencement. GSC, une fois relié par Benj, sert aux impressions, clics, requêtes et indexation de propriétés autorisées.
- Fish Audio sert aux maquettes vocales internes. Avant publication ou emploi client, confirmer un compte et une voix commercialement autorisés ; limiter le texte et réutiliser les MP3 générés.
- N'envoyer à Firecrawl, Fish Audio, GEO, OpenSEO ou GSC **aucune donnée personnelle de prospect** au-delà de ce que l'outil lit publiquement sur une page web. Ne transmettre ni fichiers CRM, ni numéros/adresses privés, ni contenu de devis. Garder les clés uniquement dans les variables d'environnement des processus concernés.
