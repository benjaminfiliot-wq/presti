# Contrat des juges du lot t (fiche 026-171, partie hors ligne) — ce que les modules, les thèmes et la branche réservée doivent respecter

Écrit par Claude Code le 30/09. Il lie trois choses : **le témoin** (`t/temoin/`, une implémentation minimale et correcte, qui n'est aucun module livré), **les jeux d'essai** (`t/*.json`, `t/themes-pieges/`) et **les juges** (`scripts/station-themes-qa.mjs`, `scripts/ecommerce-reservee-qa.mjs`). Les fiches 026-173, 026-176, 026-185 et 026-190 (Codex) devront respecter les mêmes points : les juges n'y lisent que ceci. Ce qui n'est pas écrit ici est libre. Le juge est la référence, jamais l'inverse : un module qui « passe » en contournant l'un de ces points n'a pas passé.

## 1. Les trois modules purs (026-173, `station-themes-qa --partie=modules`)

Chaque module : TypeScript à **syntaxe effaçable** (pas d'`enum`, de `namespace`, de propriété de paramètre : le juge les importe par `scripts/ts-loader.mjs` sous Node 22), **aucun import hors de `lib/pilotage/`** (`./x` ou `@/lib/pilotage/x` ; `SALLES`, `SALLE_RESERVEE`, `CLES_SALLE`, `EQUIPAGE` viennent de `./equipage`), ni `fetch(`, `Date.now(`, `Math.random`, `supabaseAdmin`, `process.env`, `new Date()`, minuterie, `require`, import dynamique (TH-1).

### `theme.ts` (TH-2)
- `CLES_THEME = ['station', 'vaisseau']` (la liste fermée, exactement).
- `validerTheme(brut)` → `{ ok: true, theme }` (le même objet reçu) ou `{ ok: false, raisons: string[] }` (français, non vide). **Il accepte `cle: 'essai'`** (le schéma la permet ; seul le chargeur restreint à `CLES_THEME`). Il refuse tout ce que `k/theme.schema.json` refuse (champ requis absent, champ inconnu, type, énumération, minimum, motif, `minItems`, `maxItems`) **et** les contraintes hors schéma de `k/validateur.mjs` (un et un seul réservé, sans poste ; les 21 clés une fois ; `defauts` couvre les 21 salles ; avatar `defaut` ; arêtes vers des nœuds existants ; tracé continu à un pas au plus ; étapes sur le tracé ; aucune adresse dans un texte ; les mêmes contraintes pour `portrait`). Il ne jette jamais (`null`, texte, liste → refus). Le juge rejoue ~330 fautes tirées du schéma.
- Chaque champ du schéma a son type dans `theme.ts` (lu : `nom: …`, `'--mc-fond': …`).

### `disposition.ts` (TH-3)
`validerDisposition(theme, disposition)` → `{ ok: true }` ou `{ ok: false, raison }` (une raison, en français). Ne jette jamais ; n'écrit jamais dans ses entrées (gelées par le juge).

`disposition = { salles: { <salle>: <clé d'emplacement> }, plaques?: { <salle>: texte }, coursives?: Coursives, tapis?: Tapis, portrait?: { coursives?: Coursives } }` — `coursives`, `tapis` et `portrait.coursives` remplacent ceux du thème ; absents, ceux du thème comptent. Les mêmes clés d'emplacement servent au bureau et au portrait.

Ordre et mots des refus (le juge cherche ces mots, insensible à la casse) :
1. `salles` illisible ; salle inconnue (le nom de la salle est dans la raison) ; emplacement inconnu (sa clé est dans la raison).
2. **Réservée** : `salles.ecommerce` présent et ≠ l'emplacement réservé → « … réservée … ne se déplace pas » ; `plaques.ecommerce` présent et ≠ `E-commerce` → « … réservée … ne se renomme pas » ; une autre salle dans l'emplacement réservé → « … réservé … ».
3. Chaque salle de `SALLES` dans un emplacement, un seul par salle : « … n'a pas d'emplacement » ; « **Deux salles** occupent l'emplacement … ».
4. **Graphe**, pour le bureau **puis** pour `portrait` : une salle est reliée si la porte de son emplacement touche une arête (distance de la porte au segment ≤ `largeur / 2`) de la composante du Commandement ; sinon « **La Salle de repos n'est plus reliée au reste** » (`La <plaque>` si la plaque commence par « Salle », sinon `La salle « <plaque> »` ; en portrait, préfixe libre) ; le Commandement lui-même : « … Commandement … ». Une arête vers un nœud inconnu est refusée. Le juge coupe le graphe **dans la disposition** (`coursives`, `portrait.coursives`) **et dans le thème** : la grille portrait est vérifiée comme le bureau.
5. **Tapis** : trace continue (deux points consécutifs à un pas au plus sur chaque axe, jamais identiques) et chaque étape sur la trace : « … tapis … ».

### `reglages.ts` (TH-4, TH-5, TH-6)
- `CLES_REGLAGES = ['theme','mise_en_page','nuit','equipage','salles','couleurs','affichage']` (l'ordre est libre, l'ensemble non).
- Forme : `theme` (`station|vaisseau`) · `mise_en_page` (`colonnes|flottante`) · `nuit: { actif?: boolean, debut?: 0..23, fin?: 0..23 }` · `equipage: { <agent de EQUIPAGE>: { nom?, avatar?, couleur? } }` · `salles: { <salle ou ecommerce>: { emplacement?, plaque?, teinte? } }` · `couleurs: { <jeton de theme.palette>: '#RRGGBB' }` · `affichage: { titre?, taille_plaques?: petite|normale|grande }`.
- `validerReglages(brut, theme)` → `{ ok: true, reglages }` (**égal au brut**) ou `{ ok: false, raisons: string[], clesPermises: string[] }` : `clesPermises` est **toujours** rendu en refus et vaut les sept clés ; une clé inconnue est nommée dans les raisons. Bornes : nom **2 à 16** signes, plaque **2 à 24**, titre **2 à 32**, tous en lettres, chiffres, espace, tiret, apostrophe (`'` ou `’`) — donc `<`, `>`, `=`, `;`, `:` refusés ; couleurs `#RRGGBB` seulement ; avatar dans `theme.avatars` ; heures entières de 0 à 23 ; **64 Ko** sérialisés au plus (au-delà : une raison qui dit « 64 Ko » ou « trop gros/volumineux » ou « taille », même si d'autres fautes existent) ; nom d'agent hors `EQUIPAGE` refusé ; jeton hors `theme.palette` (dont `:root`) refusé ; `salles` passe par `validerDisposition` (défauts du thème + surcharges) : deux salles dans un emplacement, réservée déplacée ou renommée → refus. Ne jette jamais (référence circulaire, fonction, `undefined`, `null`, liste, texte → refus) ; ne pollue jamais `Object.prototype` (`__proto__` est une clé inconnue).
- `fusionner(defauts, reglages)` : fusion **en profondeur**, les réglages l'emportent clé par clé, une clé absente garde le défaut, `undefined`/`null`/`{}` rendent les défauts, **copie** neuve (jamais un objet partagé), entrées gelées non modifiées, `fusionner(d, fusionner(d, r))` et `fusionner(fusionner(d, r), r)` égalent `fusionner(d, r)`, les clés `__proto__`, `constructor`, `prototype` ignorées.
- `appliquerReglages(noeud, reglages, theme)` : sur le **seul** nœud passé (doublure : `style.setProperty`, `setAttribute`, `dataset`, `classList`, setters `innerHTML`/`outerHTML`/`textContent`), pose **les dix jetons de `theme.palette`** (la couleur réglée si elle est `#RRGGBB`, sinon celle du thème) et `data-mise-en-page` (réglage sinon thème) ; d'autres `data-*` sont permis, aucun autre attribut, aucune classe, **aucune propriété de style hors des jetons de la palette**, **aucun HTML** (`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, enfants). Rien sur `document.documentElement`, `body`, `head`, `document` (le juge les remplace par des doublures qui consignent toute écriture). Nœud `null`/`undefined` : aucune écriture ailleurs. Rejouer deux fois donne le même état.

## 2. Les thèmes (`station-themes-qa --theme=station|vaisseau`, 026-185 et 026-190)

Dossier `public/station/themes/<clé>/` : `theme.json`, `licence.json`, un atlas `atlas*.png|webp` (composite), un fond `fond.webp|avif` (la nébuleuse). Rien d'autre que du json et des images (jamais `.js`, `.svg`, `.html`, `.css`).

- **TH-7** `theme.json` conforme au schéma **et** aux contraintes hors schéma (par `k/validateur.mjs`) ; `cle` = la clé demandée ; **exactement 21 emplacements** : 20 avec un poste et **un seul réservé, `ecommerce`, `poste: null`** ; bloc `portrait` de 21 emplacements.
- **TH-8** `validerDisposition(theme, defauts du thème)` accepte (bureau et portrait) **et** le calcul du juge trouve toutes les portes ordinaires reliées au Commandement et le tapis continu.
- **TH-9** poids : le thème (tous ses fichiers) **≤ 700 Kio**, les deux thèmes ensemble **≤ 1,5 Mio**, le fond **≤ 200 Kio** ; un atlas et un fond présents.
- **TH-10** `licence.json` = `{ "packs": [ { "dossier", "titre", "auteur", "adresse", "licence", "date" } ] }` : `dossier` parmi les dix du lot A (`01-ganamoda`, `02-ansimuz-sideview`, `03-warped-city`, `04-rottingpixels-scifi-tileset`, `05-zwonky-spacers`, `06-kenney-tiny-factory`, `07-ansimuz-tech-lab`, `08-emceeflesher`, `09-shade-puny-characters`, `10-buch`), sans doublon ; `licence` contient `CC0` ; `adresse` en `https://` ; `date` en `AAAA-MM-JJ` ; des champs en plus (`fichiers`, `licence_json`…) sont tolérés. Là où `~/station-assets/<dossier>/licence.json` existe (l'usine), titre, auteur, adresse (= `page`), licence et date doivent lui être égaux. **Aucune image du thème n'a l'empreinte d'une feuille du lot A** : le juge relit `~/station-assets` (l'usine) ou `.orchestre/travail/station-planche-qa/empreintes-lot-a.json` ; sur l'arbre réel sans l'un ni l'autre, il sort en **code 2** (préalable), jamais en vert.
- **TH-11** le jeu `t/themes-pieges/` (17 thèmes abîmés, `pieges.json`) : le juge se prouve refuser chacun avec sa raison (sans licence, atlas de 800 Ko, feuille brute, réservée avec un poste, hors du lot A, non CC0, adresse http, « starnet », champ de code, fichier `.js`, sans fond, fond trop lourd, sans portrait, 20 emplacements…).
- **TH-12** aucune adresse (`http:`, `https:`, `data:`, `javascript:`, `//`) ni balisage dans `theme.json`, aucun champ nommé comme du code (`on…`, `script`, `code`, `html`, `css`, `js`, `url`, `href`, `src`, `style`, `eval`…), aucun « starnet » (casse et espace libres) dans un nom de fichier, `theme.json` ou `licence.json`.
