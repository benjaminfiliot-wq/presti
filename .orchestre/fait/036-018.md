## À construire

Cinq gabarits `gabarit-ent-*`, inactifs et sans identifiant.

**`gabarit-ent-operations`**
- planificateur sur l'agenda réel : outil de lecture Google Agenda ou Outlook ;
- répartiteur des équipes ;
- projets dans ClickUp, monday ou Notion ;
- dossiers Drive ou OneDrive ;
- import Sheets ou Excel par le circuit contrôlé.

**`gabarit-ent-administratif`**
- pièce manquante : lecture croisée Drive, Gmail ou Outlook, puis relance de qui doit le document ;
- échéances (assurances, attestations, contrôles) dans l'Agenda ;
- attestations rédigées dans Docs.

**`gabarit-ent-finance`**
- encaissements lus dans Stripe, QuickBooks, Xero, ou Qonto par l'API (lecture seule) ;
- export au comptable vers Pennylane, Tiime ou Sage, par l'API ou par export ;
- facturier « quand c'est fini » ;
- relanceur d'impayés ;
- **montants par le code** ; aucune écriture bancaire.

**`gabarit-ent-apres-vente`**
- avis lus sur la fiche Google et sur Trustpilot (API) ;
- support Zendesk ou Chatwoot (API) ;
- alerte client mécontent ;
- entretien et contrats ;
- avis négatif toujours à un humain.

**`gabarit-ent-direction`**
- page du matin de direction, rapport du lundi, bilan à un mois, point mensuel ;
- le code compte, le modèle rédige ;
- envoi par Slack, Teams, Google Chat ou Gmail ;
- **validation d'équipe par les outils HITL de n8n** (Slack, Teams) ;
- compteur du coût IA et de ce qui sort vers un modèle externe (mode privé, A14).

**Pour les cinq**
- autonomie par type d'action selon l'annexe du contrat ;
- multi-membres, chacun valide son périmètre ;
- aucune donnée d'une autre organisation ;
- marque blanche ;
- notes sur chaque nœud d'outil.

**Essais** (`test_workflow`, simulation, données « Exemple. ») :
- une attestation qui expire donne une relance prévue ;
- un paiement lu donne un impayé arrêté ;
- un avis à 1 étoile donne une carte ;
- un rapport du lundi aux chiffres du code ;
- une autre organisation ne donne rien.
