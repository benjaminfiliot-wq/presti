## Contexte

L'organigramme (§6, poste 3) : « Après la mise en ligne, puis chaque mois : le site répond, HTTPS, poids, accessibilité, liens morts, mentions légales de l'artisan, indexation dans la Search Console, formulaire présent et fonctionnel. […] Ne modifie jamais un site en ligne ; n'envoie jamais de faux message dans le formulaire d'un client ; propose une correction au Livreur ou à Claude Code. »

Deux mémoires s'appliquent directement : **« Preuve vide est un mensonge »** (un vérificateur qui teste l'existence est satisfait par un fichier vide — quatre captures de 0 octet le 13/09) et **« Le juge mesure le décor »** (une propriété géométrique se mesure géométriquement — pas une approximation qui ressemble à la vraie mesure). Le juge de cette fiche doit donc **mesurer**, jamais constater une présence : un code HTTP réel, un poids réel en octets, un contraste réel calculé sur les couleurs rendues, un lien suivi jusqu'à son vrai code de réponse.

**Jamais de faux message dans le formulaire d'un client** : contrainte dure, différente du reste de la série (où le Juge des faits, 026-065, revérifie *avant* un envoi automatique à un prospect). Ici il n'y a **aucun** envoi à tester : le contrôle du formulaire se limite à une vérification **passive** (le formulaire existe, ses champs et son action sont présents dans le HTML rendu, son point d'entrée répond) — jamais une soumission, même de test.

Règle du 28/09 : le verdict visuel d'une capture passe par Codex (`personnelles: true`), parce qu'un site livré porte le nom de l'artisan — une donnée personnelle. Le reste (codes HTTP, poids, liens) est du code sans modèle.

## Ce qu'il faut faire

1. **`scripts/fixtures/026/qualite-sites/serveur-factice.mjs`** : un serveur HTTP local qui sert des pages réglables — une page saine (HTTPS valide, poids sous le budget, contraste correct, mentions légales présentes, formulaire complet, aucun lien mort) et, par drapeau, chaque panne séparément : code 500, certificat expiré (simulé par un indicateur, pas un vrai TLS), poids au-delà du budget (page de 3 Mo), un texte de contraste insuffisant (couleur claire sur fond clair, calculée au ratio WCAG), trois liens internes dont un mort (404), une page sans section mentions légales, un formulaire dont l'attribut `action` est absent.
2. **`scripts/fixtures/026/qualite-sites/sites-livres.json`** : cinq commandes livrées factices, dont une **programmée au retrait** (026-031 : 12 mois après suppression) que le contrôle **ne doit pas** auditer comme un site actif, et une dont l'URL en ligne est absente (livraison inachevée).
3. **`scripts/qualite-sites-qa.mjs [--partie=disponibilite,poids,accessibilite,liens,mentions,formulaire,decision] [--preuve-echecs] [--reel]`** : le cahier QSI ci-dessous, une ligne `PASS|FAIL QSI-n — …`, un bilan `qualite-sites-qa : PASS|FAIL — ids`.
4. **`--preuve-echecs`** : (a) l'arbre courant échoue avec **QSI-2** en premier (le module n'existe pas) ; (b) un témoin minimal posé par ce juge passe tout sur la page saine ; (c) chaque sabotage (au moins 9 : une écriture tentée sur le site audité, une soumission réelle du formulaire, un audit du site programmé au retrait, un poids mesuré sur un fichier tronqué plutôt que la vraie réponse, un contraste « approximé » sans calcul du ratio réel, un lien mort compté comme vivant, une mention légale absente non signalée, une décision créée deux fois pour la même panne, un verdict visuel envoyé à un moteur `:cloud` ou gratuit) échoue avec son critère.

## Cahier du juge (`scripts/qualite-sites-qa.mjs`)

- **QSI-1** Contrat : le module s'importe sans effet de bord ; aucune méthode d'écriture (`PUT`, `POST`, `DELETE`, un client FTP ou Git) vers le site audité n'apparaît dans son source — le juge grep le texte.
- **QSI-2** Disponibilité : le code HTTP et le protocole (HTTP vs HTTPS, certificat valide) sont ceux **réellement rendus** par le serveur factice, jamais devinés ; un site programmé au retrait (026-031) est exclu de l'audit sans erreur ; un site sans URL en ligne sort en `livraison_inachevee`, jamais une panne.
- **QSI-3** Poids : le poids mesuré est celui des octets réellement reçus (la réponse HTTP complète, pas une estimation d'en-tête `Content-Length` non vérifiée) ; au-delà du budget (à fixer, par exemple 3 Mo la page d'accueil) → `poids_excessif` avec le nombre exact d'octets.
- **QSI-4** Accessibilité : le contraste texte/fond est **calculé** (ratio WCAG réel sur les couleurs rendues, pas une liste blanche de classes CSS) ; en dessous du seuil AA → `contraste_insuffisant` avec l'élément et le ratio ; un attribut `alt` d'image manquant est compté.
- **QSI-5** Liens morts : chaque lien interne est suivi jusqu'à son vrai code de réponse (redirection suivie une fois, jamais indéfiniment — boucle détectée et signalée) ; un lien mort (404, 500, délai dépassé) sort dans `liens_morts` avec son URL exacte ; le débit de vérification respecte 1 requête par seconde et `robots.txt`, comme `lecteurSite.ts` (026-020).
- **QSI-6** Mentions légales : une page qui ne contient aucune des mentions attendues (nom de l'artisan, SIREN, adresse, forme juridique — la liste exacte vient du gabarit de livraison, à lire dans le HTML rendu, jamais supposée) sort en `mentions_absentes`.
- **QSI-7** Formulaire, contrôle passif seulement : le formulaire de contact est vérifié par sa **présence** dans le HTML (champs, attribut `action`, méthode) et par le code de réponse d'une requête **`GET` ou `HEAD`** sur son point d'entrée — **jamais** une requête `POST` de soumission ; le juge grep le source du module et refuse toute méthode d'écriture vers le point d'entrée du formulaire.
- **QSI-8** Verdict visuel : l'appel à un modèle pour juger une capture passe par `MOTEUR_DE` avec `personnelles: true` (Codex) ; sans lui, le contrôle automatique (codes, poids, liens) reste valide seul, et le verdict visuel sort `non_mesure` plutôt que d'appeler un moteur gratuit ou `:cloud`.
- **QSI-9** Décision, jamais d'action : chaque panne détectée crée **une** décision (`creerDecision({ type: 'qualite_site', … })`), jamais une correction directe du site ; deux passages sur la même panne, dans la même période, ne créent pas deux décisions (idempotence).
