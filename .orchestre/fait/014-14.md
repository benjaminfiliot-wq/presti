# 014-14 — l'onglet « Sites » du Poste de contrôle (v15 §3.2)

## Ce que c'est

À 300 €, on ne met pas en ligne un site que personne n'a regardé : un humain valide. Cet onglet montre les commandes de site (payées, générées, validées, en ligne) et, pour une commande **générée**, permet deux gestes : **Valider** (`generee → validee`) ou **Renvoyer en génération avec une consigne** (`generee → payee`). L'API existe (`app/api/controle/sites/route.ts`, `app/api/controle/sites/[id]/route.ts`) — tu ne la modifies pas.

## Le contrat d'API (tel quel)

- `GET /api/controle/sites?etat=<etat>&limite=50` → `{ commandes: [{ id, artisan: { id, nom, metier, slug } | null, email, etat, domaine_mode, domaine, metier, metiers_secondaires, communes, prix_cents, paye_le, genere_le, valide_le, en_ligne_le, scores, verifications, consigne, regenerations, cree_le, modifie_le }] }`. `scores` (quand la génération les a posés) : `{ performance, accessibility, 'best-practices', seo }` sur 100 ; `verifications` : le rapport JSON de `scripts/site-qa.mjs` (blocs → tests `{ nom, passe, mesure, attendu }`). Les deux peuvent être `null` (pas encore générée).
- `POST /api/controle/sites/<id>` `{ action: 'valider' }` ou `{ action: 'regenerer', consigne }` (consigne ≥ 10 signes) → `{ ok, commande }` ; 400 consigne manquante, 403 rôle lecture, 409 état incompatible, 503 indisponible (message dans `error`).
- Tout appel passe par `apiDirection<T>(chemin, init)` de `app/controle/client.ts` (jeton, timeout, erreurs réseau gérées) — jamais par le client Supabase.

## Ce que tu fais

1. `app/controle/Sites.tsx` — un composant d'onglet **sur le modèle exact de `app/controle/Journal.tsx`** (78 lignes : props `{ role }`, chargement, états chargement/erreur/vide, table `psh-dtable`). Une table dense : artisan (nom, métier), état (`LIBELLE_ETAT` de `@/lib/siteCommande`), métier et communes (compte), dates (payée, générée, validée), les **quatre scores Lighthouse** quand ils existent (vert ≥ 95, sinon rouge — le seuil est celui du juge), le nombre de régénérations. Filtre par état en tête (`?etat=`). Une ligne ouvre un panneau de détail : le récapitulatif du dossier, la liste des vérifications en échec s'il y en a, la consigne précédente, et — **seulement si l'état est `generee` et le rôle `direction`** — deux boutons : « Valider » (confirmation simple) et « Renvoyer en génération » (champ consigne obligatoire, puis envoi). Après un geste : recharge, message court. Le rôle `lecture` voit tout, sans boutons.
2. `app/controle/page.tsx` — ajoute `'sites'` au type `Onglet`, à `ONGLETS` **derrière `actif('siteCommande')`** (motif du spread des autres onglets, lignes 31-37), à `TITRES` (« Sites »), à `NAV` (icône simple), et rends `<Sites role={role} />` pour cet onglet. **Synchronise les trois** (un onglet dans NAV sans ONGLETS reste visible mais inaccessible).
