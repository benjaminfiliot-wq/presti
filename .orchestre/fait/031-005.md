# 031-005 — jeton des webhooks de la file de Hermes, et compte rendu Slack

## Pourquoi

Audit 031-003, constat 1 (critique), contre-vérification du 01/11 : « les 3 webhooks n'ont toujours aucune authentification ».
N'importe quel programme du PC ou d'Oracle peut remplir la file de bruit ou faire disparaître une vraie tâche avec une fin
forgée. Benj veut aussi voir la fin de chaque tâche dans Slack (#presti-auto).

Le PC envoie maintenant l'en-tête `x-presti-jeton` à chaque appel (`scripts/hermes-tache-n8n.mjs`, fonction `appel`). Le jeton
reste sur le PC. **n8n n'en garde que l'empreinte SHA-256 (hexadécimal, minuscules) :**

`ae2eb34b74a00103dc6e9a67b688e7bdd4a62f9d86342dc853150419c31f7a0e`

## Avant de construire

Avec le MCP `n8n-oracle` : `get_user_preferences`, puis `get_workflow_sdk_reference`, puis `get_workflow_details` sur
`SvVxqrXdpt5sOCTL`. Ne jamais deviner la syntaxe du SDK. `validate_workflow` avant `update_workflow`, puis `publish_workflow`.

## Ce qu'il faut changer (et rien d'autre)

1. Juste après **chacun** des trois nœuds Webhook (POST `hermes-tache-ajouter`, GET `hermes-tache`, POST `hermes-tache-faite`) :
   - un nœud **Crypto** : action « Hash », type SHA256, encodage hex, valeur `{{ $json.headers['x-presti-jeton'] || '' }}`,
     résultat dans une propriété nouvelle `empreinteJeton` (l'élément d'origine, `body`, `query`, `headers`, reste intact) ;
   - un nœud **IF** « Jeton valide ? » : `{{ $json.empreinteJeton }}` égal à l'empreinte ci-dessus ;
   - branche fausse : **Respond to Webhook**, code 401, corps JSON `{"erreur":"jeton"}` ;
   - branche vraie : la chaîne existante, inchangée. Si une expression en aval lit `$json` directement, vérifier qu'elle lit
     toujours les mêmes champs (sinon la faire lire `$('<nom du webhook>').item.json`).
2. **Slack, seulement si un identifiant Slack existe déjà** (`list_credentials`) : dans la branche de `hermes-tache-faite`, après
   la mise à jour réussie de la ligne, un nœud Slack qui poste dans `#presti-auto` une ligne
   `Hermes — <tache> : <statut> — <resume>` (la ligne mise à jour donne `tache`), réglé « Continue On Fail » pour qu'une panne
   de Slack ne casse jamais la réponse au PC. **Aucun identifiant n'existe : n'en crée pas** ; écris-le dans le résumé.
3. `validate_workflow`, `update_workflow`, `publish_workflow`. Vérifier par `get_workflow_details` que la version active est
   la nouvelle.

## Vérifier

`node scripts/hermes-tache-n8n.mjs --verifier-jeton` doit rendre le code 0 (« OK : sans jeton et avec un faux, 401 sur les trois
webhooks ; avec le jeton, la file répond »). Avant le changement, il rend 1 (prouvé le 01/11 à 22 h 15). Sortie complète dans
`.orchestre/preuves/031-005/verifier.log`. Puis `node scripts/hermes-tache-n8n.mjs --precheck` doit rendre 0 (la revue id 3 attend).

## Interdits

Tout autre workflow ; créer un identifiant ; toucher aux lignes de `taches_hermes` ; afficher ou lire un secret ; envoyer quoi
que ce soit d'autre que la ligne Slack décrite. Bloqué : `.orchestre/en-cours/031-005.question.md`, deux ou trois options.
