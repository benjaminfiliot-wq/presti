## Contexte

L'onglet Pilotage montre :
- **Agents** : une ligne par agent, avec son dernier battement, son statut, son coût du mois et un bouton Pause (plan §4.2, point 6). Les agents sont dans `ops.agents` (migration 0096 du bus) ; la fonction `pilotage_agents()` (fiche 04) rend `{ nom, libelle, en_pause, pause_motif, battement_le, periode_minutes, disjoncteur_ouvert_le, cout_mois_eur }` ;
- **Code** : les tâches de l'orchestre et les PR qui attendent (point 7).

**Les seuils des agents sont ceux du veilleur A0** (fiche 026-047) : un agent est **muet** quand son battement a plus de 2 × `periode_minutes` ; il est **en panne** au-delà de 2 × période + 2 h (c'est la panne qui déclenche la notification immédiate du plan §4.4). L'écran et le veilleur doivent dire la même chose (mémoire « Deux chiffres, un écran ») : mêmes seuils, écrits une fois ici.

**L'orchestre vit sur le poste de Benj**, pas sur Vercel : `.orchestre/file/`, `en-cours/` (un fichier `<id>.lock` par tâche prise, lignes `agent: …` et `depuis: <ISO>`, écrit par `scripts/orchestre.mjs:256`), `fait/`, `refuse/` et `verdicts.jsonl` (une ligne JSON par verdict : `id`, `verdict`, `ligne`, `date`, `executant`…). Pour que l'onglet le montre téléphone en main, un script du poste **publie** un relevé dans la base (`pilotage_code_publier`, fiche 04), et l'écran dit son âge. **PC éteint, le relevé ne bouge plus** : l'écran doit le dire (« le poste ne publie plus depuis 3 h : PC éteint ? »), jamais montrer un vieux relevé comme frais.

Un script peut charger `.env.local` lui-même, sans l'afficher, sur le modèle de `scripts/site-deposer.mjs:17`, qui ne remplace jamais une variable déjà posée (plan §5.5). Il ne lit jamais `presti-secrets`.

## Ce qu'il faut faire

1. **`lib/pilotage/agents.ts`**, pur (seul import permis : `euros` et `relTime` de `@/lib/direction/fraicheur`) :
   - `etatAgent(a, maintenant)` → `{ nom, libelle, etat: 'actif' | 'muet' | 'panne' | 'pause' | 'disjoncteur' | 'jamais', depuis: string | null, cout: string, panne2h: boolean }` :
     - `disjoncteur` si `disjoncteur_ouvert_le` n'est pas nul ; sinon `pause` si `en_pause` ; sinon `jamais` si `battement_le` est nul ; sinon `panne` au-delà de 2 × période + 2 h ; sinon `muet` au-delà de 2 × période ; sinon `actif` ;
     - `panne2h` vrai seulement pour `panne` ;
     - `cout` = `euros(cout_mois_eur)`, ou « — » s'il est nul ;
   - `lignesAgents(rows, maintenant)` : triées `panne`, `disjoncteur`, `muet`, `pause`, `jamais`, `actif`, puis par nom.
2. **`lib/pilotage/code.ts`**, pur :
   - le type `SnapshotCode` : `{ version: 1, genere_le, file: string[], en_cours: { id, agent, depuis }[], fait: number, refusees: number, derniers: { id, verdict, date, executant, ligne }[], prs: { numero, titre, depuis, brouillon }[] | null, prs_raison?: string, attention: string[] }`. `attention` porte les lignes du bloc « ## Attention (n) » du digest de l'orchestre (026-109 : disjonctées, verrous expirés, questions en attente, sauvegarde en retard, décisions proposées), 7 au plus, chacune avec sa commande entre accents graves : c'est la recommandation R5 de la recherche du 24/09, portée dans le Pilotage en phase 2 (revue du 24/09, B11) ;
   - `validerSnapshot(x)` → `SnapshotCode | null` : version 1 exactement ; listes de 50 éléments au plus, et `attention` de **7** au plus ; chaînes de 200 signes au plus ; toute clé hors du type fait refuser ;
   - `resumeCode(s, publie_le, maintenant)` → `{ file, enCours, verrousVieux, derniers, prs, attention, perime, message, publie_le }` (`attention` recopiée telle quelle du relevé, `[]` sans relevé) : `verrousVieux` = les tâches en cours depuis plus de 60 min (seuil du plan §8) ; `perime` au-delà de 2 h depuis `publie_le` ; `message` = « Le poste ne publie plus depuis 3 h : PC éteint ? » quand `perime`, « Aucun relevé du poste reçu. » sans relevé, sinon `null`.
3. **`scripts/pilotage-code-publier.mjs [--a-sec] [--orchestre=<dossier>]`** :
   - lit le dossier d'orchestre (défaut `.orchestre/`) **en lecture seule** : identifiants de `file/*.md`, verrous `en-cours/*.lock` (agent et `depuis`), nombre de `fait/*.md` et de `refuse/*.md`, les 5 dernières lignes de `verdicts.jsonl` (`ligne` coupée à 160 signes), et les lignes du bloc `## Attention (n)` de `digest.md` (7 au plus, chacune coupée à 200 signes ; bloc absent ou « rien à décider » → `[]`) ;
   - les PR ouvertes par `gh pr list --state open --json number,title,createdAt,isDraft --limit 20` (sans shell) ; en cas d'échec, `prs: null` et `prs_raison: 'gh indisponible'` ;
   - bâtit un `SnapshotCode` de 20 000 octets au plus (les listes se raccourcissent d'abord) ;
   - `--a-sec` : écrit le JSON sur la sortie standard, n'ouvre aucune connexion, code 0 ;
   - sinon : charge `.env.local` **sans écraser** ce qui est déjà dans l'environnement ni rien afficher, puis `POST <NEXT_PUBLIC_SUPABASE_URL>/rest/v1/rpc/pilotage_code_publier` avec `{ p_etat }` et la clé de service ; n'affiche que « publié (N octets) » ou « échec : <code HTTP> » ; code 1 si la réponse n'est pas `ok`.
4. `npm run typecheck` doit être vert. Ne modifier aucun fichier d'`.orchestre/`.
