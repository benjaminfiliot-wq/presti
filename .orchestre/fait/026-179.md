## Contexte

Décision de Benj du 25/09 : l'interface est **Claw3D, avec des dessins pixel art, dans le Poste**. La voie (§0.1) : on copie le **moteur** de Claw3D dans presti, pas son application ; aucune route de Claw3D, aucune passerelle, aucun WebSocket ; l'usine n'est jamais appelée par le navigateur.

**Ce qui se copie** (§0.3, depuis `~/claw3d`, commit 0565b78, sur l'usine, en lecture seule) :
- l'hôte Phaser `OfficePhaserCanvas.tsx`, **réécrit en mode station seul** : sans les imports d'`OfficeBuilderScene` et d'`OfficeViewerScene`, sans les classes Tailwind (absentes de Presti : le cadre ferait 0 px), avec un **module CSS** du moteur à la place ;
- le pont `OfficeSceneBridge.ts` (63 lignes) ;
- les types de carte et de zone de `lib/office/schema.ts` (dont les zones en polygone) ;
- `buildNavGrid2D` et `astar2D` de `lib/office/pathfinding.ts` (sans three) ;
- le générateur d'avatar `lib/avatars/profile.ts` (272 lignes, sans `multiavatar` ni `Math.random`).

**Ce qui se reprend de l'atelier** (`~/claw3d-pixel`, notre code du 25/09) : `StationPixelScene.ts` **sans sa fonction `roomFor`** (qui devinait la salle), `agentPainter.ts`, et, de `config.ts`, **la seule `PIXEL_PALETTE`** (pas `PIXEL_MODE` ni `PIXEL_TRUTH_MODE` : `?pixel=0` dans l'adresse coupait la vérité).

**Ce qui ne se copie jamais** : toute la 3D (three, React Three Fiber, drei, `RetroOffice3D.tsx`, les `.glb`), l'orchestrateur `OfficeScreen.tsx`, tout ce qui suppose OpenClaw ou une passerelle (`server/`, `src/app/api/*`, `lib/gateway`, `lib/runtime`…), `lib/office/presence.ts` (disque et passerelle), `multiavatar`, les systèmes d'ambiance (lumières qui vacillent, vapeur, bulles tirées au hasard).

**Phaser** est déjà dans `package.json` (3.90.0, préalable de 026-170) : **jamais** `npm install`, jamais d'écriture dans `~/claw3d-pixel`.
