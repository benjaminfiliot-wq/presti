# 036-014 — Les gabarits outillés de l'argent : Devis, Suivi, Facturation (prompt 6, outillage)

## Ton rôle

Tu es ingénieur d'automatisation n8n. Tu construis les workflows comme dans les vidéos et les dépôts :
- un déclencheur ;
- un agent IA avec son modèle, ses outils de lecture et son parseur ;
- puis les nœuds d'écriture des vrais outils.

La porte de Presti se place devant chaque écriture. Ce sont les lignes 2 à 4 de la matrice de
`plans/011-cadrage-01-11/p6-signature/outillage/OUTILLAGE.md`, § 5.

**Le code calcule tous les montants, jamais le modèle** (p6:292). L'agent rédige des libellés et des messages ; un prix vient des tarifs de
l'artisan (`lib/prix/`), sinon il est marqué « estimé » et ne part jamais seul.

## À construire

Trois gabarits, inactifs et sans identifiant :

**`gabarit-artisan-devis`** :
- Rédacteur de lignes (agent, Claude, parseur ; outils de lecture : tarifs dans Sheets ou Excel, `lib-*` des prix en outil) ;
- montants par le code (appel de `presti-dep-devis`) ;
- PDF rangé dans Drive ou OneDrive ;
- envoi Gmail ou Outlook en Signature seulement, si tous les prix viennent des tarifs (`envoi_devis`) ;
- brouillon et carte en Studio ;
- signature Yousign ou DocuSign par l'API (nœud HTTP, hôte écrit en dur), derrière la porte.

**`gabarit-artisan-suivi`** :
- Relanceur (agent ; outil de lecture : `lib-controler-conflit`) ;
- relance par le canal d'origine : Gmail, Outlook, SMTP, WhatsApp, Telegram, Twilio pour le SMS quand l'API est choisie (sinon SMS préparé,
  `lib/sms/lien.ts:10`) ;
- registre des relances ; STOP et opposition respectés.

**`gabarit-artisan-facturation`** :
- paiements lus dans Stripe (lecture seule) ;
- facture **déjà émise** envoyée (`envoi_facture`) ;
- PDF dans Drive ou OneDrive ;
- export au comptable dans Sheets ou Excel ;
- Relanceur d'impayés (agent), opt-in, jusqu'au paiement ou au motif.

Pour les trois : dépôt de chaque action dans la plateforme (HTTP Supabase, filtre du compte), marque blanche, mention de l'assistant après le
modèle (R20), notes sur chaque nœud d'outil.

**Essais** (`test_workflow`, simulation, données épinglées « Exemple. ») :
- un devis avec tous ses prix tarifés en Signature : envoi prévu ;
- un prix estimé : carte, jamais d'envoi ;
- Studio : brouillon ;
- une relance avec STOP : rien ;
- un paiement lu dans Stripe : la relance d'impayé s'arrête ;
- une facture non émise : jamais envoyée.
