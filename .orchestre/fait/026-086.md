## Contrat (recopié dans `contrat-ops.json`)

- **`public.ops_horloge_minute()`** rend `bigint` : l'identifiant de la requête pg_net, ou `null`. `security definer`, `set search_path = ops, public, pg_temp`. Exécutable par **personne** d'autre que son propriétaire : `revoke` de `public`, `anon`, `authenticated` et `service_role`. Son corps, dans cet ordre :
  1. `begin perform public.ops_baux_expirer(); exception when others then <événement> end;` ;
  2. la même chose pour `ops_decisions_echues()` ;
  3. `select decrypted_secret into v_s from vault.decrypted_secrets where name = 'cron_secret'`. Absent → un événement `horloge_sans_secret`, s'il n'y en a pas eu dans l'heure, et `return null` ;
  4. `return net.http_get(url := 'https://prestiapp.fr/api/agents/tic', headers := jsonb_build_object('Authorization', 'Bearer ' || v_s), timeout_milliseconds := 30000)`. La valeur doit rester entre 10 000 et 55 000.
- **`public.ops_horloge_etat(p_minutes integer)`** rend `jsonb`. `service_role` seul. Les clés :
  - `job_actif` et `planning` ;
  - `secret_present`, un booléen par `exists(…)` : **jamais la valeur** ;
  - `executions` (`reussies`, `echouees` sur la fenêtre, par `cron.job_run_details`) ;
  - `trous` : les écarts de plus de 5 min entre deux exécutions, 20 au plus ;
  - `reponses` : le nombre de réponses par code HTTP dans `net._http_response`, sur les 6 dernières heures au plus ;
  - `derniere_execution`.
- **Les tâches planifiées** :
  - `cron.schedule('presti-agents-tic', '* * * * *', 'select public.ops_horloge_minute()')` ;
  - `cron.schedule('presti-cron-menage', '17 3 * * *', $$delete from cron.job_run_details where end_time < now() - interval '7 days'$$)`.
- **Le secret n'est jamais dans le dépôt.**

## Relance du 28/09 : blocage 2BP01 et correctif

Le premier essai à sec (matin du 28/09) échouait dès `create extension if not exists pg_cron;` :
`ERROR 2BP01 dependent privileges exist`, un état de la base (ACL dupliquée sur `cron.job`,
diagnostiqué en détail dans `.orchestre/preuves/026-086/relance-2026-09-28.md` et
`relecture-claude-28-09.md`), reproductible même hors du bloc d'essai, même avec l'extension déjà
installée. Trois relectures (Codex, deux passes Claude) ont conclu à un geste de Benj au tableau de
bord (Extensions → pg_cron → désactiver/réactiver), resté sans effet sur l'ACL.

Correctif appliqué à la place, sans toucher aux droits de `cron.job` ni attendre de geste de Benj :
les deux `create extension if not exists` nues remplacées par un bloc gardé (`do $$ begin if not
exists (select 1 from pg_extension where extname = …) then create extension …; end if; end $$;`),
qui n'exécute `create extension` que si `pg_extension` ne porte pas déjà la ligne — donc ne relance
jamais le script de réinstallation interne de pg_cron qui échouait. `scripts/horloge-sql-qa.mjs`
(genre `extension_gardee` dans `GENRES`, HS-1) adapté en conséquence pour reconnaître cette forme et
**interdire** la forme nue désormais (aucun critère affaibli) : ajouté au `perimetre` de cette fiche,
retiré de `interdit` (il y figurait par défaut comme tout script de juge, mais cette relance en avait
besoin). Essai à sec réussi (HS-8 vert), contre-vérification indépendante (4 attaques + rejeu réel
double, `.orchestre/preuves/026-086/contre-verif-2026-09-28.md`), migration appliquée pour de vrai,
