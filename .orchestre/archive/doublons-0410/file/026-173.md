# 026-173 — les modules purs de la personnalisation (N3)

## Contexte

La station se personnalise (§5 de l'interface) : **l'habit, jamais les chiffres**. Thème (Station ou Vaisseau), mise en page (colonnes ou flottante), nuit, noms et avatars et couleurs de l'équipage, plaques, teintes et place des salles, jetons de couleur, titre, taille des plaques. Les réglages sont **partagés** (un jeu pour les fondateurs), **rangés en base** (026-175), versionnés et journalisés (026-177). **Rien n'est téléversé** : les avatars se choisissent dans la liste du thème, il n'y a ni image envoyée ni CSS libre.

**Une seule fonction pure par règle**, au serveur comme à l'écran (§5.3, §0.6) :
- la route des réglages (026-177) valide par `validerReglages` et `validerDisposition` avant d'écrire ;
- le panneau Réglages (026-187) les appelle à chaque changement, pour l'aperçu en direct et pour dire pourquoi une disposition est refusée ;
- `Habillage.tsx` (026-187) pose le résultat de `appliquerReglages` sur le nœud `.mc` ;
- le chargeur du thème (026-180) valide le thème par `validerTheme` avant de le donner au moteur.

**Le format du thème** est fixé par `scripts/fixtures/026-pilotage/k/theme.schema.json` (026-170) : `cle`, `nom`, `version`, `grille`, `mise_en_page`, `palette`, `emplacements` (forme `rectangle` ou `polygone`, porte, poste, plaque, teinte, drapeau `reservee`), `coursives`, `tapis`, `defauts`, `avatars`, `nuit`, et le bloc `portrait` facultatif. La salle réservée E-commerce (décision 7 de Benj) a un emplacement fixe, sans poste : **on ne la déplace pas et on ne la renomme pas**.

Modules purs : syntaxe effaçable seulement (le juge les importe par `scripts/ts-loader.mjs`), aucun import hors de `lib/pilotage/` (`SALLES`, `SALLE_RESERVEE` et `EQUIPAGE` viennent de `equipage.ts`, 026-070), ni `Date.now()`, ni `Math.random`, ni réseau.

## Ce qu'il faut faire

1. **`lib/pilotage/theme.ts`** : les types du thème (`Theme`, `Emplacement`, `Coursives`, `Tapis`, `Portrait`, `Palette`) d'après le schéma ; `CLES_THEME = ['station', 'vaisseau'] as const` (la liste fermée ; le thème d'essai `essai` n'existe que dans le juge) ; `validerTheme(brut)` → `{ ok: true, theme } | { ok: false, raisons: string[] }` : champs requis, 20 emplacements au moins et **un seul** réservé sans poste, formes, palette en `#RRGGBB`, aucune adresse `http`, aucun champ inconnu.
2. **`lib/pilotage/disposition.ts`** : `validerDisposition(theme, disposition)` → `{ ok } | { ok: false, raison }` en français, pour la grille bureau **et** la grille `portrait` : chaque salle de `SALLES` dans un emplacement et un seul ; le graphe des coursives connexe depuis le Commandement (« La Salle de repos n'est plus reliée au reste ») ; le tapis de la prospection continu ; la réservée à sa place, sous son nom.
3. **`lib/pilotage/reglages.ts`** :
   - `CLES_REGLAGES` = `theme`, `mise_en_page`, `nuit`, `equipage`, `salles`, `couleurs`, `affichage` (schéma fermé, §5.3) ;
   - `validerReglages(brut, theme)` → `{ ok, reglages } | { ok: false, raisons, clesPermises }` : une clé inconnue refusée **avec la liste** ; couleurs `#RRGGBB` ; noms de 2 à 16 signes (lettres, chiffres, espace, tiret, apostrophe ; le nom technique ne change jamais) ; plaques de 2 à 24 ; titre de 2 à 32 ; avatars dans la liste fermée du thème ; heures de nuit de 0 à 23 ; 64 Ko au plus sérialisé ; la disposition passée à `validerDisposition` ;
   - `fusionner(defautsDuTheme, reglages)` → les réglages l'emportent clé par clé ; une clé absente garde le défaut ; entrées gelées non modifiées ;
   - `appliquerReglages(noeud, reglages, theme)` : pose les jetons `--mc-*` (palette du thème, puis couleurs réglées) et `data-mise-en-page` **sur le seul nœud qu'on lui passe** (le `.mc` de la station) ; jamais sur `document.documentElement` ni `body` ; aucun texte posé en HTML.
4. `npm run typecheck` doit être vert (sur l'usine).
