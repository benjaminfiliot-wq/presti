# 026-252 — Next 16 (build) : sortir `LIBELLE_RETIRE` du module serveur `siteRetrait`

## Contexte (trouvé par 026-006, 28/09)

`npm run build` (= `next build --webpack`, Next 16.3.6) échoue avec :

```
node:crypto
Module build failed: UnhandledSchemeError: Reading from "node:crypto" is not handled by plugins (Unhandled scheme).
Import trace for requested module:
node:crypto
./lib/siteDossier.ts
./lib/siteRetrait.ts
./app/controle/Sites.tsx
./app/controle/page.tsx

node:zlib
Module build failed: UnhandledSchemeError: Reading from "node:zlib" is not handled by plugins (Unhandled scheme).
Import trace for requested module:
node:zlib
./lib/zip.ts
./lib/siteDossier.ts
./lib/siteRetrait.ts
./app/controle/Sites.tsx
./app/controle/page.tsx
```

L'import fautif a été ajouté par le commit `6b3054af` (026-078, Codex, 28/09 19h09) — pas un artefact de cette fiche.

`app/controle/Sites.tsx` est un composant `'use client'`. Il ne s'en sert que d'une chose : `import { LIBELLE_RETIRE } from '@/lib/siteRetrait'` (ligne 7, une constante `string`). Mais `lib/siteRetrait.ts` importe en tête de fichier `creerJetonDossier` depuis `lib/siteDossier.ts`, qui importe `node:crypto` ; `lib/siteDossier.ts` importe aussi `ZipFlux` depuis `lib/zip.ts`, qui importe `node:zlib`. Résultat : tout ce graphe (crypto, zlib, Supabase admin, e-mail, Vercel…) se retrouve tiré dans le bundle **client**, pour une seule constante de libellé. Le webpack de Next 16 refuse net les imports `node:*` non gérés dans un bundle client ; Turbopack (utilisé jusque-là) ne relevait pas l'erreur de la même façon.

## Ce qu'il faut faire

1. Créer `lib/sitesConstantes.ts` (nouveau fichier, aucune dépendance) contenant `ETAT_RETIRE` et `LIBELLE_RETIRE` (les deux constantes actuellement définies en tête de `lib/siteRetrait.ts`).
2. Dans `lib/siteRetrait.ts` : remplacer la définition locale de `ETAT_RETIRE`/`LIBELLE_RETIRE` par un ré-export depuis `lib/sitesConstantes.ts` (`export { ETAT_RETIRE, LIBELLE_RETIRE } from './sitesConstantes'`), pour que le reste du fichier (qui en dépend) continue de marcher sans changement.
3. Dans `app/controle/Sites.tsx` : changer l'import de `LIBELLE_RETIRE` pour qu'il vienne de `@/lib/sitesConstantes` au lieu de `@/lib/siteRetrait`.
4. Ne rien changer d'autre. `lib/siteDossier.ts` et `lib/zip.ts` (le vrai code `node:crypto`/`node:zlib`) restent intouchés : ils ne sont légitimement utilisés que côté serveur.
5. `npm run build`. S'il reste rouge sur un AUTRE import qui remonte au client (pas celui décrit ici), écrire la ligne exacte dans `diagnostic.md` et s'arrêter — ne pas improviser une solution plus large que ce que dit cette fiche.

## C'est fini quand

- `node scripts/next16-qa.mjs --groupe=dependances` est vert (N16-1 à N16-7).
- `diagnostic.md` montre la chaîne d'import d'avant (citée ci-dessus) et confirme qu'elle n'existe plus après (recherche de `node:crypto`/`node:zlib` dans le bundle client, ou simplement le fait que le build passe).
- Rien n'a bougé hors périmètre.
