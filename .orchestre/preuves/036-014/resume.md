## La règle « le code calcule, n8n route »

- Aucun nœud Code ne contient un opérateur arithmétique, `Math`, `reduce` ou `parseFloat` : le juge lit l'arbre syntaxique (TypeScript) de chaque nœud Code. Un montant est LU (centimes entiers ou texte rendus par la base) et seulement comparé (`c.amount === f.total_ttc_centimes`).
- **Devis** : le modèle ne reçoit **aucun prix** (son entrée ne contient que références, désignations et unités des tarifs) et son schéma n'a aucun champ de montant ; « Revalider les lignes » rejette toute clé en trop, attache à chaque ligne le prix LU dans les tarifs, la marque « estimée » (sans prix) si le tarif n'a pas de provenance reconnue (copie de `SOURCE_OK`), et cite le repère d'un ancien chantier sans jamais le prendre pour une source. Le total affiché est celui que le chef `presti-dep-devis` lit dans la base.
- **Facturation** : le modèle n'écrit que des variables (`{montant}`, `{numero}`…) ; un chiffre suivi d'un signe monétaire, un lien ou une variable inconnue est **rejeté** ; le code remplace les variables par les textes lus (« 1 200,00 € TTC »).

## Écarts au plan et points à valider (réversibles, défauts appliqués)

1. **L'envoi seul d'un devis et d'une facture est dans ces gabarits**, comme la tâche le demande (`envoi_devis`, `envoi_facture`), alors que 036-005 l'avait laissé à une carte (`lib-decider@1` réserve `envoyer_devis` aux cartes, p5:226). Les gabarits appliquent la règle du pilote eux-mêmes (Signature, pilote actif, type activé, toutes les lignes sourcées, plafond, délai d'annulation). **Avant tout client réel : accord de Benj**, et `lib-decider@2` si l'envoi doit repasser par la bibliothèque.
2. **Mention d'assistant contre `PIED_AUTOMATIQUE`** : un rappel d'impayé porte, dans l'application, `PIED_AUTOMATIQUE` ; le garde commun (R20) exige la mention d'assistant sur tout envoi en aval d'un modèle et refuse le pied des impayés sur un nœud qui déclare la mention. Le gabarit porte la mention. À trancher par Benj : étendre R4 / R20 ou garder la mention.
3. **Les vues et fonctions à écrire dans la base** (hors du périmètre, migration, « go » écrit de Benj) : `n8n_config_agents`, `n8n_demandes_a_chiffrer`, `n8n_tarifs_artisan`, `n8n_devis_prets`, `n8n_devis_lignes`, `n8n_reperes_prix`, `n8n_destinataires`, `n8n_relances_dues`, `n8n_factures_argent`, `n8n_apercus_facture`, les fonctions `n8n_pdf_devis` et `n8n_pdf_facture` (PDF en base64, rendu par `lib/DevisPDF.tsx`), et les colonnes lues ou écrites de `opportunites`, `assistant_actions`, `messages`, `relances_impayes`. Aucune n'est vérifiée dans la base : les noms de colonnes sont ceux des contrats `contrats/*.json` et de `lib/`, ceux des vues et fonctions sont nouveaux. **Sans elles les gabarits ne lisent rien** (côté sûr : un passage vide).
4. **`organisation_id` = le compte de l'artisan** : le garde commun impose ce nom de filtre ; les contrats des chefs (036-005) utilisent `artisan_id` pour le même UUID. Chaque requête porte donc les deux, égaux.
5. **Le workflow d'erreur** (`lib-erreur-commune`) n'est pas publié : `update_workflow` refuse de le désigner (message verbatim : « has no published version »), seule la création par le SDK l'accepte. Les trois premiers gabarits posés ont été refusés pour cette raison puis **archivés** (`PgzaIUuLs2Bf7XS3`, `C33YGfyhM5JmWzGM`, `cTTv7oM0LXzuT8SY`, créés par cette tâche) et recréés à neuf avec le réglage posé à la création.
6. **Sous-workflows non publiés** : n8n n'appelle un sous-workflow que dans sa version publiée. Avant une copie réelle : publier `presti-dep-devis`, `lib-controler-conflit` (puis `lib-erreur-commune`) et ajouter la copie à leurs `callerIds`.
7. **Champs requis vides** : n8n refuse de *tester* un workflow dont un paramètre requis est vide, même sur un nœud non joué (premier essai refusé : Drive, OneDrive, Sheets, Excel). Les champs portent donc des repères `…_DU_CLIENT` (ni identifiants ni secrets) que la copie remplace.
8. **Un type de nœud retiré** : l'outil HTTP de l'agent (`@n8n/n8n-nodes-langchain.toolHttpRequest`) est signalé « retiré » par n8n ; je l'ai ôté (les repères d'anciens chantiers sont lus par le code, et le modèle ne les voit pas). Son remplaçant `n8n-nodes-base.httpRequestTool` n'est pas dans la liste blanche du garde commun (non modifiable ici) : à ouvrir dans le lot 036-012 si un outil HTTP d'agent est voulu.
9. **Signature électronique** : Yousign, seule la création de la demande est portée (le document, le signataire et l'activation sont les appels suivants de la fiche connecteur 036-017) ; DocuSign, le chemin porte `COMPTE_DOCUSIGN_DU_CLIENT` à remplacer. Authentification : `httpTemplatedCustomAuth`, sans identifiant (avertissement de n8n suivi).
10. **Le MCP n8n était bien branché** malgré la consigne « Pas de MCP n8n ici » : utilisé, dans le périmètre (créer `gabarit-artisan-*`), sans toucher à aucun autre workflow. Rien n'a été publié ni activé, aucun identifiant n'a été créé, modifié ou branché, aucun appel réel au modèle, à Supabase, à Stripe ni à un canal.
11. **Présentation** : n8n signale 34 à 35 boîtes au premier niveau du canevas (au-dessus des 7 conseillées). Les groupes de nœuds ne sont pas posés (sans effet sur le fonctionnement) ; à faire dans la copie si Benj veut une toile lisible.
12. **Limites de l'essai** : les sept essais n8n rejouent les nœuds Code, If et Switch de n8n sur des entrées épinglées (lectures, chef, contrôleur, Stripe) ; ils ne prouvent ni les vues de la base, ni le rendu des PDF, ni le comportement des API des outils (aucun compte n'est branché). Le modèle n'est jamais appelé dans ces essais.
