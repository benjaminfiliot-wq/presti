# 036-039 — Le vrai tableau de bord de l'artisan

## Ton rôle
Tu es le développeur interface de Presti, au niveau d'un poste de pilotage professionnel : dense, lisible, rapide. Chaque chiffre vient de la
base et dit d'où il vient.

## Avant d'agir, lis
- `CLAUDE.md` (règles produit : aucune donnée inventée, une fonctionnalité non finie n'apparaît pas, multi-tenant strict par RLS) ;
- `.claude/skills/presti-design/SKILL.md`, la console (`app/globals.css`, palette sombre froide, accent corail `#D97757`) ;
- le tableau de bord actuel, `app/dashboard/page.tsx` (en lecture seule : il est en travaux ailleurs), et `app/crm/` (l'outil de gestion,
  sa vue 2D) ;
- le schéma, dans `supabase/migrations/` : demandes (`leads`), conversations et messages, devis, factures, clients, tarifs, inventaire et
  stock, chantiers, agenda, relances, `assistant_actions` (origine `agent`), crédits ;
- les lecteurs existants dans `lib/` (`lib/crm/`, `lib/inventaire/`, `lib/assistant/`…). Réutilise-les.

## À faire
1. **La page `app/tableau-de-bord/page.tsx`**, serveur d'abord. Elle n'existe que si `actif('tableauComplet')` est vrai (sinon 404, rien
   dans le DOM). La session principale ajoute le drapeau dans `lib/flags.ts` ; toi, tu ne touches pas ce fichier.
2. **Les blocs**, dans cet ordre, chacun avec un état vide honnête (« Aucun devis ce mois-ci »), jamais un zéro inventé :
   1. le jour : demandes neuves, messages sans réponse, rendez-vous, cartes « à valider » ;
   2. l'argent : encaissé ce mois et l'an passé, à encaisser, impayés en retard, par mois sur douze mois ;
   3. les devis (créés, envoyés, acceptés, refusés, taux d'acceptation) et les factures (émises, payées, en retard) ;
   4. les clients : nombre, nouveaux, meilleurs clients par chiffre ;
   5. les chantiers et l'agenda ;
   6. le stock (articles sous le seuil) et les tarifs (nombre de prix, derniers modifiés) ;
   7. les relances : dues, faites ;
   8. ce que les assistants ont préparé, et les crédits utilisés sur le mois.
3. **La vérité de chaque chiffre.**
   - Chaque bloc porte sa source au survol : la table et la date de lecture.
   - Les lectures passent par le client Supabase de la session de l'artisan, donc par la RLS. **Jamais par `service_role`.**
   - Les montants sont sommés en centimes, sans arrondi caché.
4. **Mise à jour en continu**, sans recharger la page.
   - Relecture toutes les 30 secondes, avec « mis à jour il y a … ».
   - Ou le temps réel de Supabase, si les tables sont déjà dans sa publication : vérifie-le dans les migrations, n'en écris aucune.
5. **Le design** : un poste de pilotage dense, pas de grandes cartes décoratives. Il tient en 390 px, avec 16 px de marge et sans défilement
   horizontal, et respecte `prefers-reduced-motion`.
6. **Le juge `scripts/tableau-de-bord-qa.mjs`**, hors ligne, avec ses mutants (chacun DOIT être vu). Les mutants :
   - une lecture par `service_role` ;
   - un chiffre sans source ;
   - un montant en euros flottants ;
   - un bloc sans état vide ;
   - la page visible drapeau baissé ;
   - un autre artisan lisible (filtre `artisan_id` ôté d'une requête qui n'a pas la RLS).
7. **Les captures** 1440 et 390, sur des données fictives seulement, dans la preuve.

Tu n'inscris pas le juge dans `scripts/tout-verifier.mjs` : la session principale le fera.
