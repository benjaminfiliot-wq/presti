# 014-01 — les quatre écrans de `/site/commander`

## Ce que c'est

Le site vitrine devient un produit à la demande : **300 € nets, une fois** (l'entreprise est en franchise en base, art. 293 B du CGI — TVA non applicable), livré sous **48 h ouvrées** après validation humaine. L'artisan remplit un dossier en quatre écrans, puis paie sur Stripe. **L'API existe et est testée** (`scripts/site-commande-e2e.mjs`, 27/27) : ta tâche est l'interface, rien d'autre. Tu ne touches ni à l'API, ni à la base, ni aux règles.

## Le contrat d'API (tu l'utilises tel quel — tu ne le modifies pas, tu ne le contournes pas)

Toutes les requêtes portent `Authorization: Bearer <jeton>` — le jeton vient de `supabase.auth.getSession()` (`@/lib/supabaseClient`), même motif que `app/inventaire/page.tsx`.

- `GET /api/site/commander/brouillon` → `{ brouillon, erreurs: string[], commandes: Commande[] }`. `brouillon.id` est `null` tant que rien n'est enregistré. 404 si le drapeau est baissé, 401 sans session.
- `PUT /api/site/commander/brouillon` avec un `Brouillon` en JSON → `{ brouillon, erreurs }`. **Jamais rejeté** : on sauvegarde ce qu'on a, `erreurs` dit ce qui manque, en phrases affichables telles quelles. 409 = « terminez votre inscription ». Tu enregistres à chaque écran validé (et tu peux enregistrer plus souvent).
- `POST /api/site/commander` → `{ url, commande }` : `url` est la page de paiement Stripe (`window.location.assign(url)`). 400 `{ error, erreurs }` si le dossier est incomplet ; 403 pour un compte fondateur ; 503 si le paiement est indisponible.
- Photos : `POST /api/media?ext=webp|jpg|png` avec **le corps brut de l'image** (pas de FormData), après `preparerPhoto(file, 'galerie')` de `@/lib/media` (qui redimensionne et donne `{ blob, ext }`) → `{ ok, url, utilise, plafond }` ; 413 trop lourde, 429 trop d'envois, message dans `error`. L'`url` rendue va dans `matiere.photos[].url`. **Jamais `supabase.storage` côté client** (interdit depuis la migration 0059).
- Types et constantes : tout vient de `@/lib/siteCommande` — `Brouillon`, `Matiere`, `Photo`, `ModeDomaine`, `MODES_DOMAINE`, `PRIX_SITE_TEXTE`, `DELAI_ANNONCE`, `PHOTOS_MIN`, `PHOTOS_MAX`, `COMMUNES_MAX`, `METIERS_SECONDAIRES_MAX`, `LIBELLE_ETAT`, `sirenValide`, `erreursAvantPaiement`. **Le prix n'est écrit nulle part ailleurs** (le vérificateur le contrôle).

## Les quatre écrans

Une machine à états en mémoire, `type Etape = 'domaine' | 'zone' | 'matiere' | 'paiement'` (motif : `app/login/page.tsx:28`), une barre de progression sobre, un bouton « Continuer » par écran qui enregistre (`PUT`) puis avance ; « Retour » toujours possible sans perte.

1. **Le domaine** — trois choix (`MODES_DOMAINE`) : « J'ai déjà un nom de domaine » (champ, ex. `martin-plomberie.fr` — si `erreurs` signale un domaine invalide, on le dit sous le champ), « Je n'en ai pas, proposez-m'en un » (champ facultatif pour une idée), « Plus tard ». Une phrase, toujours visible : *le domaine reste à votre nom, jamais au nôtre.*
2. **Le métier et la zone** — métier principal (texte), métiers secondaires (jusqu'à `METIERS_SECONDAIRES_MAX`), **communes réellement servies** (liste de puces, ajout au clavier avec Entrée, jusqu'à `COMMUNES_MAX`). Une phrase : *c'est la matière de votre référencement local : les communes où vous allez vraiment, pas un rayon.*
3. **La matière** — photos de chantiers (au moins `PHOTOS_MIN`, jusqu'à `PHOTOS_MAX` ; rôle `avant` / `apres` / `chantier` ; légende courte facultative ; aperçu ; suppression), logo (facultatif), adresse professionnelle, SIREN (9 chiffres — `sirenValide` pour dire tout de suite si la clé est fausse), horaires (texte libre), **assurance décennale : assureur et numéro, obligatoires**, lien vers les avis Google (facultatif).
4. **Le paiement** — récapitulatif lisible du dossier ; `PRIX_SITE_TEXTE` avec la mention *une fois, sans abonnement — TVA non applicable, art. 293 B du CGI* ; le délai `DELAI_ANNONCE` ; **la liste `erreurs` telle quelle** si elle n'est pas vide (bouton désactivé, chaque phrase renvoie vers l'écran concerné) ; sinon le bouton `Payer 300 €` (libellé construit depuis `PRIX_SITE_TEXTE`) → `POST` → redirection Stripe.

Retours : `?paiement=ok` → écran d'état (le `GET` montre la commande, `LIBELLE_ETAT[commande.etat]`, la date, le délai annoncé) ; `?paiement=annule` → écran 4, dossier intact. Si `commandes` contient une commande qui n'est pas en `brouillon`, la page s'ouvre sur l'écran d'état, pas sur le formulaire.
