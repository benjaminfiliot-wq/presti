Le processus enfant reçoit une fausse adresse et une fausse clé :
- `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:<port>` ;
- `SUPABASE_SERVICE_ROLE_KEY=cle-factice-juge`.

Le vrai client `@supabase/supabase-js` (`lib/supabaseAdmin.ts:1-10`) parle donc au juge. Les noms des paramètres envoyés sont confrontés à `scripts/fixtures/026-horloge-bus/contrat-ops.json` (lot 01).

## Ce qu'il faut faire

1. **`scripts/lib/faux-postgrest.mjs`** :
   - `demarrer({ contrat, reponses })` rend `{ url, appels, arreter }` ;
   - une fonction absente du contrat répond 404 `PGRST202`. Un paramètre inconnu, ou un paramètre manquant, répond 400. Le juge compte ces 400 comme une faute du code jugé ;
   - `reponses[fonction]` est une valeur, ou une fonction `(params) => { status, body }`. Elle simule par exemple une erreur `P0001` au message `ops:quota` ;
   - le serveur répond aussi à `/rest/v1/<table>` (lecture) pour les doublures de tables.
2. **Les trois juges**, qui implémentent les cahiers du juge des fiches 10, 11 et 12. Options :
   - `--racine=` ;
   - `--temoin` : les critères de non-régression, plus l'auto-contrôle du faux PostgREST, qui doit refuser un paramètre au mauvais nom ;
