# 014-16 — l'onglet « Cerveaux » du Poste de contrôle (v15 §8.3)

## Ce que c'est

Benj doit voir si Presti devient meilleur ou non : par cerveau, le score, la tendance, le dernier changement. La route existe : `GET /api/controle/cerveaux` → `{ cerveaux: [{ id, score, reussis, total, date, cas, ouverts, derniereEntree }] }` (score = dernier score accepté en %, `null` si aucun ; `derniereEntree` = le titre de la dernière entrée du journal du cerveau). Lisible par les deux rôles. Appel via `apiDirection` (`app/controle/client.ts`).

## Ce que tu fais

1. `app/controle/Cerveaux.tsx` — sur le modèle exact de `app/controle/Journal.tsx` : une table dense, une ligne par cerveau : nom, score (vert ≥ 90, orange ≥ 70, rouge en dessous ; « — » si null), `reussis/total`, cas et ouverts, date du score, dernière entrée du journal. Une phrase d'en-tête : « Un score = des cas de référence rejoués contre le cerveau tel qu'il est. Un score qui baisse ne se fusionne pas. » Pas de graphique tant qu'il n'y a qu'un point par cerveau (la tendance viendra avec l'historique).
2. `app/controle/page.tsx` — `'cerveaux'` dans le type `Onglet`, dans `ONGLETS` (**sans drapeau** : la route et le registre existent), dans `TITRES` (« Cerveaux ») et `NAV` ; rends `<Cerveaux role={role} />`. Synchronise les trois.

## Règles

Densité d'un outil (skill `presti-design`, Poste de contrôle) ; français ; aucune animation. Si `014-14` est en cours sur `app/controle/page.tsx` en même temps, `prochaine` ne te donnera pas cette tâche : attends qu'elle soit livrée.
