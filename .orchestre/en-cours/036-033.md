# 036-033 — Le bouton « Connecter », dans l'outil de gestion

## Ton rôle
Tu es le développeur interface de Presti : tu poses l'écran qui manque sur un circuit déjà construit et jugé.

## Avant d'agir
- Lis l'existant :
  - `lib/connexions/` (routes, OAuth, chiffrement, fournisseurs) et `app/api/connexions/` ;
  - le juge `scripts/connexions-qa.mjs` (39 mutants verts) ;
  - l'outil de gestion `app/crm/` (036-020, et la boîte « À valider » de 036-030) ;
  - le design `presti-design`.
- Charge toutes les ressources de design (note d'Oracle), et liste-les dans ta preuve.

## À faire
1. **L'écran `app/crm/outils/`** (« Mes outils »), avec un lien depuis l'outil de gestion (`app/crm/Gestion.tsx`). Il montre :
   - ce qui est branché (état, date, « Retirer ») ;
   - un bouton « Connecter » par outil **dont le circuit existe** : Google (Gmail, Agenda, Drive), vers
     `/api/connexions/google/demarrer` avec les paramètres que la route attend (lis-la).

   Aucun outil sans circuit n'apparaît : « une fonctionnalité non finie n'apparaît pas ».
2. **Le drapeau.** L'écran n'existe que si `peut()` et le drapeau `connexions` le permettent. Drapeau baissé : 404, rien dans le DOM, aucun lien.
   Tu ne lèves pas le drapeau : la session principale le fera.
3. **Le retour.** Après l'OAuth, la route de retour renvoie quelque part : lis où, et fais que l'écran affiche « Gmail connecté », ou
   l'erreur en clair.
4. **Le juge `scripts/connecter-ecran-qa.mjs`**, hors ligne, avec ses mutants (chacun DOIT être vu), plus une entrée dans `SUITES`. Les
   mutants :
   - bouton vers une route absente ;
   - outil sans circuit affiché ;
   - écran visible avec le drapeau baissé ;
   - jeton ou secret dans le client ;
   - « Retirer » sans confirmation.
5. **Les captures** 1440 et 390, drapeau forcé en local seulement, dans la preuve.

Écris du TypeScript typé et propre : la session principale fait le typage et le build.
