# 036-027 — Le cerveau des deux lib-* rend un texte vide : le réparer, puis republier la chaîne

## Ton rôle
Tu es l'ingénieur IA de Presti, chargé des cerveaux de n8n : tu répares un réglage de modèle, tu le prouves par les bancs, et tu republies en simulation.

## Ce que 036-025 a trouvé (`.orchestre/preuves/036-025/resume.md`, `etat.json` et la section 036-025 du journal)

- L'identifiant « Anthropic account » (`anthropicApi`, `hZsu1Oq5gUfaa2jB`) est affecté aux deux nœuds « Claude Haiku 5.5 ». Il marche :
  le modèle répond.
- Mais `completionTokens` est exactement égal à `maxTokensToSample` (300 pour l'un, 700 pour l'autre), et le texte rendu est vide. D'où
  « The AI model returned an empty response to the Structured Output Parser » : exécutions 784, 802, 820 et 790.
- `lib-lire-photo` ne transmet que la référence de la photo (`passthroughBinaryImages: false`) : le modèle « décrit » une photo qu'il ne
  voit pas. C'est une fabrication, interdite chez Presti (CLAUDE.md, « Anti-fabrication »).
- La chaîne a été dépubliée, parents d'abord : `presti-cerveau`, `presti-dep-suivi`, `presti-dep-facturation`, `lib-rediger-message`.
  `lib-lire-photo` et `presti-dep-accueil` sont restés publiés.

## Avant d'agir

- Réseau neuronal : `regles_pour` « cerveau, modèle, anti-fabrication, n8n », puis `chercher` « lib-rediger-message ».
- Lis la fiche 9 de `plans/011-cadrage-01-11/p6-signature/outillage/fiche-methode-n8n.md`, si elle existe : un banc manuel juge le
  brouillon des enfants, pas leur version publiée.
- Relis chaque workflow dans n8n avant de le toucher. Pour le nœud du modèle, lis sa définition avec `get_node_types` ou
  `validate_node_config` : ne devine aucune option.

## À faire

1. **Trouver la cause, preuve à l'appui.** Relis une exécution en échec nœud par nœud : options du nœud, réflexion du modèle (thinking)
   activée ou non, jetons consommés, texte rendu. Écris la cause dans la preuve avec le numéro de l'exécution.
2. **Réparer `lib-rediger-message`.** Selon la cause :
   - relève `maxTokensToSample` à une valeur qui laisse la place au texte attendu par le schéma (2 000, par exemple) ;
   - et/ou coupe la réflexion si l'option existe et qu'elle mange le budget.

   Ne touche ni au prompt ni au schéma, sauf si la cause est là : alors écris pourquoi. Le modèle reste Claude Haiku 5.5.
3. **Réparer `lib-lire-photo`, sans rien inventer.**
   - Le modèle doit recevoir l'image elle-même : un nœud qui la télécharge en binaire depuis sa référence, puis
     `passthroughBinaryImages: true`, ou l'équivalent que la définition du nœud propose.
   - Si l'image ne peut pas être lue (absente, trop lourde, format refusé), le workflow rend « photo non lue », sans aucune description.
     Jamais une description sans l'image.
   - Même réglage du plafond de sortie qu'au point 2.
4. **Rejouer les bancs, une fois chacun** (deux fois au plus si tu corriges entre les deux), porte « simulation » à vrai :
   - `presti-banc-argent` (facturation) ;
   - `presti-banc-suivi` ;
   - `presti-banc-cerveau` (accueil et photo) ;
   - `lib-banc-relance` : il s'était arrêté à la rédaction.

   Relis chaque exécution nœud par nœud. Un banc « succès » dont un compte rend « erreur » n'est pas vert. Le texte rédigé doit être lisible
   et en français : cite-en une ligne dans la preuve, sans aucune donnée personnelle (les bancs n'en portent pas).
5. **Republier la chaîne si les bancs sont verts.** Dans l'ordre : `lib-rediger-message`, `presti-dep-suivi`, `presti-dep-facturation`,
   `presti-cerveau`.
   - Un workflow qui échoue deux fois est dépublié, parents d'abord, avec sa raison.
   - Ce qui reste rouge est écrit, avec la condition qui le relancera.
6. **Écrire la preuve.**
   - Dans `journal-mise-en-service.md`, ajoute à la fin une section « 036-027 » : cause, réglage avant et après, bancs, exécutions,
     résultat, retour arrière.
   - Dans `.orchestre/preuves/036-027/etat.json` :

     ```
     { "noeuds": { "<id du workflow>": { "avant": {…}, "apres": {…}, "preuve": "exécution n° et ce qu'elle montre" } },
       "bancs": [ { "banc", "execution", "resultat" } ],
       "chaine": { "<id>": { "nom", "publie": true|false, "retour" } } }
     ```

     `noeuds` contient les deux lib-* (`xfRUnkwOKSwQezVb`, `UWjCdC5kv3CXt6jm`). `chaine` contient `xfRUnkwOKSwQezVb`,
     `jo8eQMEwiB9wCbKN`, `bNAF6Xzx5On853kD` et `596OC5mL2aMBq6SD`.
