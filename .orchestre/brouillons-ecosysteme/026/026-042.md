## Contexte

Le bus `ops` (migrations 0096 à 0098) n'est joignable que par des fonctions SQL réservées à `service_role`. La fiche 026-040 a livré trois modules :
- **`lib/agents/garde.ts`** :
  - `authAgent(req)` rend l'agent (`nom`, `capacites`, `typesCrees`, `tablesEcrites`, `debitMinute`) ou un refus ;
  - `exigerType(agent, type)` et `exigerTable(agent, table)` rendent `null` ou un refus ;
  - `reponseRefusAgent(refus)` rend la réponse JSON ;
- **`lib/agents/bus.ts`** : une fonction par fonction SQL, qui rend `{ ok: true, data }` ou `{ ok: false, code, status }`. Le texte brut de Postgres n'en sort jamais ;
- **`lib/agents/jetons.ts`**.

Cette fiche pose les routes, fines : garde, puis validation, puis **une** fonction de `bus.ts`, puis la réponse.

**Deux règles du plan** (`SaaS/Produit/Ecosysteme-Plan-2026-09-24.md` §3.2, §4.3, §5.1) :
- **un agent crée une décision, il ne la tranche jamais**. Il n'approuve pas un envoi, ne pose pas de jeton, ne change pas un interrupteur. Ces gestes restent au Poste, pour un fondateur, sous reconfirmation ;
- **le nom de l'agent vient du jeton, jamais du corps de la requête**.

**Le drapeau.** Une fonctionnalité non finie n'apparaît pas (`lib/flags.ts`). Le nouveau drapeau `busAgents: false` ferme les routes par un 404 tant que les migrations ne sont pas appliquées. `scripts/fermeture-e2e.mjs:260-261` refuse tout drapeau absent de sa carte, qui commence à `:218`. Chaque fichier listé dans la carte doit lire lui-même `actif('busAgents')` (`:272-276`). Le proxy ne touche pas `/api` : `proxy.ts` (ex-`middleware.ts`, renommé par 026-008 ; lire celui des deux qui existe) l'exclut par son `config.matcher`, dernière ligne du fichier (`:141` avant le renommage).

**Next 15.5.26 aujourd'hui, Next 16 avant le 21/10** : les paramètres dynamiques sont une promesse attendue, `ctx: { params: Promise<{ id: string }> }` comme `app/api/controle/alertes/[id]/acquitter/route.ts:16-21`. Aucune dépendance au middleware, qui devient `proxy`.

## Ce qu'il faut faire

1. **`lib/flags.ts`** : ajouter `busAgents: false`, avec un commentaire qui dit ce qu'il ferme et quand le lever. Il se lève après l'application de 0096 à 0098 et le PASS de cette fiche, sur décision de Benj.
2. **`scripts/fermeture-e2e.mjs`** : une seule ligne ajoutée à `CARTE`, `'busAgents': ['route', '/api/agents/etat', 'GET', <les 7 fichiers de route de cette fiche>]`. Rien d'autre dans ce fichier.
3. **Les 7 routes**, toutes avec `runtime = 'nodejs'` et `dynamic = 'force-dynamic'`. Chacune ouvre par `if (!actif('busAgents')) return 404`, puis `authAgent`, puis sa validation, puis sa fonction de `bus.ts` :

   | Route | Méthode | Garde | Fonction de `bus.ts` (SQL) | Corps attendu |
   |---|---|---|---|---|
   | `/api/agents/taches` | POST | `exigerTable('taches')`, `exigerType(type)` | `ops_tache_creer` | `{ type, cle, capacite, charge?, origine?, objet? }` |
   | `/api/agents/taches/prendre` | POST | `exigerTable('taches')` | `ops_tache_prendre` | aucun |
   | `/api/agents/taches/[id]/rendre` | POST | `exigerTable('taches')` | `ops_tache_rendre` | `{ resultat: 'faite'|'echec', preuve_url?, erreur? }` |
   | `/api/agents/evenements` | POST | `exigerTable('evenements')` | `ops_evenement_ajouter` | `{ type, objet?, resume, tache? }` |
   | `/api/agents/evenements` | GET | aucune table | `ops_evenements_lire` | `?apres=<id>&limite=<n>` |
   | `/api/agents/decisions` | POST | `exigerTable('decisions')` | `ops_decision_creer` | `{ question, contexte?, options, defaut, montant_cents?, portee, echeance, cle, tache? }`, où `options` est une liste de 2 ou 3 `{ cle, libelle, recommandee }` (`cle` en `^[a-z_]{2,30}$`, `libelle` de 1 à 80 signes : contrat de 0098) et `defaut` l'une de ces clés |
   | `/api/agents/decisions?tranchees=1&depuis=<ISO>` | GET | aucune table | `ops_decisions_tranchees` | aucun ; `depuis` obligatoire, date ISO de moins de 30 jours ; rend `[{ id, cle_idempotence, choix, tranchee_le }]`, les seules décisions **créées par cet agent** (0098 filtre sur `p_agent`). Sans `tranchees=1` → 400. C'est ce que lit le chantier A12 (026-121, 026-146) pour retrouver les idées que Benj a dit de « lancer » (revue du 24/09, A6) |
   | `/api/agents/battement` | POST | aucune table | `ops_battement` | aucun |
   | `/api/agents/etat` | GET | aucune table | `ops_etat` | aucun |

   - `p_agent` (ou `p_nom`) vaut **toujours** `agent.nom`. Un champ `agent` dans le corps est ignoré.
   - Les corps attendus sont un **contrat** : le faux bus du chef (026-102) les valide champ par champ, et le chef ne poste que ces formes (026-105). Un champ requis manquant ou au mauvais type → 400.
   - Un corps de plus de 16 Ko → 413. Du JSON invalide ou un champ au mauvais type → 400, sans appel SQL. Un résumé de plus de 200 signes → 400.
   - POST `taches` et POST `decisions` répondent **201** `{ id, creee: true }` quand la ligne est créée, et **200** `{ id, creee: false }` quand la clé était déjà connue : rejouer une requête n'est pas une erreur (idempotence, plan §3.4).
   - Une erreur de `bus.ts` → `{ error, code }` avec son `status`.
4. **À ne pas faire.** Aucune route qui appelle `ops_decision_trancher`, `ops_interrupteur_poser`, `ops_agent_poser_jeton`, `ops_agent_enregistrer`, `ops_agent_retirer`, ni aucune fonction `acq_*` (série acquisition : approuver ou marquer un envoi reste un geste de Benj). Ne pas toucher `app/api/agents/tic/` (fiche 15) ni `lib/agents/garde.ts` et `bus.ts`. Aucun appel direct à `supabaseAdmin` dans les routes.
