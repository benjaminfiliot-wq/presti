## Ce qu'il faut faire

1. **`hooks/git-garde.mjs`**, en Node pur, sans dépendance.
   - Il lit stdin. Un JSON invalide, une entrée vide ou un outil autre que `Bash` et `PowerShell` donnent le code 0.
   - Il découpe la commande en segments sur `;`, `&&`, `||`, `|` et les retours à la ligne. Il inspecte aussi le contenu de `bash -c "…"`, `sh -c`, `powershell -Command "…"`, `pwsh -c` et `cmd /c "…"`.
   - Il inspecte de même, comme une commande à part entière (revue du 24/09, C1) :
     - le texte passé à `Invoke-Expression` et à son alias `iex` ;
     - `Start-Process <exe> -ArgumentList …` (et `-FilePath <exe>`), reconstruit en `<exe> <arguments>` ;
     - l'appel `& <exe> …` de PowerShell ;
     - chaque chaîne littérale du code passé à `node -e`, `node --eval`, `node -p`, `python -c`, `python3 -c` et `deno eval` : une chaîne qui contient `git` suivi d'une sous-commande est lue comme une commande. Au doute, on refuse : ce code-là n'a pas de raison de lancer git.
   - Un exécutable `git` se reconnaît aussi sous la forme `git.exe` et par un chemin (`C:\Program Files\Git\cmd\git.exe`, entre guillemets ou non).
   - Il ne met de côté que le texte d'un argument `-m` ou `--message` de `git commit` et les arguments d'`echo` et de `Write-Output`/`Write-Host`.
   - Il retire les options globales de git (`-C <chemin>`, `-c k=v`, `--git-dir=…`, `--work-tree=…`) avant de lire la sous-commande.
   - Il lit `cwd` dans l'entrée (Claude Code l'y met) pour savoir si un argument désigne un chemin existant ; sans `cwd`, il prend le répertoire du processus.
2. **Les règles** : code 2, et un message qui nomme la règle et donne l'issue sûre (« prends un instantané, ou `git stash push -m …` ; demande à Benj »).
   - `git restore`, sous toutes ses formes.
   - `git checkout` suivi de `--` ou de `.`, ou d'un arbre suivi de `--`.
   - `git checkout` avec `-f` ou `--force` ; avec deux arguments positionnels ou plus (un arbre puis des chemins, sans `--`) ; ou avec un seul argument qui désigne un chemin existant sous `cwd`. Seuls passent `git checkout -b|-B <branche> [<départ>]` et `git checkout <branche>` quand aucun chemin de ce nom n'existe.
   - `git rm` avec `-r`, `-f` ou `--force`, dans n'importe quelle combinaison (`-rf`, `-r -f`), sauf avec `--cached`.
   - `git switch --discard-changes` ou `-f`.
   - `git reset --hard` ou `--merge`.
   - `git clean` avec `-f`, sous toutes ses combinaisons (`-fd`, `-xdf`…).
   - `git push` avec `--force`, `-f`, `--force-with-lease`, `--mirror`, ou une référence préfixée par `+`.
   - `git stash drop` et `git stash clear`.
   - `git update-ref -d`, `git reflog expire` et `git gc --prune=now`.
   - `rm` avec une option récursive et une option de force, dans n'importe quel ordre ou forme (`-rf`, `-fr`, `-r -f`, `--recursive --force`).
   - `Remove-Item` avec `-Recurse` et `-Force`, dans n'importe quel ordre, ainsi que ses alias `ri`, `rm`, `del`, `erase`, `rd`, `rmdir`.
   - `rd /s` et `rmdir /s`.
3. **Ne pas bloquer** : `git status`, `git diff`, `git log`, `git add`, `git commit`, `git fetch`, un `git push` normal, `git checkout -b`, `git checkout <branche>` (aucun chemin de ce nom), `git switch <branche>`, `git stash push`, `git rm --cached <fichier>`, `git rm <fichier>`, `rm <fichier>`, `Remove-Item <fichier>`, `node -e` ou `Start-Process` sans git, et un texte de commit ou d'`echo` qui cite une commande interdite.
4. **`gabarits/settings.json`** : ajouter à `PreToolUse` l'entrée `{ "matcher": "Bash|PowerShell", "hooks": [{ "type": "command", "command": "node scripts/hooks/git-garde.mjs" }] }`, sans retirer celle de `Read`.
5. **`README.md`** de l'orchestre : ce que le crochet refuse, et ce qu'il ne couvre pas. Codex a ses propres règles, et Antigravity est couvert par l'instantané d'`antigravity.mjs`.
6. **Dans presti** : `node scripts/orchestre.mjs maj`. Il recopie `scripts/hooks/git-garde.mjs`.
7. **À ne pas faire.** Ne pas modifier `.claude/settings.json` de presti : c'est le réglage de Claude Code, que Claude Code posera avec l'accord de Benj. Ne pas toucher `bin/`. Ne lancer aucune commande destructrice pour « essayer » : on essaie en envoyant du JSON au crochet.
