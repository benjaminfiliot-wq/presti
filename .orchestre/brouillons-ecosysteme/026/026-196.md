## Contexte

Les routes du pont (026-195) sont déployées sur Vercel et le service est dans le code de l'usine (`/srv/presti-agents`, mis à jour par `node scripts/usine-agents.mjs maj`, 026-058). Il reste trois choses que **seul Benj** peut faire (décision 5 : il crée le bot et dépose le jeton lui-même) et une installation persistante sur l'usine, qui demande son « oui ».

Les jetons ne passent **jamais** par la conversation : Benj pose le jeton du bot dans le coffre de l'usine depuis son propre terminal (`scripts/usine-coffre.mjs`, 026-050, saisie masquée) ; Claude Code crée et pose celui de l'agent sans l'afficher (`poser-jeton-agent`). L'identifiant de la conversation n'est pas un secret : le service ne l'écrit dans son journal que pour la conversation qui a envoyé le bon code d'appairage (contre-revue du 25/09 au soir), et Claude Code le pose de là.

## Ce qu'il faut faire

1. **(a) Benj** crée le bot dans Telegram : `@BotFather`, `/newbot`, nom « Presti Station ». Il garde le jeton pour lui.
2. **(b) Benj**, dans son propre terminal : `node scripts/usine-coffre.mjs poser TELEGRAM_BOT_TOKEN` (saisie masquée). La valeur ne passe jamais par la conversation. **(b bis) Claude Code**, après le « oui » de Benj (contre-revue du 25/09 au soir, I7) : `node scripts/usine-coffre.mjs poser-jeton-agent pont_telegram --nom=PRESTI_JETON_TELEGRAM` (026-050 ; l'agent est semé par 0112), sans jamais afficher le jeton ; puis `TELEGRAM_CHAT_ID=aucun` et un **code d'appairage** de 8 caractères tiré au hasard (`[A-HJ-NP-Z2-9]`), posés par `node scripts/usine-coffre.mjs poser TELEGRAM_CHAT_ID --depuis-env=…` et `… poser TELEGRAM_CODE_APPAIRAGE --depuis-env=…` (ni l'un ni l'autre n'est un secret durable : le code sert une fois, 10 min).
3. **(c) Claude Code**, après le « oui » de Benj (configuration persistante) : `node scripts/usine-agents.mjs maj` si le commit de 026-195 n'est pas encore sur l'usine ; puis installer l'unité **par le compte `gardien`** (contre-revue du 25/09 au soir, D13 : `ssh -i ~/.ssh/presti-usine-gardien gardien@<hôte>` ; `install -m 644 /srv/presti-agents/scripts/usine/systemd/presti-telegram.service /etc/systemd/system/`, `systemd-analyze verify`, `systemctl daemon-reload`, `systemctl enable --now presti-telegram`) ; noter l'empreinte de l'unité installée.
4. **(d)** Claude Code donne le code à Benj dans la conversation, **juste après** le démarrage du service ; Benj envoie `/start <code>` au bot depuis son téléphone **dans les 10 min**. Claude Code lit `presti-journal telegram 20` (026-050 ; [à vérifier : que `presti-journal` accepte `telegram` dans sa liste ; sinon `journalctl -u presti-telegram -n 20` sous `gardien`]), y trouve **la seule** ligne `appairage : chat <id>` (le service n'en écrit que pour un code juste), pose l'identifiant par `node scripts/usine-coffre.mjs poser TELEGRAM_CHAT_ID --depuis-env=TELEGRAM_CHAT_ID` (ce n'est pas un secret), pose `TELEGRAM_CODE_APPAIRAGE=epuise`, puis relance le service. Aucune ligne après 10 min → nouveau code, et on recommence ; deux lignes → ne rien poser et le dire à Benj.
5. **(e)** Benj envoie `/etat` ; il dit à Claude Code ce qu'il a reçu. Claude Code déclenche une alerte d'essai `digest` [à vérifier : le moyen d'en créer une sans rien envoyer d'autre ; sinon attendre le digest de 7 h 30] et Benj confirme sa réception. Puis `node scripts/pont-telegram-qa.mjs --reel`.
6. **(f)** Mettre à jour `presti-ops/usine/LISEZMOI.md` (hors du dépôt) : le service, ses trois valeurs du coffre (leurs noms seulement), comment l'arrêter.
7. **Ne pas faire.** **Jamais de `/pause` d'essai en production** : le juge des routes le prouve sur doublures (PT-4). Aucune valeur de jeton dans un fichier, un message ou la preuve.
