## Contexte

**L'usine existe et marche** (`presti-ops/usine/LISEZMOI.md`) : `presti-usine`, Oracle Cloud Always Free, Paris, VM.Standard.A1.Flex (2 OCPU ARM, 12 Go), Ubuntu 24.04, allumée 24 h/24. Compte Unix `usine` joint par `ssh -i ~/.ssh/presti-usine usine@88.96.53.3` (IP éphémère : `PRESTI_USINE=usine@<ip>` la remplace). Node 24, Playwright avec Chromium, ffmpeg, git. Codex CLI 0.156 connecté au compte ChatGPT de Benj. Clone du dépôt presti en **lecture seule** (`~/presti`, clé de déploiement ; `git push` refusé). **Aucun secret.** `scripts/usine.mjs` (commit 698f8eb) y fait tourner une fiche de l'orchestre par Codex et rapatrie le résultat, jugé sur le poste.

**Ce qui change (rectification du 24/09).** Les agents trouvent, écrivent, envoient, répondent. La production (maquettes, sites payés) et le chef doivent tourner **PC éteint** : sur l'usine (décisions R11 et R12, provisoires). Or certains de ces agents ont besoin de secrets : leur jeton d'agent (026-040 : un jeton par agent, limité à ses types et à ses tables). **Aucun agent qui a besoin d'un secret ne tourne sur l'usine tant que le coffre n'existe pas.** Le socle, c'est :
- **un compte Unix à part, `agents`**, sans sudo, sans shell de connexion, qui fait tourner les services 24 h/24. Le compte `usine`, lui, fait tourner les fiches de l'orchestre par Codex **avec le réseau** : il ne doit jamais pouvoir lire le coffre ;
- **le coffre** : `~agents/.config/presti/agents.env`, mode 600, dossier 700, qui ne contient **que** des jetons : les jetons d'agents à portée limitée et le jeton du bot Telegram (026-195), plus aucune clé de modèle (R16 annulée). **Jamais** la clé de service Supabase (`service_role`), jamais une clé Stripe, jamais la clé Anthropic du produit ;
- **deux assistants** installés par root dans `/usr/local/bin`, seuls permis au compte `usine` sous `agents` par sudoers : `presti-coffre` (poser, retirer, lister les noms, l'état du fichier ; **jamais** une valeur) et `presti-journal` (relire les journaux des agents, qui ne contiennent aucune donnée personnelle, et trois clés de la configuration de Codex) ;
- **le code en lecture seule** : `/srv/presti-agents`, un arbre du commit `origin/main`, propriété d'`usine`, lisible par le groupe `agents`, jamais modifiable par lui. Son `.orchestre/travail` est un lien vers `/home/agents/travail` ;
- **`avec-coffre.mjs`**, qui lance une commande avec **les seules** variables du coffre qu'on lui nomme ;
- **la surveillance** : Oracle reprend une instance Always Free si, sur 7 jours, le 95e centile du processeur, du réseau **et** de la mémoire reste sous 20 % (doc Oracle citée par le LISEZMOI). Un service mesure les trois chaque minute, bat au bus, publie un point chaque jour et ouvre une décision quand le seuil approche. **Aucune charge factice** : ce serait contourner la règle d'Oracle ; on déplace du vrai travail, ou on accepte le risque, parce que **tout ce qui tourne sur l'usine reste reprenable par le poste**.

**Pièges connus de l'usine**, que le `--reel` vérifie : pas de `ufw` (il retire `iptables-persistent` et les règles d'Oracle) ; ne jamais installer le paquet `bubblewrap` (Codex prendrait `/usr/bin/bwrap`, que le profil AppArmor `codex-bwrap` ne couvre pas) ; pas de `bash -l` pour les commandes distantes (`clear_console` de `~/.bash_logout` change le code de sortie).

Les fiches jugées ici n'écrivent que du code ; rien ne touche l'usine avant la mise en service (fiche 09), jugée par le `--reel` de ce juge, écrit dès maintenant pour qu'elle ne se juge pas elle-même.

Réservée à Claude Code : c'est un juge (`CLAUDE.md:23`).
