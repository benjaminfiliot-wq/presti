## Contexte

L'organigramme (§6, poste 1) propose que le Comptable soit « un volet du Trésorier, à condition de lui donner une identité en base » : c'est fait par 026-175. Cette fiche construit ce volet plutôt qu'une nouvelle identité : moins de code, un seul agent à surveiller, un seul jeton à protéger. La règle non négociable : **aucune donnée financière ou de client ne va à une IA gratuite ni à un modèle `:cloud`** (Codex ou un moteur local seulement) ; le Comptable ne paie rien, ne déclare rien (Benj soumet lui-même les montants préparés) ; il ne change **jamais** une mention de TVA — les trois changements (mention sur facture, taux, CGV) n'arrivent qu'ensemble, le jour de l'immatriculation, par Benj ou Claude Code.

**Où vit l'argent aujourd'hui** : `lib/direction/tresorerie.ts` (026-055) fait déjà « un seul calcul par chiffre » sur les recettes, abonnements, coûts et marge, à partir d'une lecture Stripe. Le Comptable ajoute trois choses que la Trésorerie ne fait pas : le **rapprochement ligne à ligle** (chaque paiement Stripe ↔ une commande précise, avec ses orphelins et ses écarts), le **suivi daté du seuil de franchise** (pas seulement son affichage), et la **préparation** — jamais l'envoi — des montants par période pour les déclarations URSSAF.

**Clé Stripe en lecture seule** : la clé utilisée aujourd'hui par le Checkout (`lib/stripe*`, hors périmètre) a des droits d'écriture (création de sessions). Le Comptable ne doit **jamais** s'en servir. Il lui faut sa propre clé, restreinte en lecture (Balance, Charges, Invoices, Subscriptions — Stripe permet de créer une clé restreinte par ressource). **Geste de Benj, non couvert ailleurs** : créer cette clé restreinte dans le tableau de bord Stripe et la donner une fois ; Claude Code la pose comme secret (`STRIPE_CLE_LECTURE_COMPTABLE`), jamais affichée, jamais dans un commit.

## Ce qu'il faut faire

1. **`lib/direction/comptable.ts`**, ESM/TypeScript, sans effet de bord à l'import :
   - `rapprocher(periode)` : lit les charges Stripe réussies de la période par la clé de lecture seule, les relie à `sites_commandes` / abonnements par leur identifiant externe ; rend `{ recettes: [...], orphelins: [...], ecarts: [...] }` ; un paiement dupliqué (même id Stripe) n'est compté qu'une fois ; **aucune** méthode d'écriture Stripe n'est référencée dans le fichier ;
   - `seuilFranchise(periode)` : relit la même source que 026-059 (le seuil daté), calcule le cumul de l'année civile **à partir des seules recettes rapprochées** de `rapprocher`, rend `{ cumul, seuil, pourcentage, alerte: null | 'approche_seuil' | 'seuil_depasse', franchi_le }` ;
   - `preparerDeclaration(periode)` : rend `{ periode, recettes, tva: 0, source: 'rapprochement', prepare_le }` ; **pure**, aucun appel réseau de dépôt ni de paiement ;
   - `libelle(evenement)` : un texte court pour le journal ou la tuile, par `MOTEUR_DE` avec `personnelles: true` (Codex, `lib/agents/llm.ts`, déjà écrit ailleurs — importé, pas réécrit) ; repli : un gabarit fixe si Codex est indisponible ;
   - chaque rapprochement écrit une ligne d'événement (`ops_evenement_ajouter` ou équivalent déjà posé par le bus), idempotente par période (un second passage sur la même période ne duplique rien).
2. **`app/api/controle/comptable/route.ts`** (`runtime = 'nodejs'`, `dynamic = 'force-dynamic'`) : `GET` seul, protégé par `authAgent(req)` qui doit rendre l'agent `tresorier` **ou** une session Benj du Poste (comme les autres routes `/api/controle/*`) ; `actif('busAgents')` faux → 404 ; rend `{ rapprochement, seuil, montants_prepares }` pour la période demandée (`?periode=AAAA-MM`, mois par défaut) ; **jamais** un numéro de carte, un identifiant Stripe complet ou une clé dans la réponse.
