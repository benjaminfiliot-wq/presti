**Dépend de :** 026-004.

Presti est en Next 15.5.26 (`package.json`), avec React 19.2.8 installé. Next 16 est obligatoire avant le 21/10/2026. Le juge est `scripts/next16-qa.mjs` (fiche 10), dont le groupe `dependances` couvre N16-1 à N16-7.

`@serwist/next` 9.5.12 (peer `next >= 14`) ajoute une configuration webpack (`next.config.mjs:121-140`). `next build`, Turbopack par défaut en 16, échouerait. Le script `build` devient donc `next build --webpack`, et `next dev` reste en Turbopack : Serwist est coupé en développement (`next.config.mjs:129`). `next lint` n'existe plus, et le dépôt n'a pas de configuration ESLint (`.orchestre/orchestre.json`, `_note_code`).

`middleware.ts` fonctionne encore en 16 (il est seulement déprécié). Son renommage est la fiche 12, pour que cette fiche-ci laisse un build vert à elle seule.

**Réservée à Claude Code** : un changement de dépendances est un geste de chaîne d'approvisionnement. Codex ne peut pas lancer npm dans son bac à sable (`scripts/executant.mjs:107-111`).

## Ce qu'il faut faire

1. **Relever** les versions installées de `next`, `react`, `react-dom`, `@types/react`, `@types/react-dom` et `@serwist/next`, dans `versions.md`.
2. **Installer** `npm install next@^16 react@^19.2 react-dom@^19.2` et `npm install -D @types/react@^19.2 @types/react-dom@^19.2`, avec la dernière 16.x publiée. Garder `@serwist/next` tel quel, sauf si le build l'exige [à vérifier : compatibilité de Serwist 9.5 avec Next 16 en `--webpack`].
3. **Dans `package.json`** : `"build": "next build --webpack"`, et supprimer `"lint": "next lint"`. Rien d'autre.
4. **Lancer** `npm run typecheck` puis `npm run build`. Une erreur de type ou de build qui exige de toucher `app/`, `lib/` ou `next.config.mjs` arrête la fiche : écrire la ligne exacte dans `versions.md`, et Claude Code ouvre une fiche à part. Ne jamais contourner.
5. **`budget-perf.mjs`.** S'il ne trouve plus `.next/app-build-manifest.json` en Next 16 `--webpack`, s'arrêter. Le juge de poids se réécrit dans une fiche Claude Code à part, jamais pour faire passer celle-ci.
6. **`npm audit --omit=dev`** : noter le résultat dans `versions.md`. Aucune vulnérabilité haute ou critique nouvelle par rapport à avant.
7. **Vercel, en lecture, avec le connecteur** (`get_project`) : noter le réglage « Build Command ». S'il est forcé à `next build`, le script `--webpack` serait ignoré en production. Dans ce cas, **Benj** remet le réglage par défaut (`npm run build`) dans le tableau de bord avant le push.
