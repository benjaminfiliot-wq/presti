## Contexte

La station se personnalise (§5 de l'interface), et ses réglages sont **en base**, pas dans le navigateur ni sur un disque (§0.6 : Claw3D rangeait la disposition en `localStorage` et les réglages dans un fichier) : un seul jeu pour les fondateurs, versionné, journalisé, qu'on peut rétablir (§5.5). La route (026-177) les lit (`sante`) et les écrit (`estDirection`, domaine `reglages`) par deux fonctions de cette migration.

Trois lectures nouvelles servent les salles de la station (§6.3), toutes **agrégées** :
- `pilotage_radar()` : les annonceurs repérés du jour (sur `ops.annonceurs`, 0105) et les requêtes à la bibliothèque publicitaire de Meta par heure sur 12 h (l'égaliseur du Radar) ;
- `pilotage_prospects_departements()` : par département (colonne `ops.prospects.departement`, 026-060), les prospects trouvés, contactés et qui ont dit oui ; **jamais un nom**, une entreprise ni une adresse ;
- `pilotage_activite_salles(p_depuis timestamptz)` : le temps actif du jour par salle (ACTIVE AUJ.), calculé sur les événements, pour les seules clés de `SALLES` (jamais `ecommerce`, la salle réservée).

Les sources du Radar (ADEME × SIRENE pour les artisans, bibliothèque Meta pour les annonceurs) sont celles de la voie gratuite (026-019, 026-072) : cette migration ne fait que les compter.

## Contrat

| Objet | Rend | Règles |
|---|---|---|
| `ops.station_reglages` | — | une seule ligne (clé constante `1`, contrainte d'unicité) : `version integer`, `reglages jsonb`, `modifie_par uuid`, `modifie_le timestamptz` ; RLS sans politique |
| `ops.station_reglages_historique` | — | `version`, `reglages`, `auteur`, `le` ; les 50 dernières versions seulement (purge dans `station_reglages_ecrire`) ; RLS sans politique |
| `station_reglages_lire()` | `table(version, reglages, modifie_par, modifie_le)` | la ligne, ou la version 0 et `{}` si rien n'est écrit |
| `station_reglages_ecrire(p_reglages jsonb, p_auteur uuid, p_version integer)` | `integer` (la version nouvelle) | `p_version` différente de la version courante → `ops:version_perimee` ; une clé de premier niveau hors de `theme`, `mise_en_page`, `nuit`, `equipage`, `salles`, `couleurs`, `affichage` → `ops:cle_inconnue` ; plus de 64 Ko → `ops:trop_gros` ; `p_auteur` fondateur, sinon `ops:auteur` ; écrit la ligne et l'historique dans la même transaction |
| `pilotage_radar()` | `jsonb` | annonceurs du jour (comptes et catégories, aucun nom de personne) ; requêtes Meta par heure sur 12 h |

| `pilotage_activite_salles(p_depuis timestamptz)` | `table(salle, minutes)` | clés de `SALLES` seulement |

Toutes `SECURITY DEFINER`, `search_path` fixé, exécutables par `service_role` seul (`anon` et `authenticated` refusés).

## Ce qu'il faut faire

1. **La migration**, avec un en-tête commenté qui dit pourquoi, qui écrit, qui lit (modèle : `0090_audience.sql:1-30`) : les deux tables en `create table if not exists`, leur fermeture, les cinq `create or replace function`, leurs droits, des `comment on`. Aucun `grant` à `anon` ni à `authenticated`, aucune politique, aucun `create extension`, aucun `drop`.
2. **Les jumeaux** `_A_COLLER_sql_editor_0113.sql` et `_A_COLLER_sql_editor_0113_NU.sql`, par `node scripts/sql-nu.mjs`, puis le nu avec `--controle supabase/controles/0113_station_reglages.sql`, contrôlés par `--verifier`.
3. **Le contrôle**, en lecture seule : chaque fonction existe, `prosecdef` vrai, `search_path` posé, droits d'exécution de `service_role` seul ; les deux tables sous RLS sans politique ; une seule ligne au plus.
4. **L'essai à sec**, lancé par Claude Code : `node scripts/pilotage-sql-qa.mjs --migration=reglages --generer-essai [--avec=…]`, exécuté tel quel par le MCP Supabase `execute_sql` (`DO` + `EXECUTE` du jumeau nu + `raise exception` : rien ne reste), message complet dans `essai-a-sec.txt`, puis la ligne `APRES rien_ne_reste=<valeur>` tirée de `select to_regclass('ops.station_reglages') is null`. **Dire à Benj qu'un essai à sec a tourné sur la production.**
5. **Claude Code applique 0113 lui-même**, après 0105 et 0112, par le connecteur Supabase (`apply_migration` nommée `0113_station_reglages`, corps exact du fichier), lit le contrôle par `execute_sql`, fait le test réel annulé et vérifie qu'il ne reste rien, puis lance `--reel` (mémoire « migrations-je-les-applique »).
