## Contexte

La station montre une réunion d'équipage **seulement quand elle a vraiment lieu** (rectification §4.0 : trevsagents rejette lui-même une réunion « UI-only », `presti-ops/veille/2026-09-24/images/trevsagents/t070.0.jpg`). Sur la carte, les personnages vont en Salle de réunion pendant qu'elle se tient et reviennent après (`t024.0.jpg`, `t068.0.jpg`) ; dans la barre, « RÉUNION DANS » compte jusqu'à la suivante (« MEETING 16h 46m », `zoom-fidelite/trev-049.2-barre.jpg`) ; dans le fil, le Chef écrit son compte rendu ; ses idées deviennent des cartes bleues « approuver ou tuer » (« 8 ideas → approve or kill », `t020.0.jpg`) ; une idée approuvée devient une tâche du chantier (A12) ou un réglage.

Tout est déjà posé côté serveur :
- la base (026-088) : `station_reunion_ouvrir` (une par jour de Paris, Chef seul, refus en pause), `station_reunion_chiffres` (les chiffres de chaque agent, **sans modèle**, que des nombres), `station_reunion_clore` (1 à 5 lignes de 140 signes au plus, sans `@`, sans 9 chiffres de suite, sans `http` ; objectif ; 3 idées au plus, déjà créées par le Chef) et `station_reunion_abandonner` ; un passage `pg_cron` abandonne toute réunion ouverte depuis plus de 30 min : **les personnages ne restent jamais coincés** ;
- les routes (026-092) : `POST /api/agents/reunion` (`{ action: 'ouvrir' }` → `{ id }` ; `{ action: 'clore', id, lignes, objectif, idees }` ; `{ action: 'abandonner', id, motif }`) et `GET /api/agents/reunion/chiffres` → `{ chiffres }`, réservées au jeton du Chef ;
- les routes du bus (026-042) : `POST /api/agents/decisions` (une décision, au contrat de 0098 et du plan du Chef, 026-102) et `GET /api/agents/evenements?apres=<id>` (les événements des autres agents, dont les consignes de Benj, type `consigne`).

**Ce script est le seul qui fasse la réunion.** Il est déterministe autour d'un seul appel au modèle : le Chef (Codex, GPT-6 sol) ne pose jamais rien lui-même, il écrit un fichier ; le script le valide et le refuse en bloc au moindre écart (« le déterministe d'abord », « séparer le lecteur de l'acteur », plan §2.1, comme `scripts/chef/appliquer.mjs`, 026-105).

## Le plan de réunion (contrat du fichier `reunion.json` que le Chef écrit)

`{ lignes, objectif, idees }`, `additionalProperties: false` partout :
- `lignes` : 1 à 5 chaînes de 1 à 140 signes, sans `@`, sans 9 chiffres de suite, sans `http` : le compte rendu, que le fil montre ;
- `objectif` : `null`, ou `{ libelle (5 à 80 signes), mesure (null, encaisse_eur, oui, contacts_froids ou sites_en_ligne), cible (null ou entier ≥ 0) }` : l'objectif actif, « PAR LE CHEF » ;
- `idees` : 3 au plus, chacune au format des idées du plan du Chef (026-102) : `cle_idempotence` `^chef:\d{4}-\d{2}-\d{2}:idee-[a-z0-9-]{3,75}$` (la date du jour de Paris), `question`, `contexte`, exactement les options `lancer` et `reporter` (libellés de 80 signes au plus, une seule recommandée), `option_defaut: 'reporter'`, `portee: 'aucune'`, `montant_cents: 0`, `echeance` entre +1 h et +7 j.

Le schéma exécutable est `docs/agents/chef-reunion.schema.json` (026-102 adaptée) ; `--schema=<chemin>` le remplace (le juge s'en sert).

## Ce qu'il faut faire

1. **`scripts/chef/reunion.mjs [--base=https://prestiapp.fr] [--jeton-env=PRESTI_JETON_CHEF] [--modele=gpt-6-sol] [--codex=codex] [--consigne=docs/agents/chef-reunion.md] [--schema=docs/agents/chef-reunion.schema.json] [--travail=<dossier>] [--delai=600] [--sec]`**, Node seul (modules `node:` et `fetch`), dans cet ordre :
   1. **préalables** : le jeton lu dans la variable nommée par `--jeton-env` (jamais un fichier, jamais `.env.local`), la consigne et le schéma présents ; sinon code 3 et le préalable manquant, sans rien appeler ;
   2. **ouvrir** : `POST /api/agents/reunion { action: 'ouvrir' }` ; 409 `deja_tenue` ou `deja_ouverte` → « réunion déjà tenue aujourd'hui », code 0, plus rien ; 409 `pause` → « pause générale : pas de réunion », code 0, plus rien ; autre refus → code 5 ;
   3. **rassembler** : `GET /api/agents/reunion/chiffres`, puis les consignes de Benj depuis la dernière réunion (`GET /api/agents/evenements?apres=<id>`, type `consigne` seulement) ;
   4. **écrire l'entrée** `<travail>/reunion-entree.md` : les chiffres et les consignes **entre `<donnees_etat>` et `</donnees_etat>`**, rien d'autre de variable ;
   5. **faire écrire le Chef** : lancer le modèle (`--codex`, `exec`, modèle `--modele`, bac à sable en lecture seule, aucun réseau, dossier `--travail`) avec la consigne et l'entrée, pour qu'il écrive `<travail>/reunion.json` ; tuer l'arbre du processus au-delà du délai ;
   6. **valider** `reunion.json` contre le schéma, puis refaire les contrôles de forme des lignes (défense en profondeur) ; au moindre écart : rien n'est posté, on abandonne (motif `plan_refuse`) ;
   7. **poster les idées** : un `POST /api/agents/decisions` par idée, au contrat de 026-042 (sans `engage_cents`, propre au plan) ; un 200 `{ creee: false }` (clé connue) compte comme posté ;
   8. **clore** : `POST /api/agents/reunion { action: 'clore', id, lignes, objectif, idees: [clés] }` ; code 0 ;
   9. **dans un `finally`** : si la réunion a été ouverte et n'est pas close, `POST … { action: 'abandonner', id, motif }` avec `plan_refuse`, `modele_muet` (sortie vide), `delai` ou `erreur` ; code 1.
   `--sec` : n'ouvre rien, ne poste rien ; lit les chiffres, fait écrire le Chef, valide, et imprime ce qu'il aurait posté.
   Un journal `<travail>/reunion-<AAAA-MM-JJ>.log` garde chaque étape et son code HTTP ; **le jeton n'apparaît jamais**, ni dans le journal, ni sur la sortie, ni dans l'entrée du modèle. Codes : 0 réunion close ou rien à faire ; 1 réunion abandonnée ; 2 usage ; 3 préalable manquant ; 5 base injoignable.
2. **`docs/agents/reunion.md`** : ce que fait la réunion, quand (18 h, heure de Paris, décision provisoire), où (l'usine, à côté du Chef, dès que le coffre existe ; à la main sur le PC avant), comment la lancer à la main et à sec, ses codes de sortie, et ce qu'elle ne fait jamais (envoyer, dépenser, approuver, écrire autre chose que la réunion et ses idées).
3. Ne rien écrire ailleurs. Ne pas écrire la consigne de modèle ni son schéma (026-102).
